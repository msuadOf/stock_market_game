# simulation：公司经营仿真实现

`simulation` 负责通过经营活动生成公司财务结果。行业环境影响需求、价格和成本；公司根据自身能力与资金作出决策；实际业务形成合同、交付、收付款和会计记录。

当前目录只有设计文档，尚未迁入或实现本文规划的模块。现有公司经营代码仍位于 `company/operations` 等位置，不能将本目录视为已经可调用的实现。

## 模块职责

仿真模块接收明确日期、环境输入和经营指令，维护跨期经营状态，产生实际业务事件。账簿据此形成利润表、资产负债表和现金流量表。

本模块不直接抽取目标利润，不设置证券价格或成交量，不为维持经营或交易自动补钱。成长、周期和研发是可组合的经营特征，不是规定利润轨迹的互斥公司类型。

目标布局由 `company/` 的 `CompanySystem` 提供薄入口，下设并列的 `simple/` 与 `simulation/`。两种模式对上层支持相同的财务查询、披露及分红、配股、增发、回购等功能。`simple` 按可配置的月、季度、半年或年度结算周期生成营收和开支，推算利润及其他财务数据；默认采用持续一段自然时间的趋势加小幅随机波动，增长趋势统一按年化配置再换算到结算期间。具体客户、生产和研发过程可以省略，ROE 由共同指标层计算，基本面结算与报告公开排期分开。各公司可配置自己的公司行为偏好，但方案仍经共同规则校验和执行；换算公式及边界见 [DESIGN.md 第 2 节](DESIGN.md#2-代码封装与状态归属)。

简单模式只生成汇总账面财务，不追踪公司真实资金来源，也不设补款周期或额度；旧 `SyntheticFunding` 提案已取消。投资者资金、认购、分红及真实回购成交仍按共同账户和股份事实处理。`simulation` 负责完整经营链，`environment` 仅是其内部环境模块；简单模式的账面财务简化不扩展到仿真模式的有限现金约束。

新局选择 `Simulation` 后本局固定，存档恢复原实现。两个实现不相互调用，仿真调用唯一的 `accounting` 算法。本文与 `DESIGN.md` 暂保留现有阅读路径，源码接入时再统一迁至 `company/simulation/` 并修正引用；当前没有执行目录重构。

后续真实经营仿真的专属源码统一放在本目录：算法、配置、状态、随机事件、内部保存恢复、测试与 fixture 均不得散落到父目录或同级其他位置。父层只保留共同封装，共享会计继续复用。这样可以按目录独立开发和提交，减少与简单模式及宿主任务同时修改文件的机会；同一仓库的目录划分不保证完全没有 Git 冲突，公共契约变更仍需协调。

## 目标代码布局

以下是后续实现的职责分配，不表示相应源码文件已经存在：

| 位置 | 职责 |
| --- | --- |
| `mod.rs` | 内部实现入口，接收父层调用并编排经营推进 |
| `config.rs` | 环境、行业、公司与业务参数的校验 |
| `state.rs` | 仿真状态组合与必要跨期事实 |
| `environment.rs` | 公共需求、利率、资源价格等环境演化 |
| `industry.rs` | 行业需求池、报价比较及需求分配 |
| `decisions.rs` | 公司预算、资源分配与经营行动 |
| `customers/` | 客户独立现金、债务、部分偿付及后续回收 |
| `research/` | 研发阶段、技术成果与失败经历 |
| `businesses/` | 制造、项目、银行等不同业务过程 |
| `finance/` | 仿真账套装配、行业子账及会计接线，复用 `accounting` 算法 |
| `events.rs` / `scheduler.rs` | 经营事件、因果引用与仿真到期事项 |
| `settlement.rs` | 跨主体收付款、事件配对和原子性协调 |
| `persistence.rs` | 仿真专属状态投影与恢复校验，由父层统一存档入口调用 |
| 各模块测试及 `tests/`、`fixtures/` | 仿真单测、模块间案例和最小测试数据 |

共享金额、会计及报表算法不复制进本目录；各模式的账务状态各自保持唯一所有者。共同公司身份不强制包含客户或经营合同，简单模式以汇总财务满足相同功能，不构造空壳仿真对象。单元测试贴近对应模块；父层验证模式选择、相同功能契约、信息边界及共同股本结算规则。

## 案例怎样帮助理解算法

[DESIGN.md 的经营案例](DESIGN.md#10-经营案例与计算示例)将参考公司对应到实际计算步骤：茅台的产品结构、宁德时代的技术渗透、比亚迪的价格竞争、恒瑞及北方华创的研发时滞、中芯等公司的产能利用率、万科与保利的预售交付，以及资源、银行、券商、平台和水电业务。另用有限现金例子说明部分付款与后续补付。

案例中的计算数字是虚拟演示，不是上述公司的真实财务或游戏默认参数。公式使用 `Revenue`、`CostOfSales`、`CashBalance` 等英文标识，每个新标识紧接中文释义、单位和手算示例；后续代码使用同义 `snake_case`。完整月度算例展示从需求分配到采购、交付、部分收款、研发、三张报表核对及下月回款，解释为什么利润不等于现金增加。全部 20 家参考公司及核验范围仍以[完整设计蓝图](../../../../../../agents/remaining-questions-and-features/q14-financial-model-design.md)为准；格力仅为后续对比样本。

## 推进与验证

月初更新环境和经营计划，自然日执行到期业务和真实收付，期间结束后结账。只在成功日终保存，日内状态保留在内存；详细步骤见 [DESIGN.md](DESIGN.md)。

后续实现优先验证库存与产能、有限现金、研发时滞、行业单位、重复事件、双边结算原子性及保存恢复。普通单测遵守仓库十秒上限；文档存在不代表这些测试已经通过。

修改经营算法、状态归属或代码布局时，同步更新 `DESIGN.md`；修改公共使用方式或模块入口时，同步更新本文件。正式交易和会计规则仍以对应领域规范为准。
