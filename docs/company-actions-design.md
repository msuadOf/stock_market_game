> 状态：**设计文档，无运行时代码**。本文档只固定未来若实现分红、增发、回购、
> 清算分配时的接口边界，使会计/权益/登记/税费语义先被说清楚。依据
> `company-information-npc-intentions` 计划 guardrail #4：本发布**不执行**任何
> 股东分红、股权融资、回购或清算分配；不增减股本、不做除权除息参考价处理、
> 不向投资者补钱。**不存在**任何待执行队列、定时器或公开 API 等运行时构件。

- 取证日期：2026-09-10（本文引用的官方文本均见
  [`packages/engine/tests/fixtures/company-model/policy-sources.json`](../packages/engine/tests/fixtures/company-model/policy-sources.json)）
- 关联决策：ADR-0016（公司事实与 NPC 个体预期）、开放问题 Q12（封闭经济外部现金流）

## 1. 为什么现在只写设计

公司经营与商业债务收付（K2/K3）要求完整复式记账，这些是公司对**外部商业对手方**
的义务，与股东结算无关，照常实现。向股东的分配则会改变股本、每股指标与投资者
资金，若与本次会计底座同时实现，验收面会不可控。因此本发布把股东结算冻结在
"设计边界"层：将来实现时**只能**落在这个边界内，不得绕开它自造语义。

## 2. 四个接口边界

### 2.1 借贷（debt-like）边界

公司**商业借款**（向外部贷款人的借款、还款、利息、税费）属于 K2/K3 已实现范围，
不是股东结算。未来若引入"可转债"等兼具权益与负债特征的合同，其负债成分与权益
成分的划分必须依据：

- 《企业会计准则第37号——金融工具列报》（财会〔2017〕14号，2017-05-02 印发）
  第七至十五条（金融负债与权益工具的区分：第七条实质判断、第八/九条定义、
  第十条无条件避免交付、第十一至十五条或有结算/结算选择权/复合工具）、
  第二十一/二十二/二十五条（负债利息计损益 vs 权益发行/股利计权益）——
  原文已核验（fixture `cas-37-fi-presentation-2017`，verified-official，
  2026-09-10 第二次取证）。
- 《企业会计准则第30号——财务报表列报》（财会〔2026〕11号，2026-07-24 印发）
  第二十四条：负债条款导致企业可能以自身权益工具清偿时的流动性划分约束。

**边界**：本发布不引入任何新负债合同类型；银行/工商借款仅按 K3 已核验范围执行。

### 2.2 权益（equity）边界

利润进入留存收益（`未分配利润`），但**不自动分配**（K2）。未来实现分配时：

- 分红宣告形成负债（应付股利）并减少权益，会计上属于"与所有者的资本交易"，
  在所有者权益变动表中单独列示——《企业会计准则第30号——财务报表列报》
  （财会〔2026〕11号）第六十条、第六十一条（一）（三）：综合收益与所有者资本
  交易分别列示，"所有者投入资本和向所有者分配利润"为必列项目；第六十五条
  要求附注披露资产负债表日后提议或宣布发放的股利。
- 初始股本为开局事实，不作为本次运行时发行（K2）；未来增发/回购改变股本时，
  必须同步更新发行人股票总股本与登记子账，且流通股与总股本不得互换。

**边界**：本发布权益变动表的"对所有者的分配"行恒为 0；游戏内没有任何代码路径
写入非零分配。

### 2.3 登记（registry）边界

股本、已发行股份总数、股东名册的权威记录属于**发行人/登记**域，当前由
`StockSpec` 的总股本与流通股字段承担（K2：固定股本与初始股东权益必须与股票
总股本一致）。未来股东结算需要：

- 一个独立的登记子账接口：股份变动（发行/回购/注销）只能经显式凭证进入，
  与 `BusinessEventId` 一样至多入账一次；
- 交易撮合发生的股份转手**不改变**已发行总股本，只改持有人——现有撮合已满足，
  不需要登记子账；登记子账只服务于股本变动类公司行为。

**边界**：本发布总股本在开局后不可变；不存在股本变动事件类型。

### 2.4 税费（tax）边界

股东层面的红利税、股权转让所得税**不属于公司会计**，属于投资者侧结算，本发布
不实现。公司侧税费（增值税销项/进项、所得税当期/递延）按 K3 已核验范围执行，
税务政策是版本化显式配置，详见
[`company-accounting.md`](company-accounting.md) §税务。

未来若实现分红，红利税款代扣属于投资者账户与登记边界的联合变更，必须先补
官方法源（当时现行个人所得税法及税收优惠公告），再实现；不得用固定税率近似
后标注"真实 A 股参数"。

## 3. 与除权除息的关系

执行分红会产生除权除息参考价需求。本发布的涨跌停、昨收与撮合**不包含**除权
除息参考价处理（guardrail #4），`docs/trading-rules.md` 亦未登记任何除权规则。
将来实现时必须：

1. 先在 `docs/trading-rules.md` 登记交易所现行除权除息安排的官方依据；
2. 修改昨收/涨跌停计算并同步全部相关断言测试；
3. 保持旧存档不兼容策略（新格式无迁移，ADR-0016 计划范围）。

## 4. 明确不做清单（本发布）

- 无分红/派息事件类型；无应付股利科目写入路径。
- 无增发、回购、注销、清算分配事件类型；无股本变动。
- 无除权除息参考价；无向投资者补钱的任何通道（Q12 未决）。
- 无股东结算相关的待执行队列、定时器、后台任务或 REST/WASM/Tauri API。
- NPC 与玩家在股东身份上与现状一致：只是二级市场持股人，不触发公司行为。
