# A 股交易规则基线

游戏的证券交易规则以中国大陆沪深 A 股竞价交易为基线。参数属于权威会话配置，
前端只能预检查，最终由 Rust engine 拒单或结算。

金额与每股价格的 `Money` 内部单位为分，跨端统一使用规范有符号 `i64` 十进制分
字符串；例如 `"1"` 为0.01元，`"1000000000000"` 为100亿元。Web 金融计算保持整数
精度，不接受旧数字金额；`AccountingAmount` 仍为独立元字符串。编码不改变下列交易
规则、费用或舍入，图表近似不能用于反算委托。见 [ADR-0031](decisions/0031-money-decimal-cents-wire.md)。

Escrow 并行候选的资源边界见 [ADR-0017](decisions/0017-escrow-parallel-tick.md)：
SealAllocationSnapshot 的 `DecisionResourceSnapshot::seal` 读取报价过期处理后的资源；其他密封批释放不回补本批预算。
买单使用现金 envelope，卖单现金预留恒为零。分歧 #9 的卖费实收封顶/后腿追收是明确批准的
**游戏简化**，不是交易所或券商真实清算承诺；nominal 费率与累计最低佣金不因并行化改变。
`engine::TickCommitEvidence` 与 `engine::UpdateStreamProjector` 是验证投影入口，不是另一套交易规则。
本批工程接线复核日期：2026-09-23；下列交易所条款最近一次内容核对日期：2026-09-22；费用表本次访问失败的边界另列，
不将部分来源复核冒充全部规则验收。
2026-09-25 又核对了沪市现行规则 3.5.1 与深市现行规则 3.4.2：同价同向申报的先后
依据交易主机接受申报的时间。此次只复核竞价优先原则，不代表重查了下列其他条款。

## 已实现

- 普通主板与主板风险警示股票涨跌幅 10%，创业板 20%；每只股票显式配置，避免仅凭名称猜板块。
- 最小价格变动 0.01 元。
- 沪深交易所分别判断当前自然日开闭市；只要一家在局交易所开市，共享市场时钟即可推进。
  休市证券不接受申报和撤单、不生成新行情或日 K，不以另一交易所的开市虚构成交；
  每证券的分钟历史、交易日计划期限及 T+1 日界解锁仅按本证券实际开市日推进。
  默认年度休市表仍是明确标注的模拟回退，不声称已取得未来年度真实休市公告；详见
  [`simulation-calendar.md`](simulation-calendar.md)。
- 买入申报为 100 股整数倍；主板/ST 当前模型单笔上限 1,000,000 股，创业板限价单
  上限 300,000 股、市价单上限 150,000 股；权威配置拒绝把一手改成其他数量。
- 卖出不得超过“持仓 − T+1 锁定 − 已挂卖单”；不足 100 股的零股必须随一笔卖单一次性卖出。
- 当日买入股份不可卖，下一交易日日界解锁。
- 开盘集合竞价在 09:15–09:25 接受限价申报，09:15–09:20 可撤单；09:25 一次性撮合后，
  未成交的当日有效限价单继续进入连续竞价簿。09:25–09:30 不接受新申报。
- 在允许撤单的时段，刚受理但仍有挂单余量的委托也可撤单；部分成交只撤余量，
  已全部成交则明确反馈“已成交、无法撤单”。撤单是否成功由对应股票订单簿的当前状态决定。
- **游戏简化：** 本 tick 撤单释放的资金或可卖股份，要到下一 tick 才能供新委托占用。
  本 tick 的新委托仍按轮初可用资源校验；计划即使收到撤单成功反馈，也不能在本轮复用这笔释放。
- 收盘集合竞价在 14:57–15:00 接受限价申报且不可撤单；窗口结束时按证券交易所各自的集合竞价
  清算规则一次撮合，未成交余单随紧接的日界失效。收盘竞价事件显式携带 `ClosingAuction` 阶段和
  `clearing_price`，不得误作开盘价或投影到开盘分时区域。
- 交易所归属在每只股票上显式配置。沪市集合竞价最终同价时取候选中间价。深交所规则
  3.4.3 的最终距离参照为开盘前收价、盘中/收盘最近成交价；当前游戏所有深市竞价仍统一
  使用昨收，属于尚未修正的简化，不是完整真实规则。完全同距时取低价也仅为模拟确定性。
- 连续竞价限价申报默认执行价格笼子：买入上限取参考价的 102% 与参考价加十个最小价位中的
  较高者，卖出下限取参考价的 98% 与参考价减十个最小价位中的较低者；参考价按买卖方向
  依次使用对手一档、本方一档、最新成交价/前收。
- **可选游戏简化（2026-09-27）：** 新游戏配置 `price_cage_enabled` 可关闭连续竞价
  价格笼子，默认开启；关闭后仍执行涨跌幅和其他申报规则。该选择随当前存档保存。
- 买卖双方收取交易过户费 0.01‰；卖出方另收 0.5‰ 印花税；券商佣金率和最低佣金可配置。
- **游戏简化：** 统一市价意图按涨跌停价作保护并逐档立即成交，未成交余量不进入订单簿。
  尚未细分沪深市价申报类型及其最优五档、余量转限价等差异。
- 全部未成交委托共享账户资源占用预算：买单占用成交额及费用；卖单仅占用可卖股份，不占用
  现金。撤单、日终清簿后释放相应占用，快照公开 `reserved_cash` 和按股票汇总的
  `reserved_sell_qty`，界面显示的“可用资金/可卖”必须扣除对应占用。卖单名义费用公式、税率和
  最低佣金累计口径不变；实际费用按每一成交腿从成交所得封顶收取，并按佣金 → 印花税 → 过户费
  的固定顺序分配。这是游戏简化，不等同于交易所真实清算或一般券商规则。完整口径见
  [ADR-0017 分歧 #9](decisions/0017-escrow-parallel-tick.md#5-九条分歧台账)。

## 图表周期的展示简化（2026-10-05）

默认 Web 局以每 tick 一秒显示交易时钟。自定义 `SessionSetup.ticks_per_day/auction_ticks/closing_auction_ticks` 的自定义长度局属于游戏时间缩放（简化）：时钟沿用 engine `observation_civil_instant` 的开盘900秒、连续14220秒（无收盘窗口时14400秒）和收盘180秒比例，跳过午间休市。整数 tick 可使阶段边界粗化；例如开盘10 tick 的申报结束 tick 7 显示09:25:30，不伪造另一套09:25时钟。开盘1 tick 时没有独立 PreOpen，开盘或收盘窗口为0时对应阶段缺失，均不是完整交易所时间制度。UI 常驻说明这些简化，不改变撮合阶段、原始 tick、成交或存档事实。

图表按 tick 覆盖区间的起点归入固定显示槽，默认仍每分钟60 tick、竞价每细线6 tick；自定义局没有覆盖的分钟槽保持为空，不插值生成交易。开盘 `AuctionCompleted` 落在竞价区末槽，表示本次竞价已结束；极短/非三整除局的准确事件时间以逐笔时钟为准。当前时钟在完整 tick 日界显示下一交易日开盘；逐笔末 tick 保留上一日15:00，午休端点成交保留11:30，不冒充13:00新成交。

Web 的周 K、月 K 使用 `aggregateCandles` 按自然周（周一至周日）和公历自然月合并已有日 K；虚拟前史与实际运行均携带明确公历日期。分桶不因可视窗口首根变化而改变，不补造休市日或无成交区间，当前未结束周期只展示已有事实。按用户最新决定，不保留每5／20个交易日聚合选项。MA5／10／20／30／60 在所选周期的合并收盘价上计算 SMA，N 指 N 根所选周期 K 线。聚合只用于绘图，不改变 engine 日 K、成交、委托、结算或时间规则；合并量为股数之和，展示换算为手，无权威合并成交额时详情显示不可用。季 K、年 K 和分钟 K、可编辑 MA 由后续实施接入，不因列入产品需求而视为已经实现。

## NPC 策略选择

**NPC 仓位选择（2026-09-26）：** 公共执行路径不按固定单股比例或统一现金保留比例限制
策略目标，允许策略选择集中持股或持有现金。资金、真实手续费、股份、T+1 与申报规则继续
校验。个体参数表达一次目标调整步幅，不是最终仓位上限；见
[ADR-0021](decisions/0021-strategy-position-choice-and-noise-pricing.md)。同 ADR 经用户于
2026-09-27 澄清：每笔交易区分主动成交和指定价格等待，适用于各类 NPC 与玩家。
散户现有主动买卖与游资趋势买卖使用公共限价委托的“最高／最低”价格选项，轮到该股票
受理该单时确定一次价格：开启笼子的连续竞价取笼子与涨跌幅范围的交集，关闭笼子或
集合竞价使用涨跌停价。最高价买单数量按涨停价与本局费用估算并预留资金，实际报价
较低时释放差额；释放额不回补本 tick 预算。未成交部分按确定的价格留簿，机构自己的估值限制与游资反转
策略的等价报价保留。没有增加特殊做市账户或保证流动性的资金。

公共接口也允许最低价买入和最高价卖出，分别使用跌停价与涨停价。价格选项是游戏下单
入口功能，不是另一种交易所市价申报；它与已有的余量撤销市价意图不同。未受理请求保存
选价方式，已经受理的挂单只保存实际价格，行情变化、读档或竞价转连续时不自动追价。
指定价格单仍可能因盘口变化而不符合笼子；订单簿照常校验，不增加拒单后立即重试。
具体资金及类型契约见 [ADR-0022](decisions/0022-symbolic-limit-prices.md)。此次相关条款
核对日期为 2026-09-27，依据见 ADR-0021 第 5 节。

机构成本候选、风险暂停和真实买入后的不利选择为**游戏策略假设**，不是交易所制度
或真实市场统计规律。触发与恢复门槛逐机构冻结，恢复必须由下一本人观察确认；
只暂停继续买入，不自动强制卖出、返费或补钱。已有卖出减仓可按本人净值回撤提高
紧迫度，仍受 T+1、真实费用及合法撤单窗口约束。公式与数值见
[ADR-0026](decisions/0026-individual-institution-experience.md)。

## 已知待修正的受理顺序偏差

**草稿阶段容量约定（2026-09-25）：** 请求队列、未成交挂单和待处理计划事件不按固定条数拒绝合法请求。资金、可卖股份、T+1、单笔申报数量与交易时段仍分别校验。机器资源故障应明确报告，不能伪装成交易拒绝。详见 [ADR-0019](decisions/0019-draft-market-scope-and-capacity.md)。

**计划策略（游戏规则）：** 积极交易型机构在每日开盘后的首个连续交易 tick 观察并可
建立当日到期计划；成长、均衡型机构每日观察但计划可跨日，深度价值和防御型机构
不因普通开盘自动复核；其随机观察频率也低于每天一次，允许跨日不观察。成交与撤单仍由
真实订单簿反馈，买入股份对外继续受 T+1
限制；“日内计划”指计划有效期至当日日终，不表示当日买入后可以卖出。

NPC 请求在上一 tick 的已提交状态上形成，下一 tick 受理；玩家请求验收入队后在下一 tick 参与交易。
盘前、连续交易和集合竞价已把本轮就绪的 NPC、玩家及部分计划根命令合入局部受理：
不同账户争同一股票的受理先后由该股入口实际发生的先后决定，来源标签与订单 ID 不充当优先级；
同一账户的现金和逐股可卖数量分别校验。计划链只在收到对应命令的结果后续行，
已全部成交的订单撤单会返回明确的业务失败，部分成交仍可撤剩余量。

计划根现逐个完成并交付，无须等同批其他账户的根都完成。三阶段的同账户资源争用已从候选数组位置改为接收事实：上一提交形成的 NPC 请求、两个 tick 间排队的玩家请求，以及本 tick 真正就绪的计划命令分别保留其账户内先后；这个比较只用于同账户现金或逐股可卖股份。跨账户同股委托的时间优先仍取该股入口的实际受理先后。现有 NPC 与玩家候选虽仍按来源拼成向量，但来源块不再充当账户资源裁决依据；后续仍需继续核对无关请求的等待范围，并提高真实活跃负载的整轮多线程加速比。
这些限制与交易所的价格、时间优先规则不同，迁移要求见
[ADR-0018 §7](decisions/0018-long-running-immutable-timeline.md#7-交易约束撮合顺序与并行)。

## 公司行为与现金除息边界

现金除息的共同计算使用证券所属交易所日历：权益登记日次一交易日除息，标准纯现金方案的参考价为前收盘价减税前每股现金红利。依据为沪市《交易规则（2026年修订）》4.3.1—4.3.3 和深市对应规则 4.4.1—4.4.3；两者自 2026-07-06 施行，官方原文核对及来源见[现金分红研究](../agents/remaining-questions-and-features/dividend-research.md)。不能以自然日加一代替交易日，也不能用税后红利、修改历史成交或制造成交实现除息。发行人获批调整公式时须明确区分，当前基础计算显式拒绝，不静默套用标准公式。

`company::ex_reference_price` 当前仅覆盖每股红利精确为整数分的标准纯现金计算，不对不足一分的每股方案擅自取整；非正参考价明确拒绝。这是计算基础，不代表已将除息参考价接入市场、涨跌幅基准或公司行为完整结算。股东登记、个人股息税和现金方案事实记录也不等于投资者账户已经收到款项；真实账户付款、配股／增发认购、回购委托与成交仍需共同接线。

`Simple` 的公司现金仅为账面展示，不是分红预算；分红仍须满足可分配利润和明确方案条件，投资者认购检查本人真实现金，回购须真实成交。不能把账面生成当成真实资金来源，亦不能因此给认购者补钱。沪深中国结算发行人指南本次仅返回维护页，尚未核实的碎股、尾差、配股登记与退款及回购专户规则不得猜测实现；可达性证据见[指南复核](../agents/company-system/corporate-rules-refresh.md)。

## 个人流通股股息红利差别化个人所得税（2026-10-06 登记口径）

本节登记 `company::cash_dividend_tax` 与 Session 日终收缴已接通的完整语义。法规依据为
[财税〔2012〕85号](https://fgk.chinatax.gov.cn/zcfgk/c102416/c5203902/content.html)《关于实施上市公司股息红利差别化个人所得税政策有关问题的通知》
（2013-01-01 施行）与财税〔2015〕101号《关于实施上市公司股息红利差别化个人所得税政策
有关问题的通知》（2015-09-08 施行）；条文名称与适用日期按 2026-10-06 口径登记，
并经同日非作者复核对照官方原文逐条核验（见
[复核记录](../agents/company-system/personal-dividend-tax-fix-review.md)），调整实现时必须同时更新测试与本文档。

- **三档税率（85号第一条、101号第一条）**：持股期限 1 个月以内（含）的，股息红利所得
  全额计入应纳税所得额，按 20% 计税；1 个月以上至 1 年（含）的，暂减按 50% 计入
  （实际税负 10%）；超过 1 年的，暂免征收（0%）。
- **持股期限（85号第一条第二款）**：指个人取得股票之日至转让交割之日前一日的持有时间。
  “1 个月”“1 年”的自然年（月）定义见 85号第八条：“1 个月”指上月某日至本月同日前一日；
  “1 年”指上年同月同日至本年同月同日的前一日。
  实现上卖出日（交割日）当日仍计入档期判断的边界（`disposed_on <= 周年日` 归上一档）。
- **月末边界钳制（实现口径，2026-10-06）**：取得日在目标月无对应日（如 1 月 31 日对 2 月、
  2 月 29 日跨平年）时，期间边界钳制到目标月最后一日（1 月 31 日 → 2 月 28/29 日；
  2 月 29 日 → 次年 2 月 28 日），依据《民法典》第二百零一条、第二百零二条的期间计算
  规则（无对应日的，月末日为期间最后一日）并结合 85号第八条“同日”定义。不得对整类
  月末取得批次拒绝计税。
- **派发不预扣、转让时扣收（101号第二条；资金账户扣收与不足通知补足口径见 85号第二条）**：上市公司派发股息红利时，
  对个人持股 1 年以内（含）的不代扣；待个人转让股票时，按持股期限计算应纳税额，
  从个人资金账户中扣收。持股超过 1 年的股息在持有超一年后处置时按 0% 不产生税款。
- **账户单位与 FIFO（85号第三条）**：应纳税所得额以个人证券账户为单位计算；股份
  按每日日终净增（减）数、取得日先后的先进先出原则计算持股期限。实现为逐自然日
  `record_net_day` 净额批次与 FIFO 处置记录。
- **限售股（85号第四条）**：解禁前取得的股息红利所得暂减按 50% 计入（实际税负 10%）；
  持股期限自解禁之日起计算。实现为 `StatutoryRestricted` 批次：解禁前到账的分红按 10%
  直接计税，处置档期以 `release_on` 起算。法定依据分类（财税〔2009〕167号、
  财税〔2010〕70号）需显式证据字段。
- **亚分税额（实现口径，2026-10-06）**：85号/101号未规定应纳税额不足一分的处理，
  官方明文未取得。登记为本游戏实现口径：**按持有人每笔分红合计应纳税额四舍五入
  （half-up）到分**；每笔分红内部仍用精确分数求值，仅在按笔汇总后取整，登记与
  收缴回执保留精确事实。例：每股 7 分 × 3 股 × 20% = 4.2 分 → 收缴 4 分。
- **资金不足的部分收缴与追缴（85号第二条）**：划收时资金账户余额不足的，按
  `min(应纳税额, 账户真实现金)` 部分扣收，不虚构资金、不叠加历史已收缴税额抬高上限；
  未清税额由后续每次日终继续追缴，并通过 `GameSession::dividend_tax_outstanding_views`
  typed 查询面（ts-rs 正规导出 + Web 严格 parser）显式暴露未划收税额、`needs_funds`
  与原因（`InsufficientAvailableCash`/`Cleared`）。本地 WASM 宿主经 owner 隔离导出
  （`owner_dividend_tax_outstanding_views`），公司行为面板（CompanyPanel 体系内的
  DividendTaxPanel）展示本人未清税额并对 `needs_funds` 显式提示；Tauri/远程宿主的
  税务状态查询留待后续批次，不支持时 UI 显式提示而非静默。
- **显式不支持**：居民企业、证券投资基金、非居民以及未配置税务身份
  （`TreatmentNotConfigured`）不按个人口径计税，显式拒绝或不产生个人税事实；
  同一账户混合法定限售与流通税股批次的处置显式不支持。
- **装配期限制**：税账（`configure_cash_dividend_tax_book`）只能在名册尚无历史日结回执
  且无已登记分红时配置；事后配置无法重建 FIFO 税事实并会令日终永久失败，因此显式拒绝。

### 开局税务模式与默认税籍（2026-10-06 产品决策登记）

本节登记新局税务模式选项（`SessionSetup.dividend_tax_mode`）与默认税籍语义，属
2026-10-06 用户产品决策：「新局默认用户交易都扣税，还可以选择用大A的方式扣税
（个人扣税、机构/企业另外算……企业部分先留下抽象层接口），还可以配置为不扣税。
此外，分红要扣税」。

- **模式与持久化**：默认 `IndividualPublicMarket`（大 A 个人差别化），可选 `Exempt`
  （不扣税）。字段为严格持久化契约——新档必填、无 serde 兼容默认，缺失该字段的旧档
  在 engine 反序列化与 Web `parseSetup` 两端均被显式拒绝（错误指明
  `dividend_tax_mode`）；恢复后装配期自动配置与计税语义不变。
- **默认模式的装配期自动开账**：配置完整股东名册（`GameSession::configure_share_registry`）
  成功后，引擎在同一候选副本上为每个「个人」身份的账户持有人走既有
  `configure_cash_dividend_tax_book` 自动配置 `IndividualPublicMarket` 税账；名册或
  税账任一步失败都不留半配置状态。个人身份分类的权威映射是
  `taxpayer_identity_of_kind`：玩家（Player）与自然人散户 NPC（Retail）属个人；
  机构（Inst）与游资（Hot）NPC 属非个人。
- **机构/游资边界**：非个人身份保持 `TreatmentNotConfigured`，不产生个人税事实；
  企业/机构计税未实现（显式登记「企业/机构税未实现」，查询视图以
  `TaxpayerIdentity::NonIndividualPending` 呈现）。
- **不扣税模式**：引擎装配期不为任何身份自动配置税账（新局默认局 fixture 中
  `dividend_tax_books` 保持空数组）；宿主显式装配期命令 `configure_dividend_tax_book`
  仍是既有入口，开局后被拒是正确行为（装配期守卫），错误完整上抛不静默降级。
  `Exempt` 仅豁免个人现金股息税：交易环节过户费、印花税与佣金口径在两种模式下
  一致不变（按用户原意核对后登记的口径）。
- **装配期后进入的股东**：经二级市场净买入在日后进入股东登记的账户不自动补开
  个人税账（受既有装配期守卫约束），其分红保持 `TreatmentNotConfigured`。这是当前
  引擎边界，不是税法口径。
- **企业/机构税抽象层留白**：`DividendTaxProfile` 已含 `ResidentEnterprise` /
  `SecuritiesFund` / `NonResident` 显式变体；`TaxpayerIdentity::NonIndividualPending`
  是非个人身份的统一扩展位。实现其计税前不得把非个人身份映射为任何已实现身份
  （`CashDividendTaxBook::validate` 对非个人身份显式拒绝）。
- **查询与 UI 入口**：`GameSession::account_dividend_tax_status(account)` 只读返回
  模式、身份分类与每个已登记证券的税账状态（未知账户显式报错）；本地 WASM 宿主以
  owner 隔离导出 `owner_dividend_tax_status` / `owner_dividend_tax_outstanding_views` /
  `configure_dividend_tax_book`。新局创建界面（TaxModeInput，默认勾选大 A 方式）与
  公司行为面板（DividendTaxPanel）已接线；Tauri/远程宿主的税务状态查询留待后续批次，
  不支持时 UI 显式提示。

## 送转（股票股利与资本公积转增）实际登记（2026-10-06）

送转已接通为真实股份登记全链路：显式方案批准（`GameSession::approve_stock_distribution`）→ 公告状态推进 → R 日按登记快照冻结账户级碎股分配（沪深碎股降序、同余 seed 洗牌沿用既有算法，seed 由事件身份派生）→ R+1 以 `MovementScope::NonTradingTransfer` 在股东名册同日追加非交易过户回执落新增 lot、投资者账户真实加股（只增持仓数量，不产生现金、不进 T+1 锁定）→ 发行股数守恒更新（名册、发行人身份与 setup 初始股数加增发回放一致，恢复按此严格校验）。R+1 入账依据沪深《证券发行人业务指南》归档摘录（沪业字〔2024〕6号 2.5节、深业〔2025〕68号 2.5节），见[送转基础记录](../agents/company-system/stock-distribution.md)。限售继承：持有者原 lots 全部为同一限售类时新 lot 继承该限售属性与截止日（深市指南有明文；**沪市对应条文未定位，登记为证据缺口**，不跨市场推断）；混合限售来源显式拒绝整日回滚，保留 `SourceLotAttributionPending` 语义，不按比例摊；原限售截止日已早于入账日的按 Unrestricted 登记（处置路径本就视同可流通）。回购专户股份按既有 facts 排除。

**每股面值与多次送转语义（2026-10-06 修复轮）：** 面值遵循现实口径——每股面值恒定，送转入账后注册资本按 面值×新增股数 演进。首次送转声明的面值由「已绑定注册资本法定事实 ÷ 名册当前已发行股数」整除推导并就此固定；同一发行人的后续送转必须沿用同一面值，不允许用增大后的发行股数反推出缩小的面值。送转真实入账时，Simple 账面的注册资本法定事实按上述金额演进（`source_evidence` 不变，显式 bind-once 入口仍拒绝直接改写），各次送转声明以 `registered_capital_at_approval` 冻结批准时点注册资本作为历史；恢复校验与 Web 严格 parser 都按「当前法定注册资本 − 批准日当天及之后才入账的送转股本增加」重构批准时点口径核对。送股（股票股利）的可分配利润上限、法定公积金 50% 免计提门槛均按演进后的注册资本核定。

除权参考价按上市地交易所**分列参数化**，两市措辞口径不同、禁止合并：沪市 4.3.1 用"流通股份变动比例"、深市 4.4.1 用"股份变动比例"（`StockDistributionExRightsFormula::ShanghaiCirculatingShareChange` / `ShenzhenShareChange`，公式变体与交易所不匹配显式拒绝）。本批仅实现送转分量（配股未实现，配股价格分量恒为零）：参考价 =（前收盘价 − 同日合计税前每股现金红利）÷（1 + 变动比例），比例用百万分之一股整数单位；同日多起送转事件的合并口径（相加还是复合）未在官方材料核实，**在方案受理时即显式拒绝**（`approve_stock_distribution` 直接拒绝同发行人同证券同除权日的第二起事件，不再推迟到 R+1 首 tick 的除权准备）。除权参考价作为行情前收与涨跌幅基准，与现金除息共用同一锚组（`AppliedExReferenceGroup`），不覆写历史成交。**游戏简化：** 除法结果按最小价位取整数分时使用银行家舍入（half-to-even，与 `Money` 既有纪律一致）；沪深规则条文只给出公式，分位舍入方向未在已核验摘录中写明，取得官方口径后再行校正。

**本批明确不支持并登记的边界：**

- **游戏简化：公司行为资金与股份均在相关日期日终入账，当日盘中不可用。** 新股在 R+1（送转入账/上市日）日终才落账，当日盘中不可卖出；现金分红款也在发放日日终才到账。官方口径为 R+1 上市当日即可流通（沪业字〔2024〕6号 / 深业〔2025〕68号 2.5 节），与上市日语义的这一差异留待后续批次对齐，本批不改变日终入账管线。
- 送转个人所得税（送股按面值计税的差异化口径）未实现；股息税账只覆盖现金分红。
- 转增的账面前置校验未建模：Simple 账面没有资本公积科目与来源类别，也未建模法定公积金转增的 25% 留存下限适用差异。转增在 Simple 侧只做面值口径的展示事实登记（`StockDistributionFinanceFact`，声明即冻结、入账后回填），不做借贷过账、不产生公司或投资者现金；送股仅额外受可分配利润上限约束。注册资本法定事实按面值口径随入账演进（见上节），股本/资本公积报表科目与合并列报的接续建模属于后续账面批次。
- 送转公开 typed 公告与 NPC 本人获知尚未接通（announce 只推进状态机，不产生公开公告发布）。
- 配股、增发、回购注销的实际登记仍未实现。

## 尚未模拟

新股上市初期无涨跌幅限制、科创板/北交所的全部差异、停复牌、退市整理、盘中临停、
大宗交易、融资融券和真实券商的个性化佣金舍入均不在当前版本范围。界面不得把游戏结果描述为真实
投资建议或真实券商成交结果。

公司经营的收付不进入证券投资者资金池。工商年度所得税只在年末计提并尝试支付，未模拟
法定预缴及汇算清缴期限；商业借款、地产项目借款与银行定期存款采用显式合同到期日收付，
不足时保留未付事实并逐自然日重试，不自动续贷、补钱或触发停牌、退市及股东清算。
付款失败公开材料属于游戏经营风险事实，不等同于现实法定重大违约认定。完整简化及法源
限制见 [`company-accounting.md`](company-accounting.md) §2.6。

固定集团只支持单层、精确基点持股与唯一配对的单批内部商品交易；来源身份不完整、
存货成本池跨 item 歧义、同成员对多个内部销售批次、跨年旧未售内部批次及非工商买方
内部商品采购均显式不支持。内部未售成本按移动加权池均匀比例分摊，不采用 FIFO。
这些为游戏装配简化，不是现实上市公司合并规则；详见
[`company-accounting.md`](company-accounting.md) §8，不改变证券交易、T+1、费用或投资者资金规则。

## 快捷委托与定时自动（2026-10-05）

前端手数输入按100股转换为原 Intent 整数股；买入整手、可卖/T+1、零股及板块单笔上限复用既有校验。比例和全部使用可用整手，不自动突破单笔上限。可买能力扣除已挂单资源及成交额、配置佣金（含最低佣金）、0.01‰过户费；只作预检查，最终 engine 拒单/结算仍为权威。二进制费率乘法和银行家舍入沿用 Money::apply_rate。此轮未调整费率；现有费用来源的访问边界仍按上文记录。

最小/最大保留 Lowest/Highest 意图，B1/S1 在每次提交时取对应当前真实报价；不存在报价时明确等待。定时自动是会话内 Web 功能，不是交易所原生委托类型，也不写入日终存档。

**游戏简化：** 自动按压缩休市后的游戏秒累计，以公开 Snapshot 进度到期执行；默认一 tick 为一秒，自定义交易日按既有阶段比例映射。暂停无进度不执行。前端批次跨多个间隔时，只用最新权威资源执行一次，不补发过去时点的委托；因此高倍率/远程批量交付不保证每个游戏秒一单。间隔最小1游戏秒，亚秒请求暂不支持；1.5秒会落到到期后的下一可用进度。页面关闭、刷新、读档或 baseline 重新同步会停止自动。资源不足保持开启，未来到期再试；切股仍绑定原证券。取消所有只撤现有自有活动订单，保持自动开启。

本次数量语义依据核对日期：2026-10-05。沪市现行[《交易规则（2026年修订）》3.3.8](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)规定竞价买入100股整数倍与不足100股余额一次卖出；[申报数量前端控制通知](https://www.sse.com.cn/lawandrules/guide/stock/jyglywznylc/tz/c/c_20230209_5716007.shtml)说明余股可单独或合并整手一次申报。本次仅核对数量条款，并沿用已登记的沪深/板块差异，不声称重验所有制度。
