# A 股交易规则基线

游戏的证券交易规则以中国大陆沪深 A 股竞价交易为基线。参数属于权威会话配置，
前端只能预检查，最终由 Rust engine 拒单或结算。

金额与每股价格的 `Money` 内部单位为分，跨端统一使用规范有符号 `i64` 十进制分
字符串；例如 `"1"` 为0.01元，`"1000000000000"` 为100亿元。Web 金融计算保持整数
精度，不接受旧数字金额；`AccountingAmount` 仍为独立元字符串。编码不改变下列交易
规则、费用或舍入，图表近似不能用于反算委托。见 [ADR-0031](decisions/0031-money-decimal-cents-wire.md)。

Escrow 并行候选的资源边界见 [ADR-0017](decisions/0017-escrow-parallel-tick.md)：
SealAllocationSnapshot 的 `DecisionResourceSnapshot::seal` 读取报价过期处理后的资源；其他密封批释放不回补本批预算。
买单使用现金 envelope，卖单现金预留恒为零。分歧 #9 的卖费实收封顶/后腿追收是明确批准的
**游戏简化**，不是交易所或券商真实清算承诺；nominal 费率与累计最低佣金不因并行化改变。
`engine::TickCommitEvidence` 与 `engine::UpdateStreamProjector` 是验证投影入口，不是另一套交易规则。
本批工程接线复核日期：2026-09-23；下列交易所条款最近一次内容核对日期：2026-09-22；费用表本次访问失败的边界另列，
不将部分来源复核冒充全部规则验收。
2026-09-25 又核对了沪市现行规则 3.5.1 与深市现行规则 3.4.2：同价同向申报的先后
依据交易主机接受申报的时间。此次只复核竞价优先原则，不代表重查了下列其他条款。

## 已实现

- 普通主板与主板风险警示股票涨跌幅 10%，创业板 20%；每只股票显式配置，避免仅凭名称猜板块。
- 最小价格变动 0.01 元。
- 沪深交易所分别判断当前自然日开闭市；只要一家在局交易所开市，共享市场时钟即可推进。
  休市证券不接受申报和撤单、不生成新行情或日 K，不以另一交易所的开市虚构成交；
  每证券的分钟历史、交易日计划期限及 T+1 日界解锁仅按本证券实际开市日推进。
  默认年度休市表仍是明确标注的模拟回退，不声称已取得未来年度真实休市公告；详见
  [`simulation-calendar.md`](simulation-calendar.md)。
- 买入申报为 100 股整数倍；主板/ST 当前模型单笔上限 1,000,000 股，创业板限价单
  上限 300,000 股、市价单上限 150,000 股；权威配置拒绝把一手改成其他数量。
- 卖出不得超过“持仓 − T+1 锁定 − 已挂卖单”；不足 100 股的零股必须随一笔卖单一次性卖出。
- 当日买入股份不可卖，下一交易日日界解锁。
- 开盘集合竞价在 09:15–09:25 接受限价申报，09:15–09:20 可撤单；09:25 一次性撮合后，
  未成交的当日有效限价单继续进入连续竞价簿。09:25–09:30 不接受新申报。
- 在允许撤单的时段，刚受理但仍有挂单余量的委托也可撤单；部分成交只撤余量，
  已全部成交则明确反馈“已成交、无法撤单”。撤单是否成功由对应股票订单簿的当前状态决定。
- **游戏简化：** 本 tick 撤单释放的资金或可卖股份，要到下一 tick 才能供新委托占用。
  本 tick 的新委托仍按轮初可用资源校验；计划即使收到撤单成功反馈，也不能在本轮复用这笔释放。
- 收盘集合竞价在 14:57–15:00 接受限价申报且不可撤单；窗口结束时按证券交易所各自的集合竞价
  清算规则一次撮合，未成交余单随紧接的日界失效。收盘竞价事件显式携带 `ClosingAuction` 阶段和
  `clearing_price`，不得误作开盘价或投影到开盘分时区域。
- 交易所归属在每只股票上显式配置。沪市集合竞价最终同价时取候选中间价。深交所规则
  3.4.3 的最终距离参照为开盘前收价、盘中/收盘最近成交价；当前游戏所有深市竞价仍统一
  使用昨收，属于尚未修正的简化，不是完整真实规则。完全同距时取低价也仅为模拟确定性。
- 连续竞价限价申报默认执行价格笼子：买入上限取参考价的 102% 与参考价加十个最小价位中的
  较高者，卖出下限取参考价的 98% 与参考价减十个最小价位中的较低者；参考价按买卖方向
  依次使用对手一档、本方一档、最新成交价/前收。
- **可选游戏简化（2026-09-27）：** 新游戏配置 `price_cage_enabled` 可关闭连续竞价
  价格笼子，默认开启；关闭后仍执行涨跌幅和其他申报规则。该选择随当前存档保存。
- 买卖双方收取交易过户费 0.01‰；卖出方另收 0.5‰ 印花税（`Exempt` 不扣税模式按
  2026-10-08 决策免征，见「开局税务模式」节的模式配对门禁）；券商佣金率和最低佣金可配置。
- **游戏简化：** 统一市价意图按涨跌停价作保护并逐档立即成交，未成交余量不进入订单簿。
  尚未细分沪深市价申报类型及其最优五档、余量转限价等差异。
- 全部未成交委托共享账户资源占用预算：买单占用成交额及费用；卖单仅占用可卖股份，不占用
  现金。撤单、日终清簿后释放相应占用，快照公开 `reserved_cash` 和按股票汇总的
  `reserved_sell_qty`，界面显示的“可用资金/可卖”必须扣除对应占用。卖单名义费用公式、税率和
  最低佣金累计口径不变；实际费用按每一成交腿从成交所得封顶收取，并按佣金 → 印花税 → 过户费
  的固定顺序分配。这是游戏简化，不等同于交易所真实清算或一般券商规则。完整口径见
  [ADR-0017 分歧 #9](decisions/0017-escrow-parallel-tick.md#5-九条分歧台账)。

## 图表周期的展示简化（2026-10-05）

默认 Web 局以每 tick 一秒显示交易时钟。自定义 `SessionSetup.ticks_per_day/auction_ticks/closing_auction_ticks` 的自定义长度局属于游戏时间缩放（简化）：时钟沿用 engine `observation_civil_instant` 的开盘900秒、连续14220秒（无收盘窗口时14400秒）和收盘180秒比例，跳过午间休市。整数 tick 可使阶段边界粗化；例如开盘10 tick 的申报结束 tick 7 显示09:25:30，不伪造另一套09:25时钟。开盘1 tick 时没有独立 PreOpen，开盘或收盘窗口为0时对应阶段缺失，均不是完整交易所时间制度。UI 常驻说明这些简化，不改变撮合阶段、原始 tick、成交或存档事实。

图表按 tick 覆盖区间的起点归入固定显示槽，默认仍每分钟60 tick、竞价每细线6 tick；自定义局没有覆盖的分钟槽保持为空，不插值生成交易。开盘 `AuctionCompleted` 落在竞价区末槽，表示本次竞价已结束；极短/非三整除局的准确事件时间以逐笔时钟为准。当前时钟在完整 tick 日界显示下一交易日开盘；逐笔末 tick 保留上一日15:00，午休端点成交保留11:30，不冒充13:00新成交。

Web 的周 K、月 K 使用 `aggregateCandles` 按自然周（周一至周日）和公历自然月合并已有日 K；虚拟前史与实际运行均携带明确公历日期。分桶不因可视窗口首根变化而改变，不补造休市日或无成交区间，当前未结束周期只展示已有事实。按用户最新决定，不保留每5／20个交易日聚合选项。MA5／10／20／30／60 在所选周期的合并收盘价上计算 SMA，N 指 N 根所选周期 K 线。聚合只用于绘图，不改变 engine 日 K、成交、委托、结算或时间规则；合并量为股数之和，展示换算为手，无权威合并成交额时详情显示不可用。季 K、年 K 和分钟 K、可编辑 MA 由后续实施接入，不因列入产品需求而视为已经实现。

## NPC 策略选择

**NPC 仓位选择（2026-09-26）：** 公共执行路径不按固定单股比例或统一现金保留比例限制
策略目标，允许策略选择集中持股或持有现金。资金、真实手续费、股份、T+1 与申报规则继续
校验。个体参数表达一次目标调整步幅，不是最终仓位上限；见
[ADR-0021](decisions/0021-strategy-position-choice-and-noise-pricing.md)。同 ADR 经用户于
2026-09-27 澄清：每笔交易区分主动成交和指定价格等待，适用于各类 NPC 与玩家。
散户现有主动买卖与游资趋势买卖使用公共限价委托的“最高／最低”价格选项，轮到该股票
受理该单时确定一次价格：开启笼子的连续竞价取笼子与涨跌幅范围的交集，关闭笼子或
集合竞价使用涨跌停价。最高价买单数量按涨停价与本局费用估算并预留资金，实际报价
较低时释放差额；释放额不回补本 tick 预算。未成交部分按确定的价格留簿，机构自己的估值限制与游资反转
策略的等价报价保留。没有增加特殊做市账户或保证流动性的资金。

公共接口也允许最低价买入和最高价卖出，分别使用跌停价与涨停价。价格选项是游戏下单
入口功能，不是另一种交易所市价申报；它与已有的余量撤销市价意图不同。未受理请求保存
选价方式，已经受理的挂单只保存实际价格，行情变化、读档或竞价转连续时不自动追价。
指定价格单仍可能因盘口变化而不符合笼子；订单簿照常校验，不增加拒单后立即重试。
具体资金及类型契约见 [ADR-0022](decisions/0022-symbolic-limit-prices.md)。此次相关条款
核对日期为 2026-09-27，依据见 ADR-0021 第 5 节。

机构成本候选、风险暂停和真实买入后的不利选择为**游戏策略假设**，不是交易所制度
或真实市场统计规律。触发与恢复门槛逐机构冻结，恢复必须由下一本人观察确认；
只暂停继续买入，不自动强制卖出、返费或补钱。已有卖出减仓可按本人净值回撤提高
紧迫度，仍受 T+1、真实费用及合法撤单窗口约束。公式与数值见
[ADR-0026](decisions/0026-individual-institution-experience.md)。

## 已知待修正的受理顺序偏差

**草稿阶段容量约定（2026-09-25）：** 请求队列、未成交挂单和待处理计划事件不按固定条数拒绝合法请求。资金、可卖股份、T+1、单笔申报数量与交易时段仍分别校验。机器资源故障应明确报告，不能伪装成交易拒绝。详见 [ADR-0019](decisions/0019-draft-market-scope-and-capacity.md)。

**计划策略（游戏规则）：** 积极交易型机构在每日开盘后的首个连续交易 tick 观察并可
建立当日到期计划；成长、均衡型机构每日观察但计划可跨日，深度价值和防御型机构
不因普通开盘自动复核；其随机观察频率也低于每天一次，允许跨日不观察。成交与撤单仍由
真实订单簿反馈，买入股份对外继续受 T+1
限制；“日内计划”指计划有效期至当日日终，不表示当日买入后可以卖出。

NPC 请求在上一 tick 的已提交状态上形成，下一 tick 受理；玩家请求验收入队后在下一 tick 参与交易。
盘前、连续交易和集合竞价已把本轮就绪的 NPC、玩家及部分计划根命令合入局部受理：
不同账户争同一股票的受理先后由该股入口实际发生的先后决定，来源标签与订单 ID 不充当优先级；
同一账户的现金和逐股可卖数量分别校验。计划链只在收到对应命令的结果后续行，
已全部成交的订单撤单会返回明确的业务失败，部分成交仍可撤剩余量。

计划根现逐个完成并交付，无须等同批其他账户的根都完成。三阶段的同账户资源争用已从候选数组位置改为接收事实：上一提交形成的 NPC 请求、两个 tick 间排队的玩家请求，以及本 tick 真正就绪的计划命令分别保留其账户内先后；这个比较只用于同账户现金或逐股可卖股份。跨账户同股委托的时间优先仍取该股入口的实际受理先后。现有 NPC 与玩家候选虽仍按来源拼成向量，但来源块不再充当账户资源裁决依据；后续仍需继续核对无关请求的等待范围，并提高真实活跃负载的整轮多线程加速比。
这些限制与交易所的价格、时间优先规则不同，迁移要求见
[ADR-0018 §7](decisions/0018-long-running-immutable-timeline.md#7-交易约束撮合顺序与并行)。

## 公司行为与现金除息边界

现金除息的共同计算使用证券所属交易所日历：权益登记日次一交易日除息，标准纯现金方案的参考价为前收盘价减税前每股现金红利。依据为沪市《交易规则（2026年修订）》4.3.1—4.3.3 和深市对应规则 4.4.1—4.4.3；两者自 2026-07-06 施行，官方原文核对及来源见[现金分红研究](../agents/remaining-questions-and-features/dividend-research.md)。不能以自然日加一代替交易日，也不能用税后红利、修改历史成交或制造成交实现除息。发行人获批调整公式时须明确区分，当前基础计算显式拒绝，不静默套用标准公式。

`company::ex_reference_price` 当前仅覆盖每股红利精确为整数分的标准纯现金计算，不对不足一分的每股方案擅自取整；非正参考价明确拒绝。这是计算基础，不代表已将除息参考价接入市场、涨跌幅基准或公司行为完整结算。股东登记、个人股息税和现金方案事实记录也不等于投资者账户已经收到款项；真实账户付款、配股／增发认购、回购委托与成交仍需共同接线。

`Simple` 的公司现金仅为账面展示，不是分红预算；分红仍须满足可分配利润和明确方案条件，投资者认购检查本人真实现金，回购须真实成交。不能把账面生成当成真实资金来源，亦不能因此给认购者补钱。沪深中国结算发行人指南本次仅返回维护页，尚未核实的碎股、尾差、配股登记与退款及回购专户规则不得猜测实现；可达性证据见[指南复核](../agents/company-system/corporate-rules-refresh.md)。

## 个人流通股股息红利差别化个人所得税（2026-10-06 登记口径）

本节登记 `company::cash_dividend_tax` 与 Session 日终收缴已接通的完整语义。法规依据为
[财税〔2012〕85号](https://fgk.chinatax.gov.cn/zcfgk/c102416/c5203902/content.html)《关于实施上市公司股息红利差别化个人所得税政策有关问题的通知》
（2013-01-01 施行）与财税〔2015〕101号《关于实施上市公司股息红利差别化个人所得税政策
有关问题的通知》（2015-09-08 施行）；条文名称与适用日期按 2026-10-06 口径登记，
并经同日非作者复核对照官方原文逐条核验（见
[复核记录](../agents/company-system/personal-dividend-tax-fix-review.md)），调整实现时必须同时更新测试与本文档。

- **三档税率（85号第一条、101号第一条）**：持股期限 1 个月以内（含）的，股息红利所得
  全额计入应纳税所得额，按 20% 计税；1 个月以上至 1 年（含）的，暂减按 50% 计入
  （实际税负 10%）；超过 1 年的，暂免征收（0%）。
- **持股期限（85号第一条第二款）**：指个人取得股票之日至转让交割之日前一日的持有时间。
  “1 个月”“1 年”的自然年（月）定义见 85号第八条：“1 个月”指上月某日至本月同日前一日；
  “1 年”指上年同月同日至本年同月同日的前一日。
  实现上卖出日（交割日）当日仍计入档期判断的边界（`disposed_on <= 周年日` 归上一档）。
- **月末边界钳制（实现口径，2026-10-06）**：取得日在目标月无对应日（如 1 月 31 日对 2 月、
  2 月 29 日跨平年）时，期间边界钳制到目标月最后一日（1 月 31 日 → 2 月 28/29 日；
  2 月 29 日 → 次年 2 月 28 日），依据《民法典》第二百零一条、第二百零二条的期间计算
  规则（无对应日的，月末日为期间最后一日）并结合 85号第八条“同日”定义。不得对整类
  月末取得批次拒绝计税。
- **派发不预扣、转让时扣收（101号第二条；资金账户扣收与不足通知补足口径见 85号第二条）**：上市公司派发股息红利时，
  对个人持股 1 年以内（含）的不代扣；待个人转让股票时，按持股期限计算应纳税额，
  从个人资金账户中扣收。持股超过 1 年的股息在持有超一年后处置时按 0% 不产生税款。
- **账户单位与 FIFO（85号第三条）**：应纳税所得额以个人证券账户为单位计算；股份
  按每日日终净增（减）数、取得日先后的先进先出原则计算持股期限。实现为逐自然日
  `record_net_day` 净额批次与 FIFO 处置记录。
- **送转股份进入税账（2026-10-06 集成修复轮登记）**：送股（股份股利）与转增
  （公积金转增股本）属 85号第六条第（八）项明列的「个人从公开发行和转让市场
  取得的上市公司股票」，其持股期限依第一条第二款自**取得之日**起算；取得之日
  即 R+1 到账日（沪业字〔2024〕6号 / 深业〔2025〕68号 2.5节：送转新增股份上市日
  R+1）。实现为：R+1 当日在当日公开市场日结之后，以非交易过户回执自身事件身份
  作为**同日正向续记**落入税账 FIFO（取得日 = R+1，来源 `CorporateAction`），
  不与原股份视为同一批次；继承限售属性的送转 lot 经既有映射按
  `StatutoryRestricted` 口径计税（85号第四条：解禁前分红 10%、处置档期自
  解禁日起算）。依据说明：85号原文组合直接决定口径（第六条（八）+第一条第二款
  +第三条），中国结算《上市公司股息红利差别化个人所得税政策常见问题解答》的
  单句原文未在公开渠道取得，未作为依据。**实现口径偏差登记：** 85号第三条的
  「每日日终净增（减）」是逐日净额；本引擎对同一自然日的公开市场回执与送转到账
  分列两条日结事实（先市场后送转，顺序确定），不做事前净额合并——当同日既有
  卖出又有送转到账时，税账处置数量多于逐日净额口径（偏向多计处置、新股按新
  取得日记档），后续批次对齐后再校正。同日两条回执以穷尽 `match` 于
  `MovementScope` 派生各自税账事件 id（未知 scope 编译期强制显式决策），
  恢复勾稽校验每个已配置税账的名册回执都必须有对应日结事实，缺失显式失败。
- **限售股（85号第四条）**：解禁前取得的股息红利所得暂减按 50% 计入（实际税负 10%）；
  持股期限自解禁之日起计算。实现为 `StatutoryRestricted` 批次：解禁前到账的分红按 10%
  直接计税，处置档期以 `release_on` 起算。法定依据分类（财税〔2009〕167号、
  财税〔2010〕70号）需显式证据字段。
- **亚分税额（实现口径，2026-10-06）**：85号/101号未规定应纳税额不足一分的处理，
  官方明文未取得。登记为本游戏实现口径：**按持有人每笔分红合计应纳税额四舍五入
  （half-up）到分**；每笔分红内部仍用精确分数求值，仅在按笔汇总后取整，登记与
  收缴回执保留精确事实。例：每股 7 分 × 3 股 × 20% = 4.2 分 → 收缴 4 分。
- **资金不足的部分收缴与追缴（85号第二条）**：划收时资金账户余额不足的，按
  `min(应纳税额, 账户真实现金)` 部分扣收，不虚构资金、不叠加历史已收缴税额抬高上限；
  未清税额由后续每次日终继续追缴，并通过 `GameSession::dividend_tax_outstanding_views`
  typed 查询面（ts-rs 正规导出 + Web 严格 parser）显式暴露未划收税额、`needs_funds`
  与原因（`InsufficientAvailableCash`/`Cleared`）。本地 WASM 宿主经 owner 隔离导出
  （`owner_dividend_tax_outstanding_views`），公司行为面板（CompanyPanel 体系内的
  DividendTaxPanel）展示本人未清税额并对 `needs_funds` 显式提示；Tauri/远程宿主的
  税务状态查询留待后续批次，不支持时 UI 显式提示而非静默。
- **显式不支持**：居民企业、证券投资基金、非居民以及未配置税务身份
  （`TreatmentNotConfigured`）不按个人口径计税，显式拒绝或不产生个人税事实；
  同一账户混合法定限售与流通税股批次的处置显式不支持。
- **装配期限制**：税账（`configure_cash_dividend_tax_book`）只能在名册尚无历史日结回执
  且无已登记分红时配置；事后配置无法重建 FIFO 税事实并会令日终永久失败，因此显式拒绝。

### 开局税务模式与默认税籍（2026-10-08 三层产品决策登记）

本节登记新局税务模式选项（`SessionSetup.dividend_tax_mode` + `flat_withholding_bp`）
与默认税籍语义，属 2026-10-06 用户产品决策与 2026-10-08 三层修订（ADR-0040）：
「简税默认+大A可选（按原话三层）」「简税比例 10%（推荐）——分红到账时直接扣，
无持股期档位；开局参数可编辑，机构不另算」「不扣税：连印花税也免（佣金/过户费照付）」。

- **三层模式与持久化**：默认 `FlatWithholding`（简税），可选 `AShareIndividual`
  （大 A 个人差别化）与 `Exempt`（不扣税）。`dividend_tax_mode` 为新档必填字段，
  无 serde 兼容默认；比例采用下述三态契约。旧两变体枚举值（`IndividualPublicMarket`）
  已按无兼容原则整体删除，携带旧值的档在 engine 反序列化与 Web `parseSetup` 两端
  显式拒绝，不静默映射；
  恢复后装配期自动配置与计税语义不变。
- **简税比例三态契约**：`flat_withholding_bp` 仅 `FlatWithholding` 模式必填（合法域
  0..=10000bp，即最高全额代扣——超过会破坏原子代扣不变量，显式拒绝）；其他模式
  缺失或 `null` 表示不携带，携带数值显式拒绝，序列化输出 `null`。默认值 1000bp
  （10%）由 Web `DEFAULT_SETUP` 与 UI 草稿层提供，不设 serde 默认，杜绝旧档静默
  取默认的兼容路径。
- **简税（`FlatWithholding`）语义（游戏化简化登记）**：分红付款日对名册每位**账户**
  持有人（玩家、散户 NPC、机构 NPC——机构不另算，同样代扣）按 比例 × 税前应得
  直接代扣；代扣额按持有人四舍五入（half-up）到分（例：每股 7 分 × 3 股 × 5000bp
  = 10.5 分 → 扣 11 分）。**无持股期档位、无税账 FIFO、卖出不补税**。代扣与到账
  同事务原子执行（先贷记税前应得、立即扣收），代扣额 ≤ 税前应得 ≤ 到账后现金，
  故**不存在余额不足的部分收缴与追缴情形**，也不产生未清税额事实——这是简税相对
  个人差别化口径的实现口径（更简模型，如实登记）。**不创建、不持久化任何
  `CashDividendTaxBook`**（简税档 `dividend_tax_books` 恒为空数组）；代扣事实以
  `FlatWithholdingReceipt`（payment_id/plan_id/account/paid_on/gross/rate_bp/withheld，
  严格持久化）逐笔记档，恢复勾稽校验每位账户持有人到账恰有一条金额一致回执、
  代扣额可按比例复算，Web 严格 parser 同构。简税模式下显式配置个人差别化税账
  （`configure_dividend_tax_book`）被显式拒绝——代扣已覆盖全部持有人，叠加会对
  同一笔分红双重计税。**边界**：外部具名持有人（`HolderId::External`）无游戏账户，
  不代扣、不产生个人税事实（与 AShare 模式同一边界，登记为引擎边界而非税法口径）。
- **大 A 方式（`AShareIndividual`）的装配期自动开账**：配置完整股东名册
  （`GameSession::configure_share_registry`）成功后，引擎在同一候选副本上为每个
  「个人」身份的账户持有人走既有 `configure_cash_dividend_tax_book` 自动配置
  `IndividualPublicMarket` 税账；名册或税账任一步失败都不留半配置状态。计税语义
  即上节登记的个人差别化完整口径（三档/FIFO/转让补缴/部分收缴追缴），不变。
  个人身份分类的权威映射是 `taxpayer_identity_of_kind`：玩家（Player）与自然人
  散户 NPC（Retail）属个人；机构（Inst）与游资（Hot）NPC 属非个人。
- **机构/游资边界**：非个人身份保持 `TreatmentNotConfigured`，不产生个人税事实；
  企业/机构计税未实现（显式登记「企业/机构税未实现」，查询视图以
  `TaxpayerIdentity::NonIndividualPending` 呈现）。简税模式下机构持有人不落入
  `TreatmentNotConfigured`——其分红同样被代扣（机构不另算），状态视图以
  `DividendTaxStatus::FlatWithholding` 呈现。
- **不扣税模式（`Exempt`）与印花税门禁**：引擎装配期不为任何身份自动配置税账
  （新局档 `dividend_tax_books` 保持空数组）；宿主显式装配期命令
  `configure_dividend_tax_book` 仍是既有入口，开局后被拒是正确行为（装配期守卫），
  错误完整上抛不静默降级。**`Exempt` 同时免征交易环节卖出印花税（2026-10-08
  决策），佣金与过户费照付**；实现为 setup 校验的模式配对——`Exempt` 要求
  `stamp_tax_rate == 0`，`FlatWithholding`／`AShareIndividual` 要求
  `stamp_tax_rate == 0.0005`（现行 A 股基线）——该配对在 `SessionSetup::validate`
  单一入口强制，费用管线（结算、名义费用、NPC 估算与恢复重放）全部经 `GameConfig`
  传播，不存在绕过配对的第二条计费路径。违反配对的 setup 在创建与恢复两端显式拒绝。
  **测试覆盖缺口（2026-10-08）**：现有三层模式卖出测试以 5 股 × 10 元成交，过户费
  为 0.05 分、按既有 `Money::apply_rate` 舍入后为 0 分；`transfer_fee >= 0` 断言不能
  证明 `Exempt` 的非零过户费照收。仍需过户费舍入后大于 0 分的真实成交用例覆盖，
  不将现有小额 fixture 的通过结果宣称为完整过户费验收。
- **装配期后进入的股东**：经二级市场净买入在日后进入股东登记的账户不自动补开
  个人税账（受既有装配期守卫约束）。AShare 模式下其分红保持
  `TreatmentNotConfigured`；简税模式下装配期后进入的账户持有人同样在付款日被
  代扣（代扣不依赖税账，按名册到账事实执行）。这是当前引擎边界，不是税法口径。
- **企业/机构税抽象层留白**：`DividendTaxProfile` 已含 `ResidentEnterprise` /
  `SecuritiesFund` / `NonResident` 显式变体；`TaxpayerIdentity::NonIndividualPending`
  是非个人身份的统一扩展位。实现其计税前不得把非个人身份映射为任何已实现身份
  （`CashDividendTaxBook::validate` 对非个人身份显式拒绝）。
- **查询与 UI 入口**：`GameSession::account_dividend_tax_status(account)` 只读返回
  模式、身份分类与每个已登记证券的税账状态（未知账户显式报错）；本地 WASM 宿主以
  owner 隔离导出 `owner_dividend_tax_status` / `owner_dividend_tax_outstanding_views` /
  `configure_dividend_tax_book`。新局创建界面（TaxModeInput，默认勾选简税并附比例
  输入，非法比例不写草稿）与公司行为面板（DividendTaxPanel）已接线；Tauri/远程
  宿主的税务状态查询留待后续批次，不支持时 UI 显式提示。

## 送转（股票股利与资本公积转增）实际登记（2026-10-06）

送转已接通为真实股份登记全链路：显式方案批准（`GameSession::approve_stock_distribution`）→ 公告状态推进 → R 日按登记快照冻结账户级碎股分配（沪深碎股降序、同余 seed 洗牌沿用既有算法，seed 由事件身份派生）→ R+1 以 `MovementScope::NonTradingTransfer` 在股东名册同日追加非交易过户回执落新增 lot、投资者账户真实加股（只增持仓数量，不产生现金、不进 T+1 锁定）→ 发行股数守恒更新（名册、发行人身份与 setup 初始股数加增发回放一致，恢复按此严格校验）。R+1 入账依据沪深《证券发行人业务指南》归档摘录（沪业字〔2024〕6号 2.5节、深业〔2025〕68号 2.5节），见[送转基础记录](../agents/company-system/stock-distribution.md)。限售继承：持有者原 lots 全部为同一限售类时新 lot 继承该限售属性与截止日（深市指南有明文；**沪市对应条文未定位，登记为证据缺口**，不跨市场推断）；混合限售来源显式拒绝整日回滚，保留 `SourceLotAttributionPending` 语义，不按比例摊；原限售截止日已早于入账日的按 Unrestricted 登记（处置路径本就视同可流通）。回购专户股份按既有 facts 排除。

**每股面值与多次送转语义（2026-10-06 修复轮）：** 面值遵循现实口径——每股面值恒定，送转入账后注册资本按 面值×新增股数 演进。首次送转声明的面值由「已绑定注册资本法定事实 ÷ 名册当前已发行股数」整除推导并就此固定；同一发行人的后续送转必须沿用同一面值，不允许用增大后的发行股数反推出缩小的面值。送转真实入账时，Simple 账面的注册资本法定事实按上述金额演进（`source_evidence` 不变，显式 bind-once 入口仍拒绝直接改写），各次送转声明以 `registered_capital_at_approval` 冻结批准时点注册资本作为历史；恢复校验与 Web 严格 parser 都按「当前法定注册资本 − 批准日当天及之后才入账的送转/配股股本增加 + 批准日当天及之后注销/缩股核减」双向重构批准时点口径核对（修复轮补减资方向：漏加回会使注销后既有声明被误拒）。送股（股票股利）的可分配利润上限、法定公积金 50% 免计提门槛均按演进后的注册资本核定（未入账送转的预计股本计入门槛核定的注册资本口径，避免批准后由自身增资重新触发计提而卡死入账）。

除权参考价按上市地交易所**分列参数化**，两市措辞口径不同、禁止合并：沪市 4.3.1 用"流通股份变动比例"、深市 4.4.1 用"股份变动比例"（`StockDistributionExRightsFormula::ShanghaiCirculatingShareChange` / `ShenzhenShareChange`，公式变体与交易所不匹配显式拒绝）。本节公式仅承载送转分量；配股价格分量（`配股价 × 实际认购比例`）已按现行口径接入除权公式，见「配股／增发实际执行」节的「除权公式（配股项接入）」：参考价 =（前收盘价 − 同日合计税前每股现金红利）÷（1 + 变动比例），比例用百万分之一股整数单位；同日多起送转事件、或配股×送转同日的合并口径（相加还是复合）未在官方材料核实，**在方案受理时即显式拒绝**（`approve_stock_distribution` / `approve_rights_offering` 互相预检同发行人同证券同除权日的既有事件，直接拒绝同日第二起碰撞事件，不再推迟到 R+1 首 tick 的除权准备；偏好自动送转提案对同除权日配股事件同样拒绝并记入偏好台账）。除权参考价作为行情前收与涨跌幅基准，与现金除息共用同一锚组（`AppliedExReferenceGroup`），不覆写历史成交。**游戏简化：** 除法结果按最小价位取整数分时使用银行家舍入（half-to-even，与 `Money` 既有纪律一致）；沪深规则条文只给出公式，分位舍入方向未在已核验摘录中写明，取得官方口径后再行校正。

- 送转公开 typed 公告与 NPC 本人获知尚未接通（announce 只推进状态机，不产生公开公告发布）。

## 拆股／缩股实际执行（2026-10-07 S1 批，ADR-0039 决策 3）

拆股（股份拆细，1 拆 N）与缩股（股份合并，N 并 1）已接通为真实全链路
（显式方案入口 `GameSession::approve_share_split`；公司行为基础机制，不设
新局开关）。依据按「明文／解读／缺口」三级登记（官方研究记录见
[拆股台账](../agents/company-system/share-split.md)）：

- **制度依据分级**：
  - **明文**：沪市《交易规则（2026 年修订）》4.3.1—4.3.3（公式条文 4.3.2；
    本批直接核验[官方 docx 原文](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)）：
    除权除息事由列举「权益分派、公积金转增股本、配股等**情况**」、权益登记日
    次一交易日处理、`除权（息）参考价格＝[（前收盘价格−现金红利）＋配股价格×
    变动比例]÷（1＋变动比例）`、发行人可申请调整公式；深市对应规则
    4.4.1—4.4.3（措辞「股份变动比例」，仓库既有核验摘录）。新《公司法》
    （2023 修订）第 142 条面额股／无面额股可选、第 148 条面额股发行价不得
    低于票面金额——面值非必须 1 元（紫金矿业 0.1 元先例），制度上存在不同
    面值。
  - **解读**：公式代入**负／正比例**即覆盖缩股／拆股（10 并 1 → 变动比例
    −0.9 → 参考价 = 前收 × 10）。官方条文未例示负比例代入，此口径有股权分置
    改革缩股（如吉林敖东 1:0.6074）等市场实践先例，登记为解读级。
  - **缺口**：**拆股在 A 股无常规通道依据与任何先例**——公司法无专门股份
    拆细程序、沪深《证券发行人业务指南》无拆股条文、学术界（谢德仁 2018）
    指出送股／转股经济实质即股份拆细并呼吁建立拆细制度。**缩股仅见于特殊
    场景**（破产重整出资人权益调整——《企业破产法》第 85 条第 2 款出资人组
    表决，如 *ST创智 2011；股改缩股对价；纯 B 股缩股保上市），无常规可提案
    通道。ADR-0039 决策 3 用户拍板「拆股等也要实现」→ 本机制按标准股份
    拆细／合并语义建模，**登记为游戏实现口径，不冒充官方通道**。
- **方向与比例**：整数比例 N ≥ 2。拆股每 1 股换 N 股；缩股每 N 股换 1 股。
  缩股碎股（每户 q mod N）按送转碎股同一先例口径处理：余数降序、同数由
  事件身份派生 seed 洗牌、依序各多得 1 股（官方对缩股碎股无统一明文，
  B 股缩股个案公告各异——登记为游戏口径）。拆股逐户乘 N 恒整除，无碎股。
- **面值与注册资本**：拆股面值 ÷ N（须整除为整数分，否则受理显式拒绝）、
  注册资本不变；缩股面值 × N、注册资本按「旧股口径消灭面值」核减 =
  par_before × (S_before − N×S_after)（碎股消灭部分；整除缩股注册资本不变）。
  面值权威链：任一拆股／缩股声明把面值重锚到其新面值，其后的送转声明与
  后续重新计值必须沿用（送转本身不改变面值；无重新计值事实时沿用送转
  bind-once 面值或由法定注册资本 ÷ 发行股数整除推导）。
- **回购专户参与**：拆股／缩股是全体股份的重新计值，不是权益分派——
  证监会回购规则第 13 条的专户失权针对「利润分配与公积金转增股本」，不
  覆盖重新计值，因此专户（IssuerTreasury）股份按同一比例换算（与送转排除
  专户形成语义区分）。
- **登记与入账日程**：按送转先例口径（拆股／缩股无官方 R/R+1 条文，登记为
  游戏口径）：显式方案 → 公告 → R 日冻结登记快照并按确定性算法换算 →
  R+1（= 除权日，权益登记日次一交易日）以新 `MovementScope::
  ShareReDenomination` 非交易回执入账：拆股每户新增 lot（取得日 = R+1）；
  缩股 FIFO 核减原 lot（**未消耗的存活 lot 保留原 id 与取得日**——取得日
  延续；核减允许越过未解禁限售 lot，重新计值不是转让，限售属性由存活 lot
  承载）。投资者账户持仓同步换算（T+1 锁定数量按换算比例等比缩小）。
- **税账**（无官方明文，登记为游戏实现口径）：
  - 拆股增量（q×(N−1)）按「取得日 = R+1」同日正向续记进个人税账 FIFO
    （与送转 85号第六条（八）同一保守口径；拆股新增不是股息红利所得，
    不产生应税事实）；
  - 缩股核减走**非应税**重新计值核减（`TaxRedenominationReceipt` 留痕 FIFO
    核减片段、不进入应税处置口径——重新计值不是转让，不触发补税；取得日
    由存活 lot 延续）。
- **除权公式**：参考价 = (前收 − 同日合计税前每股现金红利) × denominator ÷
  numerator（`numerator/denominator` = 新股／旧股比例的精确有理数，避免缩股
  1/N 微数二次舍入），银行家舍入到分（游戏简化，与送转一致）；交易所分列
  参数化（沪「流通股份变动比例」／深「股份变动比例」，变体与交易所不匹配
  显式拒绝）；可与同日现金红利合并成组；**拆股／缩股×送转、×配股、或第二起
  重新计值同除权日的合并口径未核实，受理时三层预检显式拒绝**（对齐 0a38e52e
  送转×配股先例；偏好自动送转提案对同除权日拆股事件同样按存在性保守守卫并
  记入偏好台账）。
- **typed 公告**：方案公告复用既有公告通道（公告日 18:00 相位、恰好一次；
  `AnnouncementContent::ShareSplit`）。
- **显式不支持并登记的边界**：非整数比例缩股（现实中股改缩股比例可为任意
  有理数如 1:0.6074，本批只支持整数 N 并 1）、拆股面值非整除缩小、偏好
  自动提案（仅留 `SimpleCompanyPreferences` 结构扩展位；现实中无常规提案
  通道）、拆股／缩股与送转／配股同日合并除权。

## 公司行为偏好自动提案（2026-10-07，游戏化设计）

**本节登记的是游戏机制，不是官方规则**：现实中分红/送转由上市公司治理程序（董事会预案、
股东大会决议）发起，其内部审议细节不公开建模；本游戏以「每公司显式可配置的行为偏好」在
simple 模型内近似该发起方（ADR-0037：偏好自动方案与显式 API 并存；公司决策不由投资者发起）。

- **偏好属于模型内部**（`company/simple/preferences.rs`）：每公司显式配置现金分红偏好
  （目标派息比例 bp、最小可分配利润门槛、相邻提案最小结算周期间隔）与送转偏好（门槛、
  每股送转比例、累计股本扩张上限、周期间隔）；未配置 = 无偏好 = 不自动产生任何方案
  （安全默认，不是隐含的默认经营风格）。配股/增发/回购偏好项为结构扩展位，机制未实现。
- **只提案、不旁路**：评估发生在结算周期末日结算完成后的日结候选事务内，构造的方案走与
  显式 API 完全相同的 `approve_cash_dividend` / `approve_stock_distribution` 入口与同一
  announce/登记/入账状态机、同一制度校验（可分配利润、法定公积金、注册资本法定事实、
  完整名册）；偏好触发不减少任何校验。提案被制度拒绝时原因如实记入偏好台账（同周期同因
  幂等、每周期每类别至多评估一次，不产生重试风暴），不令日结失败。
- **游戏化派息封顶（非官方规则）**：自动现金分红提案的每股派息上限按**实际日程推导的
  跌停敞口余量**计算，防止除息参考价非正（参考价非正会使除息日日结致命失败，自动提案
  不得把局推向不可结算状态）。推导口径：
  - 锚 = 提案时点最新收盘价（= 结算周期末日当时最后一个交易日的收盘，评估发生在周期
    末日日结后、批准日开市前，锚之后每个交易日收盘相对前一收盘最多再跌一个跌停幅度）；
  - 敞露交易日数 n = `(周期末日, 登记日]` 区间内的交易所交易日数，按方案日程确定性计算
    （批准日 = 公告日 = 周期末日次一自然日，登记日 = 公告日后首个交易日且不与公告日同日，
    因此 n 恒为 1 或 2：公告日为交易日时 2，休市时 1；跨春节等长假不放大 n，因为长假中
    无交易日收盘）；涨跌幅限制取该股适用的整数基点；
  - 最坏登记日收盘 = **从锚出发迭代引擎真实跌停链 n 步**的最小可能收盘（`market` 的
    `price_bound` 整数逻辑：昨收 × (1−p) 按**正数四舍五入**取至最小价位；**跌停幅度不足
    一个价位（舍入结果未离开昨收）时强制至少下移一个价位**；最低不低于一个价位）。
    该迭代与撮合引擎共用同一整数核心，不另行闭式近似。历史教训（2026-10-07 修复轮 2，
    已修复）：旧实现的闭式线性下界 floor(锚 × (1 − n·p)) 依托「四舍五入偏上 ⇒ n 日收盘
    ≥ 锚×(1−p)^n」的推断，漏掉低价域守卫——锚 × p 不足半个价位时守卫强制整价位下移，
    单日实际跌幅超过 p（反例：4 分锚 @10% 板两日实际 4→3→2，闭式却给 3；触发域为
    10% 板锚 3–5 分、5% 板锚 3–10 分 × n=2），按闭式封顶会使最坏除息参考价非正。
  - 除息日参考价 = 登记日收盘 − 同除息日合计税前每股红利（纯现金组），故合计红利的封顶
    = 最小可能收盘 − 1 分；**同除息日的既有方案（显式 + 自动）gross 合并计入**，本提案
    只能使用剩余额度，占满/超出时提案被拒并如实记入台账，下一结算周期再评估；
  - 同除息日若还有送转事件（合并除权组，参考价 = (前收 − 现金红利)/(1 + 股份变动比例)），
    分子须保留 `1 + ceil(变动比例/10^6)` 分（10 送 10 即 2 分）才能保证除权参考价 ≥ 1 分，
    封顶相应收紧；自动送转提案同样做合并余量校验，且**同除权日已存在送转事件时直接
    拒绝**（两起送转事件的合并除权口径未在官方材料核实，叠加会在除权日日结显式失败）；
    **同除权日已存在配股事件时同样直接拒绝**（2026-10-07 最终交叉修复：配股×送转
    同日的合并除权口径未核实，受理时实际认购比例未定，按事件存在性保守守卫并记入
    偏好台账）。
  余量推导只覆盖「公告→登记」的敞口：除息日开盘前安装的除息参考价即成为当日昨收，
  当日交易的跌停下限按同一守卫语义（四舍五入到价位、跌停幅度不足一个价位时强制整
  价位下移、最低一个价位）计算，恒 ≥ 1 分，因此**除息日当日再跌停也不会使价格非正**；
  除息参考价本身在最坏日程 + 连续一字跌停下仍 ≥ 1 分（上述迭代推导：封顶恰留 1 分）。
  剩余已知边界：显式 API 不受此游戏化封顶约束（用户自担，与自动提案并存语义）；两起
  **显式**送转方案、或显式送转×配股方案同除权日在**受理时**即被显式拒绝（合并口径
  未核实、显式拒绝而非近似；同日碰撞不再推迟到除权日日结才失败）；极低股价（数分）
  叠加极大送转比例或大跌幅的极端组合可能因迭代链触底一个
  价位导致封顶非正而被拒——那是如实拒绝，不是静默近似。
- **游戏化日期节奏**：自动提案的批准日 = 公告日 = 周期末日的次一自然日；权益登记日为公告日
  后的首个交易日且不与公告日同日（保证既有 typed 公告在公告日日结仍处于 Announced 状态、
  经同一公开通道发布）；除息/除权日为登记日次一交易日；现金派发日 = 除息日（最短合法间隔）。
- 自动送转提案固定采用送股（`BonusShares`）：转增虽已可经显式 API 受理（N3 批起有
  资本公积科目与余额校验），但偏好自动提案仍固定送股——账面资本公积余额依赖配股等
  前置事件形成，自动提案不保证来源充足；且库藏股存在时强制要求回购专户登记事实，
  本批不自动提案转增。
- 结构前置不满足（发行人未上市、无完整股东名册）时不评估、不提案也不记录拒绝；偏好
  评估为轻量整数比较，只在结算周期末日发生，无每 tick 开销。
- 严格持久化：偏好配置（`SimpleCompanyConfig.preferences`）与拒绝台账
  （`SimpleCompanyState.preference_ledger`）均为新字段、无 serde 默认，缺失该字段的旧档
  显式拒绝；恢复后评估行为不变、不重复产生历史方案。台账只读查询接口已就绪；2026-10-07
  S2 批起本机 WASM 宿主以 `company_preference_rejections` 只读查询最近已完成日终存档中的
  台账（首个日终完成前显式报错，不冒充空台账），公司面板呈现、新局偏好配置入口
  （`SimpleCompanyPreferences` 分红/送转项，未配置=不自动提案）同批接线；Tauri/远程宿主
  查询面留待后续批次，不支持时 UI 显式提示。

## 快捷委托与定时自动（2026-10-05）
