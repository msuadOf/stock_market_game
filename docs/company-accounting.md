## 1. 规则时间与模拟时间（会计规则适用假设）

本节登记规则来源、公布的生效安排和游戏对模拟日期的解释，不代表运行时存在可序列化的
`RegulationProfile`。当前实现没有该 Rust 类型，也不承诺跨游戏更新冻结一整套规则、按旧规则恢复
旧存档或提供兼容迁移；允许破坏性更新使旧存档失效。`simulation_policy_id` 是职责身份，
不是规则集版本或跨更新兼容标记。

同一运行内的政策选择和已发生事实仍按当前实现保持一致。当前 `CalendarPolicy` 是另一项明确的
运行事实：它包含完整日历数据与 digest，随当前 `SaveSlot` 保存，恢复时重建并校验；这不承诺
未来版本仍接受旧结构或旧政策数据。存档仍严格要求完整当前结构，任何不完整或矛盾事实显式拒绝，
不自动迁移、补字段或改写政策。

1. 会计规则按模拟日期与下列已公布生效安排解释；游戏使用当前实现支持的规则与假设，
   不把这个解释包装成随存档跨更新冻结的 `RegulationProfile`。
2. **默认 2030-01-01 开局**：境内上市公司届时已越过《企业会计准则第30号——
   财务报表列报》（财会〔2026〕11号）对"其他境内上市企业"设定的 **2029-01-01**
   生效门槛；非境内外同时上市的保险公司也已越过《企业会计准则第25号——保险
   合同》（财会〔2020〕20号）对"其他执行企业会计准则的企业"设定的
   **2026-01-01** 门槛。两者均直接适用，是已公布生效安排的直接推论（verified-official）。
3. **早期开局（2000-01-01 起）**：统一适用本清单现行准则文本，依据是各修订通知
   明示的"允许/鼓励提前执行"（财会〔2017〕22号、财会〔2026〕11号通知原文均载明）。
   这是**游戏假设**（`game-assumption-early-adoption`）：不逐年重演 2001 企业会计
   制度 → 2006 准则体系 → 2014/2017 修订的历史演进，也不声称还原各年份实际
   适用规则。
4. 未来生效条目（生效日晚于取证日）必须同时具备文号、官方原文 URL、发布日期
   ——见 `policy_manifest` 测试的 `future-without-notice` 拒绝用例；不引用任何
   未发布的修订草案。

### 2.6 经营节奏游戏假设（Company Operations）

🎮 `game-assumption-operations-pacing` 登记以下五项版本化简化：银行存款吸收与贷款发放按确定性
存贷日日程执行；地产开发中断暂停开发支出但不延长自然日完工时钟；地产完工后不再发生新的预售，
现售不在本模型；保险/地产信用恶化仅记录为风险事件、不自动重估经营面；保险赔案按确定性保障日
日程发生、不经经营到期调度队列。以上为游戏假设，**不构成真实银行、地产或保险经营节奏声明**。

经营日结的期末收付节奏同属游戏简化：工商在自然月末执行一个月直线折旧（合法零额只推进
资产寿命，不造零金额凭证）；Industrial、Bank、Insurance、RealEstate 在 12 月 31 日
全年业务结束后计提各自年度所得税，并每日以实际现金尝试支付应交余额，不模拟法定预缴
与汇算清缴期限。四行业共用 `company::income_tax` 的纯计算、严格年度状态与
`IncomeTaxOutcome`，每个真实 Owner 独立保存显式政策、年度开始时的亏损池和开局 DTA。
同年重复调用从该基准重算全年已入账业务的累计目标，而不是反复消费亏损；税前利润明确
排除 `6801` 所得税费用。累计当期税相对本年已评估税额只过账差额，递延税资产也只过账
目标余额差额；未新增业务的重复处理不增加凭证或消耗事件身份。已缴税后下调的应交
所得税净借方在资产负债表与附注列为 `CurrentTaxAssets`，不抵销增值税，不自动退款、
补现金或生成负金额分录；当前期与比较期分别按各自真实余额判断资产／负债方向。
失败不提交年度基准、亏损池、事件身份或部分账务，修复失败条件后允许重试。
历史重评从已保存的最早年度基准逐年重算后续抵扣与税额，以本年目标运动相对原运动的

| 现金分红付款 | 借 `simple_dividend_payable`、贷 `simple_dividend_settlement_asset` | 既有口径；非现金结算资产负余额表示账面/真实分离 |
| 回购注销 | 借 `4001`（面值×注销股数）、贷 `simple_capital_reserve`（等额） | 🎮 简化登记：回购资金为 ADR-0038 合成来源、从未进入账面权益，注销不按库存股成本核减权益总额（权益总额不变）；真实 A 股按库存股成本注销并核减股本与资本公积/留存收益的差异显式登记为游戏简化 |
| 缩股（重新计值） | 借 `4001`（消灭面值）、贷 `simple_capital_reserve`（等额） | 与回购注销同一简化口径；拆股面值总额不变、不产生分录 |

- **新科目**：`simple_capital_reserve`（Simple 资本公积—股本溢价，权益）与
  `simple_issuer_funding_asset`（Simple 发行人募集资金账面调整（非现金），资产），
  仅存在于 Simple 账套（五 `simple_*` 汇总科目之外的第九、十个游戏专属科目）；
  报表分类分别为新权益行 `CapitalReserve` 与新资产行
  `SimpleIssuerFundingAdjustment`（科目表未归类该行的四行业账套不列零值行，
  既有列报不变）。
- **跨期不回退不变量**：行为分录日期必须晚于最后结算日（`as_of`），禁止向已
  封账期间回写（已登记报告按原窗口冻结）；恢复校验按行为事实重构期望分录与
  账簿做多重集勾稽（计数匹配，Rust/Web 两侧同构，`cash_flow` 必须 `NonCash`），
  并重算账面展示字段核对。
- **批准时点注册资本双向重构（修复轮）**：分红/送转/配股/拆缩股声明冻结的
  `registered_capital_at_approval` 按「当前法定注册资本 − 批准日当天及之后入账的
  送转/配股股本增加 + 批准日当天及之后注销/缩股核减」重构核对（批准在日内、
  入账在日终；回购注销与缩股为减资方向，漏加回会使既有分红计划在注销后被误拒）。
- **回购注销面值（修复轮）**：核减面值读 `outstanding_par_value()` 在册面值链
  （最近**已入账**拆股/缩股重锚后沿新面值，不取历史送转/配股冻结面值；已批准
  未入账的重新计值不改变在册股份面值——注销与未生效拆股天然隔离）。送转/拆股
  新声明的面值链 `current_par_value()` 按最新声明重锚、未区分 settled/unsettled，
  为 main 既有口径，登记为已知边界（见 trading-rules「送转预留与冻结义务」）。
- **ROE 联动**：配股结算的权益净增加按规则 9 进入加权平均（`Increase`，按实际
  生效日）；送转/回购注销/缩股为权益内部结转（净额为零），不产生权益事件、
  不影响加权平均（与证监会公告〔2010〕2号口径一致——内部结转不改变归母
  净资产）。
- **账面展示字段（2026-10-08 用户决策原文：「公司账面现金/投资额展示字段：
  现金=累计留存收益（净利润−累计分红）、投资额=累计收入×固定比例（默认 30%，
  新局可编辑）；均为展示值不建模真实资金流（账面/真实分离铁律不变）」）**：
  `SimpleFinanceState.cash_book / investment_book` 按公式从权威账簿与分红付款
  事实重算（每结算周期末与分红付款后），`book_display.investment_of_revenue_bp`
  为 `SimpleFinanceConfig` 严格持久化新参数（0..10000bp，默认 3000）。**两字段
  不进资产负债表**——报表勾稽零影响，只在查询面暴露（引擎
  `CompanySystem::simple_book_display` + ts-rs `SimpleBookDisplay`；宿主 wasm
  查询与 UI 呈现留待后续批次）；不产生任何真实资金流、不加资金 owner。选择
  「不进报表」而非「投资进资产、差额挂其他」的理由：两字段定位是展示值，
  进报表会制造与真实权益的勾稽假象，违背账面/真实分离铁律。
- **cash_book 公式中「分红」的口径解释（2026-10-08 复核后显式登记）**：仅指
  **已付现金分红**（`pay_dividend` 的付款批次）；送股（股票股利）与转增不改变
  cash_book——两者是权益内部结转，不涉及现金。由此产生的已知口径差异：
  送股后资产负债表 `RetainedEarnings` 行因 4103 借记而减少、cash_book 不变
  （分母中的「净利润」按 Revenue/Expense 科目净额计，不含 4103 权益科目运动）。
  该差异按用户公式的字面口径（净利润 − 累计分红）执行并在此登记，不静默。

## 9. 既有四行业会话接线与固定集团公开链

本节开头关于 `SessionSetup.company_operations` 的接口描述是**现有旧经营接线**，不是
`SimpleFundamentals` 的后台模型。`SessionSetup.company_operations` 当前可以显式提供四行业的
`CompanySpec`、行业 `books` 和 `flow`；省略时沿用默认工商公司。自定义账套必须只有一张前史首日前一天的
`OpeningBalance`，之后由同一经营处理器生成两个完整自然年度及当年截至开局前日的前史。
发行人、总股本、行业账套与经营参数的种类必须一致，未上市子公司可以作为集团成员。上述底层算法可供
`CompanySimulation` 后续分支保留/迁移，不表示当前 simple 通过 Session 在后台运行这些算法。

用户已批准的 [ADR-0035](decisions/0035-company-system-simple-fundamentals.md) 正在接入
`CompanySystem` 共同入口及 `SimpleFundamentals`。Simple 按上一结算账面值及百分比规则更新营收、费用
并派生共同财务结果；公司报表 cash/投资额只是账面展示，不代表真实预算或追踪过的资金来源，simple
不启动旧四行业经营链。两种模式仍须提供共同财务、披露和股本行为能力。Simple 分红按可分配利润和方案等
条件实际结算到真实持股人，不因展示 cash 不足拒绝；配股/增发认购由本人真实 cash 约束，回购经真实委托
与成交，投资者账户/股份结算须幂等。`CompanySimulation` 行业业务、客户有限现金和真实公司资金流留到
后续分支；现有四行业账簿/经营代码存在不等于该新模式已接线。

Simple 的 `CompanyKind` 必须由配置显式提供，并与发行人和 Finance Owner 一致；创建、恢复和更正
均使用对应 `Industrial`、`Bank`、`Insurance`、`RealEstate` 列报口径，不能把银行或保险静默列为工商。
每种 Simple 账套在对应基础科目表上增加五个游戏专属科目：`simple_receivable`（汇总应收）、
`simple_payable`（汇总应付）、`simple_revenue`（汇总营业收入）、`simple_fixed_expense`（汇总固定费用）、
`simple_variable_expense`（汇总变动费用）。这些不是官方会计编号，也不代表实际合同、客户或付款事实。
其共同报告分类分别为 `Receivables`、`AccountsPayable`、`OperatingRevenue`、`AdministrativeExpense`、
`OperatingCost`；附注科目名称明确带有 `Simple 汇总`。固定费用和变动费用的分类仅为游戏摘要列报，
不宣称已经模拟实际管理活动、生产销货或相关 gross margin。

该摘要全部使用 `NonCash`，不把银行汇总收入或费用冒充利息、贷款、吸收存款，也不把保险汇总变动
冒充保费、赔付或 LIC，不把地产汇总收入冒充交付事实。行业专用行未发生摘要变动时，其零值或缺少
发生额只表示该模型没有生成该业务，不能解读为已经模拟并验证了真实业务。公共材料仍标记
`SimpleGenerated`。新增科目只存在于 Simple 账套；报表分类仅在科目实际存在时启用，既有
Simulation 行业科目表和经营语义不变。完整报表及所得税继续来自同一权威账簿和共享税务 Owner。

`SessionSetup.groups` 继续保存固定根公司及直接子公司持股股数，这是共同发行人/股本事实，不等同于
simple 追踪公司资金。集团关系、股本从
`CompanySpec` 派生，按 §2.1 的单层、精确基点、严格多数控制及期间覆盖规则验证。
`SaveSlot.groups` 为当前严格格式的必填事实，须与 setup 一致；恢复不迁移旧格式。
现有四行业真实月末/年末封账后生成集团五产物和对应中期不可变快照（属于上述旧仿真接线），沿根公司的排期
公开 `Consolidated` 报告；`Standalone` 与 `Consolidated` 各有独立公开 ID 与登记键。
查询只返回已公布版本，不把私有经营账簿提前公开，也不把无集团公司伪装为空合并。

工商 `trade_counterparty_events` 保存 Journal source 的对手方与往来科目身份，
`inventory_source_events` 保存 Journal source 的 item/account 身份；金额、日期和
借贷方向仍以 Journal 为唯一权威，库存数量与计价仍以 `InventoryLedger` 为权威。
恢复校验来源存在性、科目/item/对手方关系、重复身份及实际分录的身份覆盖。
历史往来按报告截止期间的真实分录净额派生，不用当前已结付的开项余额替代历史余额；
单侧及同科目多成员对的累计申报均不得超过真实账面余额。

内部赊销仅在卖方与买方的对手方、日期、应收/应付含税金额能唯一配对时装配。
收入、卖方成本、买方入库存货成本均从对应 source 读取。单一申报批次的未售成本
按真实移动加权成本池的出库成本比例、半偶分舍入均匀扣减，遵守既有 D5，不改为 FIFO；
全量出库须精确清零。利润表少数/归母损益使用当年窗口，权益变动使用报告窗口，
期末权益保留历史累计口径；报告截止期间后的分录不进入该历史报告。

以下装配边界显式拒绝而不静默生成无抵销报告：缺对手方身份的开局往来；同一
存货科目关联多个 item 导致来源成本无法唯一分解；不能唯一配对的内部购销；
同成员对多个内部销售批次；跨年仍未售出的旧内部批次；非工商买方的内部商品采购。
这些是当前 D3/D5/D6 简化装配边界，不是现实 A 股/CAS 33 的禁止规定，也不构成
全面合并会计合规声明。合并 Scope 重述按 §2.7 D5 使用各成员已有的结账有效期，工商成员还须
与自己的税务重述身份一致，不共享集团亏损池，也不持久保存另一份集团来源映射。
集团截止 Ledger 仅是已验证真实凭证的纯读投影，不将当前实际付款重新按历史现金验证，
不把晚记调整伪装成历史实际收付款。已公开合并报告以新的 `Correction` 关联旧 ID，未公开
报告重新生成 `Original` 定稿版本；排期发布使用最新定稿序号，原公开版本和个人获知历史不变。
集团刷新接缝必须运行于包含经营、结账和公开库的同一外层候选，只有全部成功才安装；
当前接线与短测验收状态见 [集团更正工作记录](../agents/remaining-questions-and-features/q23-group-tax-correction.md)，
不能仅因纯输入与生成器已存在就把完整集团组合验收标为通过。

`Consolidated` 的 `income.net_income_to_parent` 是归母净利润的必填来源，缺失时
`ReportSet::validate`、公布/公开库恢复及结账登记簿恢复均显式拒绝；不得用集团净利润
或 0 冒充归母净利润。`Standalone` 的对应字段可以合法为 `None`，合并报告合法的
`Some(0)` 也不因数值为零被拒绝。结账恢复新增检查仅覆盖这一 scope 必填条件，
不代表版本键一致性、完整更正/重述及全部 `ClosingEngine` 恢复不变量已经验证。
