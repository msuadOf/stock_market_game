# ADR-0009: 集合竞价阶段与分时图对称坐标

- **状态：** accepted
- **日期：** 2026-09-07
- **决策者：** msuad
- **关联：** ADR-0005（撮合驱动价格）、`DESIGN.md`、`UX-CONTRACT.md`

## 上下文

现有交易日从 09:30 连续竞价直接开始，前端却显示“集合竞价”文字，数据与语义不一致；分时图虽然围绕昨收估算范围，但缺少右侧涨跌幅轴，也没有 09:15–09:30 的独立竞价区。

## 决策

1. 一个默认交易日包含 900 个开盘窗口 tick（09:15–09:30）和 14,400 个连续竞价 tick（09:30–11:30、13:00–15:00），总计 15,300 tick；每 tick 仍表示一个游戏秒。开盘窗口的前 600 tick 是 09:15–09:25 集合竞价申报期，后 300 tick 是 09:25–09:30 不接受申报的 `PreOpen`。
2. `SessionSetup.auction_ticks` 显式配置整个开盘窗口长度；`0` 表示关闭并供短周期测试使用；必须小于 `ticks_per_day`。申报期按窗口的 2/3 计算。
3. 09:15–09:25 积累限价委托但不提前成交。`StockSpec.exchange` 将交易所与证券类别正交建模；
   两市均先选择最大可成交量并满足价优委托全部成交、成交价同价至少一方全部成交。沪市在
   最小未成交量仍有多个候选价时取中间价并按最小价位正数四舍五入；深市取价优买卖申报量差
   最小、再取最接近昨收的候选价，完全同距时以低价作为模拟器的确定性末级规则。09:25 按该
   唯一价格和价格时间优先一次性撮合，未成交的当日有效限价申报保留原始委托顺序并转入连续竞价簿。
4. 引擎通过 `TradingPhase::{CallAuction, PreOpen, Continuous}`、`AuctionTick` 和 `AuctionCompleted` 暴露权威状态。无交叉委托时指示价为空、成交量为零，不由前端伪造价格。
5. 有竞价成交时，成交价定义当日开盘价并计入当日 OHLCV；无成交时保持昨收零量占位，连续竞价第一笔真实成交再定义开盘价。
6. 分时横轴保留 09:15–09:25 开盘集合竞价独立区域，并将 100 个六秒槽完整铺满该区域；09:25–09:30 `PreOpen` 不占用图表宽度，也不显示为行情数据。连续竞价的 240 分钟压缩午休后等距铺开，11:30 与 13:00 共用一个午休转折点，并由 10:30、11:30/13:00、14:00 将连续交易横轴四等分。数据仍落在固定时间槽位，未来槽位留白。
7. 纵轴以昨收为 0%，取集合竞价与连续竞价全部有效点相对昨收的最大绝对偏离，并在上下使用同一价格距离，因此价格轴和右侧涨跌幅轴严格对称且包含整条曲线。

## 后果

- Web、WASM、server、Tauri 使用同一套引擎事件，不维护前端专属竞价算法。
- 高倍率事件压缩必须按竞价分钟保留最新 `AuctionTick`，并保留 `AuctionCompleted`；宿主在该事件后同步运行快照，以携带余单转簿结果。
- 新默认局启用 900 tick 集合竞价，配置必须显式提供 `auction_ticks`。
- 存档只支持当前完整结构，不维护版本迁移路径。`StockSpec.exchange`、证券类别、T+1 状态、
  委托所有权、冻结状态、策略价格窗口、随机数状态和日 K 均须完整保存；Web 与 Rust 边界不推断、
  补齐或静默改写缺失字段。
