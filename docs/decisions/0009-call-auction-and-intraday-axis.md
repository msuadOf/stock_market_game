# ADR-0009: 集合竞价阶段与分时图对称坐标

- **状态：** accepted
- **日期：** 2026-09-07
- **决策者：** msuad
- **关联：** ADR-0005（撮合驱动价格）、`DESIGN.md`、`UX-CONTRACT.md`

## 上下文

现有交易日从 09:30 连续竞价直接开始，前端却显示“集合竞价”文字，数据与语义不一致；分时图虽然围绕昨收估算范围，但缺少右侧涨跌幅轴，也没有 09:15–09:30 的独立竞价区。

## 决策

1. 一个默认交易日包含 900 个集合竞价 tick（09:15–09:30）和 14,400 个连续竞价 tick（09:30–11:30、13:00–15:00），总计 15,300 tick；每 tick 仍表示一个游戏秒。
2. `SessionSetup.auction_ticks` 显式配置竞价长度；`0` 表示关闭，兼容旧配置和短周期测试；必须小于 `ticks_per_day`。
3. 集合竞价阶段积累限价委托但不提前成交。指示价按候选委托价依次选择：最大可成交量、最小买卖量不平衡、最接近昨收、确定性价序。09:30 按该唯一价格和价格时间优先一次性撮合，未成交竞价委托取消。
4. 引擎通过 `TradingPhase`、`AuctionTick` 和 `AuctionCompleted` 暴露权威状态。无交叉委托时指示价为空、成交量为零，不由前端伪造价格。
5. 有竞价成交时，成交价定义当日开盘价并计入当日 OHLCV；无成交时保持昨收零量占位，连续竞价第一笔真实成交再定义开盘价。
6. 分时横轴保留集合竞价独立区域；连续竞价的 240 分钟压缩午休后等距铺开，11:30 与 13:00 共用一个午休转折点，并由 10:30、11:30/13:00、14:00 将连续交易横轴四等分。数据仍落在固定时间槽位，未来槽位留白。
7. 纵轴以昨收为 0%，取集合竞价与连续竞价全部有效点相对昨收的最大绝对偏离，并在上下使用同一价格距离，因此价格轴和右侧涨跌幅轴严格对称且包含整条曲线。

## 后果

- Web、WASM、server、Tauri 使用同一套引擎事件，不维护前端专属竞价算法。
- 高倍率事件压缩必须按竞价分钟保留最新 `AuctionTick`，并保留 `AuctionCompleted`。
- 旧存档缺少 `auction_ticks` 时按 0 读取；新默认局启用 900 tick 集合竞价。
