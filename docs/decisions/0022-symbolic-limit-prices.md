# ADR-0022：委托支持指定价格、最高价和最低价

- 状态：accepted（已实施）
- 日期：2026-09-27
- 修订：ADR-0021 第 3.2 节中 NPC 预先计算固定主动报价的实现。

## 用户要求与选择

用户要求增加“最高／最低”委托价位，让 NPC 和后续玩家使用同一个入口，并研究是否能简化计算。
公共 `PlaceLimit.price` 使用 `LimitPrice::Fixed(Money) | Highest | Lowest`。
这是游戏下单入口提供的选价方式；最终仍生成普通限价单，不冒充沪深交易所的一种市价申报。

未受理请求保留选价方式；轮到该股票实际处理这笔请求时，依据当时盘口与本局配置解析一次。
不提前把一批请求全部换算成数值。进入订单簿后，订单保存确定的价格，剩余部分不随行情自动追价。
玩家界面的价格选项可以后续接入，本次公共 API、排队和存档先支持完整类型。

## 价格含义

| 方向 | 最高 | 最低 |
| --- | --- | --- |
| 买入 | 涨停价与当前买入笼子上限中的较低者 | 跌停价 |
| 卖出 | 涨停价 | 跌停价与当前卖出笼子下限中的较高者 |

上表中的笼子只在开启该配置的连续竞价中应用。关闭笼子或在集合竞价时，最高为涨停价、最低为跌停价。
指定价格不自动调整，仍由交易层独立检查价格、股份、资金与交易阶段等规则。
“最高买入”并不意味着一定成交在最高价：连续竞价按已有对手单价格成交；集合竞价按清算价成交。

## 资金与并发

价格要等受理时才确定，但账户内的资金争用必须在此前明确分配，不能让不同股票同时使用同一笔钱。

- 指定价格买单按指定价与本局费用占款。
- 最高价买单按执行日涨停价与费用预留，足以覆盖受理时可能出现的合法报价。
- 最低价买单按跌停价与费用预留；这个价位不会随连续竞价盘口变化。
- 卖单只占用申报股份。资金或股份不足明确拒单，不借款，也不擅自减少申报数量。
- NPC 的最高价买单同样按涨停价含费估算数量，避免自身生成不能支付的请求。
- 实际选价完成后，通过一条明确的非成交记录更新委托价格并释放多预留的资金。
  记录保留原选价方式、预留基准价和实际申报价，供提交记录重放核对。
  该记录不产生交易量、费用、股份交付或撤单。后续成交和剩余挂单使用实际确定的价格。
- 价格解析只能作用于尚未解析的新请求。普通固定价单与已有挂单不能通过这条路径改价。
  账本重放必须能复核同一过程，不能只改撮合线程里的价格。
- 沿用 ADR-0017：释放额不回补同一 tick 的预算，在下一提交快照中可用。

因此，最高价买单在价格较低时可能暂时占用较多现金，NPC 同次申报的股数也可能比按眼前笼子上限
估算时更少。这是明确的支付保证，不是新增个人仓位上限。
例如现金足够按 10.20 元买一手，却不足以按 11 元涨停价买一手并支付费用时，NPC 不生成
最高价买单；公共入口收到数量明确的一手最高价买单会按资金不足拒绝。指定 10.20 元的
限价请求仍按自己的价格核算。

## NPC 工作单、存档与边界

主动散户和动量游资提交 Highest 买单、Lowest 卖单。机构估值与反转策略的指定价格偏好保留。
新的动态选价意愿可以通过正常撤旧再申报流程替换旧工作单；不能把旧单视为持续跟踪“最高／最低”。
协调工作单时的价格判断不改变请求原意，也不能重复消费或遗漏原始候选。

未受理的 NPC、玩家请求与撤换依赖在存档中保存原选价方式；已经受理的单只保存实际数值价格。
恢复存档、竞价转连续竞价不会重新解析已有订单。当前 JSON 价格结构为 `{"Fixed": 1000}`、
`"Highest"` 或 `"Lowest"`；1000 的单位仍为分。不保留旧数字请求的兼容分支。

## 验证与效果范围

验证实时选价、四种方向组合、笼子开关、开收盘竞价、资金恰足及差一分、部分成交与余量留簿、
解析记录守恒与重复/伪造拒绝、同轮释放不可复用、排队存档和固定订单恢复，以及 NPC 工作单依赖。

本次减少策略直接处理主动报价的责任，但新增了受理时的价格解析与资金调整，不能仅凭类型变化
宣称整轮计算更快。真实性也不等于保证每只股票有成交；极端缩量的价格轨迹仍需单独模拟。

## 交易制度依据

沿用本轮 2026-09-27 已核对的沪深交易规则（2026-07-06 起施行），官方链接及条款见
[ADR-0021 第 5 节](0021-strategy-position-choice-and-noise-pricing.md#5-交易规则依据)：
连续竞价有效报价范围、已有对手申报价成交、集合竞价与市价申报类型差异。
本决定增加公共下单入口的选价功能，不改变这些撮合规则；关闭价格笼子仍是显式游戏简化。
