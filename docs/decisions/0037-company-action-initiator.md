# ADR-0037：公司行为发起方——偏好自动方案与显式 API

- **状态：** accepted（用户 2026-10-06 批准产品决策；偏好系统实现归后续批次，不以本 ADR 宣称代码完成）
- **日期：** 2026-10-06。
- **决策者：** 用户拍板；AI 记录。
- **关联：** [ADR-0035](0035-company-system-simple-fundamentals.md)、[ADR-0038](0038-simple-issuer-synthetic-settlement-funds.md)、[ADR-0039](0039-rights-placement-split-scope-and-toggle.md)；未定项见[当前交接](../../agents/company-system/current-handoff.md)「公司行为偏好、自动方案……仍未完成」。

## 背景

[ADR-0035](0035-company-system-simple-fundamentals.md) 已要求公司行为「采用每家公司可配置的偏好，结合财务条件与显式参数提出分红、配股、增发、回购等方案」，但没有敲定方案由谁发起、何时产生；[当前交接](../../agents/company-system/current-handoff.md)仍把公司行为偏好与自动方案列为未完成。若方案只能由外部显式注入，NPC 公司在正常游玩中不会自行分红、配股或回购；若由投资者触发，则偏离大 A 真实语义——上市公司的利润分配、配股、增发、回购决议由发行人依其治理程序作出，不由证券投资者发起。

用户 2026-10-06 拍板（原文要点）：「选择『公司按偏好自动 + 玩家显式』——每个公司有显式可配置的行为偏好，日结时自动产生方案（NPC 公司走这条）；同时保留显式 API 供测试/特殊场景。最接近大 A 真实语义：公司决策不由投资者发起。」

## 决策

1. `CompanySystem` 层为每家公司提供显式可配置的**行为偏好**：分红、送转、配股、增发、回购等方案的自动产生规则（触发与财务条件、规模等）。
2. **日结时按偏好自动产生方案**：NPC 公司的公司行为方案在日结流程中由偏好驱动自动提出，不依赖宿主或测试逐笔注入。
3. **保留显式 API** 供测试与特殊场景显式注入或构造方案。自动产生与显式注入的方案进入同一共同契约与状态机，同受共同制度校验，不设第二套规则或旁路。
4. 语义基线：公司决策不由投资者发起；投资者（玩家或 NPC 账户）没有发起公司行为的入口。
5. 偏好只影响方案生成，不能绕过共同制度、可分配利润、投资者真实现金与股份条件，也不保证回购成交（沿用 ADR-0035 的约束）。
6. 偏好的具体参数域（检查频率、规模、概率及默认预设）与配置的持久化格式由实施批次另行明确；偏好随严格存档持久化，恢复不改语义。

## 备选方案

- 仅显式 API，公司行为全部由宿主或测试注入：拒绝。正常游玩中 NPC 公司不会有公司行为，偏离大 A 语义，偏好配置无从生效。
- 由投资者或大股东账户发起：拒绝。用户明确「公司决策不由投资者发起」。

## 后果

- **正面：** NPC 公司在无人干预下自主产生公司行为方案，新局自然出现分红、配股、回购等事件；测试与特殊场景用显式 API 精确控制，两条路径共享同一状态机与校验。
- **负面：** 偏好进入新局配置与严格存档契约；自动方案生成须在日结候选事务内确定性执行，失败不提交部分公司结果（沿用 ADR-0035 的事务边界）。
- **后续批次：** 偏好系统实现批次以本决策为据。B3（回购）与 B4（配股／增发）批次的方案发起统一采用「偏好自动 + 显式 API」双入口，不另造触发机制；B2 的新局选项与配置面如需暴露偏好，以本决策为语义来源。

## 实现批次用户决策注记（2026-10-07）

用户在 P 批（simple 偏好系统）开工时进一步拍板（原文要点）：「偏好系统（这个是决策，
是策略，是指导机制的东西）是 company/simple 和 company/simulation 这两种不同的模型内部
的东西，simple 做个最简单的就可以了，要求简单性能占用少」。

据此落实的实现口径（见 `docs/trading-rules.md`「公司行为偏好自动提案」与
[台账](../../agents/company-system/simple-preferences.md)）：

- 偏好类型与评估逻辑落在 `packages/engine/src/company/simple/preferences.rs`（模型内部），
  不进入 `company/` 共同层或 session；共同层只暴露最小接口（按公司取偏好、结算完成判定、
  记录/读取拒绝台账）。
- simple 只实现最简可用：现金分红与送转两个偏好项，轻量整数/定点比较、只在结算周期末日
  评估、无每 tick 开销；配股/增发/回购只留类型扩展位。simulation 的偏好体系由其独立分支
  另行设计，不受本实现约束。
