# ADR-0038：Simple 发行人侧公司行为结算资金合成

- **状态：** accepted（用户 2026-10-06 批准产品决策；回购实现归后续批次，不以本 ADR 宣称代码完成）
- **日期：** 2026-10-06。
- **决策者：** 用户拍板；AI 记录。
- **修订：** 显式限定 [ADR-0024](0024-shrinking-investor-cash-pool.md) 的边界（见「对 ADR-0024 的修订与限定」）；不改变既有交易制度、撮合与费用规则。

## 背景

[ADR-0035](0035-company-system-simple-fundamentals.md) 已确定 `Simple` 的公司报表现金只是账面展示、不是付款预算：现金分红按可分配利润与方案条件支付给真实持股人，发行人侧记应付清偿的账面事实、投资者侧真实入账（[当前交接](../../agents/company-system/current-handoff.md)已验证 Session 真实税前到账、公司应付清偿及同日合计除息锚）。回购则一直要求「须经真实委托与成交」，但发行人侧回购资金从何而来没有敲定：`Simple` 不追踪真实公司资金流向，若要求公司先有真实资金才能回购，等于给 `Simple` 追加一套其明确没有的资金链。[Q12](../open-questions.md) 只登记了投资者侧不补钱的边界。

用户 2026-10-06 拍板（原文）：「simple模型：回购的时候，钱凭空生成，比如计划回购3亿，那就凭空3亿资金，仿照A股的实际情况，比如买完回购注销，然后更新数据（比如总股份）」

## 决策

1. `Simple` 模式下，**发行人侧公司行为结算资金是合成事实**：发行人回购按获批计划额度合成资金（计划回购 3 亿元即凭空生成 3 亿元资金），用于其后的委托、撮合与结算。这是游戏化的显式授权：不来自公司账面现金、不受账面现金余额限制。与既有现金分红的「公司应付清偿」合成语义统一表述——发行人侧记账面清偿／合成来源事实，对手方投资者真实入账。
2. 执行流程仿照 A 股实际情况：合成资金经**真实委托与成交**买入，不伪造卖方或成交；买入完成后注销回购股份，更新总股本与登记子账，并按适用规则处理除权。
3. 卖出方投资者真实收到合成资金，构成**投资者资金池注入**。它只在获批公司行为结算中发生、幂等且原子，不是给投资者补钱、返费或维持成交的机制。
4. `Simulation` 分支必须换成**真实资金链**：回购资金来自公司真实资金与融资来源、受有限现金约束，不凭空生成；`Simulation` 创建在实现前仍显式拒绝（ADR-0035）。
5. 计划额度与实际成交差额的处理、回购专户、碎股等官方细则须按现行规则另行核验后再实现，实施批次不得凭印象实现（[trading-rules.md](../trading-rules.md) 已登记相关边界）。

### 对 ADR-0024 的修订与限定

- ADR-0024 的**投资者侧规则不变**：投资者之间不造钱、不为维持成交补钱、税费照常退出、不保证成交、不伪造订单。
- **发行人侧公司行为结算是用户显式授权的例外**：分红付款与回购买入从发行人侧注入合成资金，经真实结算进入投资者账户，可使投资者现金总量增加。ADR-0024「投资者现金总量逐渐减少」的描述只在无公司行为结算的路径上成立，不得据此拒绝或截断已获批的公司行为结算。
- 该例外不扩张为任何投资者补贴：不得以资金池变化为由触发补钱、费用返还、资金重置或制造成交。

## 备选方案

- 回购资金受公司账面现金约束：拒绝。`Simple` 账面现金只是展示（ADR-0035），照此回购会在账面现金不足时不可用，违背用户「凭空生成」的明确决定。
- 推迟到 `Simulation` 用真实资金链一并实现回购：拒绝。用户要求 `Simple` 先按本决策接通，`Simulation` 留待后续分支。

## 后果

- **正面：** `Simple` 回购不再依赖不存在的公司资金链；分红与回购在发行人侧统一为合成清偿语义，文档与 UI 可用同一口径标注资金来源。
- **负面：** 投资者现金总量可因公司行为结算增加，与「资金池缩小」的既有叙事并存；UI 与报表须如实标注注入来源，避免被误读为补钱机制。
- **后续批次：** B3（回购批次）scope 据此确定——发行人侧按获批计划额度合成资金，无需实现公司资金筹集；真实委托、成交、注销、总股本更新与除权处理仍须完整实现。[Q12](../open-questions.md) 已同步登记本授权。
