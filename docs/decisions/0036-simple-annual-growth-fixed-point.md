# ADR-0036：Simple 年化趋势的定点复利换算

- **状态：** accepted（工程设计）；算法实现及短测仍须独立复核。
- **日期：** 2026-10-06。
- **关联：** [ADR-0035](0035-company-system-simple-fundamentals.md)与[公司系统蓝图](../../agents/remaining-questions-and-features/q14-financial-model-design.md)。

## 问题

用户要求 Simple 的增长参数按年化表达，结算可选月、季度、半年或年；自然时间趋势在期间内改变时须分段复合。直接用月数除以十二线性缩放不符合复利语义。使用浮点数直接乘 `AccountingAmount` 会丢失大额金额精度，宿主数学库差异也不应改变恢复结果。

## 决定

年化增长率以 `i32` 整数基点输入，合法范围为 `-10_000` 至 `i32::MAX`，低于 −100% 显式拒绝。期间换算使用 `(1 + AnnualGrowth)^(PeriodMonths / 12)` 的非负增长因子。`AnnualGrowth = -100%` 在任何正长度期间的因子为零，复合仍为零；零基数不会自然复业。换算因子采用 `1_000_000_000` 的定点精度；使用整数幂比较及整数根搜索，选择距真实因子最近的定点整数，正好半步时使用 half-even。非法日期及算术溢出显式报错，不通过截断修复。

结算使用自然月、自然季度、自然半年或自然年，完整期间的 `PeriodMonths` 分别为 1、3、6、12。本轮趋势持续时间为正整数自然月，在自然月首边界切换；不按结算次数计时，不引入自然日／365、自然日／366或部分月的另一套年占比。闰年二月同样占一个自然月。不支持的部分月趋势输入必须拒绝，不能取整冒充完整月份。

趋势跨段时，按实际趋势边界形成正整数月数的段，先合并相邻且年化趋势相同的段，然后按时间从早到晚复合各段定点因子；不为计算方便任意细切，不让期末趋势覆盖整个期间。每次因子 half-even 的绝对舍入误差不超过 `0.5 / 1_000_000_000`，累计误差受后续因子乘积影响，不承诺所有增长率下统一的金额误差上限。期间因子最终应用于原始精确金额，只对总金额舍入一次到分，不先舍入增长额、也不逐段舍入金额。采用商余分解避免不必要的中间乘积溢出；最终越出 `AccountingAmount` 范围仍须拒绝。因子精度是明确工程近似，不宣称不同结算周期下逐分完全相同。

复用纯 Rust 的 `num-bigint::BigUint` 计算整数根比较中的临时大整数，避免另写固定 limb 算术库。仓库锁文件已有 `num-bigint` 0.4.8；本决定仅授权其成为 engine 的直接依赖，用途限制于趋势换算，不改变账户 `Money`、股数、委托、撮合或 wire 类型，不引入 I/O 或平台依赖。能由标准整数完成的金额应用及因子复合仍使用 checked 整数运算。

## 验证与边界

短测覆盖四周期换算、零增长、负增长、自然时间跨段复合、总金额 half-even、大于 JavaScript 安全整数的金额及溢出原子性。算法与测试由未实施者独立复核，不以纯算子通过代替 Session、披露及宿主接通。

本决定不规定经济趋势分布、持续时间或扰动默认数值。扰动由各结算周期分别配置，不强制内部月度生成；已确定的趋势、扰动和期间基准保存到当前严格状态，不新增兼容、迁移或 schema 代际。ROE 继续由共同指标层计算，不作为基本面生成参数。
