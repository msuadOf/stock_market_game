# ADR-0025：只在日终生成持久存档并更新存档文件

- 状态：accepted（用户确认；实现与定向验证逐批登记）
- 日期：2026-10-01
- 决策者：用户
- 修订：用户存档触发方式与 ADR-0019 的存档精简落地边界；不改变交易制度。

## 决策

用户要求：“日内不保存存档，只在一天结束的时候保存存档更新存档文件。”

1. 持久存档只由成功的自然日日结触发。交易日先完成收盘竞价、日终委托失效与交易结算，
   再完成公司经营、必要封账和披露；休市日也须完成当日到期经营和披露后才能保存。
   采用现有 CivilUpdate 的完整日结边界，不把一个 PriceTick 或 UI 刷新当成日终。
2. 日内不生成供用户持久化的当前状态存档，不写浏览器快速槽或存档文件。日内点击保存
   只安排日终保存或选择输出目标；首个日结前须明确提示还没有可用日终存档。
3. 引擎回滚检查点、正常快照、活动委托查询和诊断内存投影不是持久存档。它们可以在
   日内使用，但不得借此写盘；活动委托界面不再通过完整存档查询订单余量。
4. 三宿主共用已完成日结的不可变存档候选。日内行情推进不能改变这个候选，失败日结
   不得替换它；异步写入的内容必须来自该候选，不能请求当时已进入盘中的新状态。
5. 已选且授权的文件目标在后续日终重复更新；浏览器不具备覆盖文件能力时须明确告知，
   不用一串下载冒充更新同一个文件。没有文件授权时，本地快速槽仍只能在日终更新。
6. 写入失败显式显示原因并保留上一份有效存档；不能先宣称已保存，再忽略异步写入失败。
   读档可以日内执行，但不因此产生一次新的日内持久化。新局/读档后的旧异步响应不得
   覆盖当前局目标，保存与恢复仍须保留资金、股份、T+1、费用与信息披露边界。
7. 打开游戏时只读取一次快速槽，先按存档中的配置和种子恢复，再启动内存会话。
   之后不再读取持久存档，直到用户明确读档或选择其他文件；行情、暂停/继续、后台切换
   和日终写入都不能触发重新读档。明确新局不重新加载旧档，坏档显式报错并允许用户
   选择新局或其他日终档，不能自动忽略坏档。
8. 公共加载入口只接受完整日结档，不接受日内快照、活动连续/竞价委托及日内母单、冻结 envelope、
   委托失效计时器或待受理请求。日内委托与撮合只存在于内存，读档后的委托界面从
   当前引擎查询，不从存档投影。跨日个人计划、历史成交事实、成本经历和随机状态仍须
   保留；计划的预期买入不是已冻结买单，修改日终现金无需替日内挂单补钱或自动撤单。

此前“修改现金不足以支撑存档里已有买单怎么办”的提问不适用于正常日终档，按以上边界
核销，不作为待用户决策。真正不合法的日级事实仍显式拒绝，不静默修补结构或修改资产。

### 日界 NPC 请求准备（2026-10-05 修正）

`GameSession::new` 和最后一个市场 tick 不提前生成下一交易日的 `pending_npc`；
日结档在 tick 日界保留 `None`。下一天首个市场 tick 在隔离 `TickShadow` 中、
`ExpiryShadow` 之前，以已经完成自然日经营与披露的提交版本准备 NPC 请求。
这样休市开局也不会把下一交易日请求写入日终档，NPC 同时可以观察已完成的日结事实。
准备失败时 RNG、attention、策略状态和请求一起回滚。日内仍消费前一 commit 已准备的批次，
缺失或 `observed_tick` 不匹配继续显式拒绝；公共加载仍拒绝任何非空待处理请求。

## 实施范围

先补日终候选、活动委托只读查询、日终写入协调器和复用文件目标，再完成已确认的
功能代码缺口。待选型扩展、股东资金流、真实行情校准和完整回归不在本次授权范围。
存档格式精简不能删除继续运行所需的计划、个人状态、随机流或已承诺历史；若修改格式，
只支持严格的新格式，不建立旧格式迁移路径。

## 验证边界

仅运行代表性定向短测：首个日结前不可持久保存、成功日结更新、日内候选不变、失败
日结/失败写入保留旧档、真实订单查询不生成存档，以及读档/新局拒绝旧写入。
不运行完整回归、长期市场或完整浏览器/三宿主矩阵；每批经独立复核后本地提交，不推送。
