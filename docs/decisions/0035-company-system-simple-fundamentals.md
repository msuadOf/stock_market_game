# ADR-0035：CompanySystem 共同入口与 SimpleFundamentals

- **状态：** accepted（设计）；实现和验证进度见[实施清单](../../agents/company-system/implementation-checklist.md)，不以本 ADR 宣称代码完成。
- **日期：** 2026-10-06。
- **依据：** 用户确认的[公司系统蓝图](../../agents/remaining-questions-and-features/q14-financial-model-design.md)，以及本轮“先接通 `company/simple`，`company/simulation` 后续另开分支”的决定。

## 问题

现有公司身份及 Session 装配强制依赖 `Books`、合同和完整经营状态。仅增加模式名称、隐藏财务明细，仍会让简单模式运行复杂仿真，也可能把没有的现金流当作零值用于估值或股东结算。

## 决定

`session → company` 通过薄共同入口 `CompanySystem` 调用。共同身份复用 `CompanyId`、`IndustryId`、发行人和股份数量；内部枚举只持有所选实现的状态。`CompanyKind` 的会计类别不等同证券板块。新局模式和配置必须明确，同局不切换；未实现的 `Simulation` 请求明确拒绝，不降级为 `Simple`。

本轮实现 `SimpleFundamentals`：共享轻量环境与公司独立趋势、扰动生成月度收入，再由简化净利率生成净利润。可选权益按期初权益加本期净利润推进；负利润、负权益和零收入按各自语义处理，零收入复业要求明确输入。参数是虚拟假设，不使用真实市场统计，不根据证券价格倒推基本面；蓝图算例不是默认参数批准。

简单模式不构造 `Books`、客户、合同、债务或占位现金，也不在后台推进旧经营系统。其指标标明 `SimpleGenerated` 来源、期间、范围和单位；解释来自实际生成步骤，不编造客户回款、研发或真实凭证。完整报表、现金流及股东现金结算不支持时明确表达原因，不能填零冒充支持。

公开排期复用既有 `ReportFrequency`，不在简单模型新增第二套独立披露时钟。公司内部生成事实与 `information` 的公开材料、账户本人获知分离；玩家只能查询已公开材料，NPC 只消费本人已获知材料。分析所需指标缺失时该方法明确不可用，不偷读私有状态、不静默更换方法、不制造共同正确股价。

推进使用既有自然日时钟和候选状态事务。失败不提交部分公司结果或随机状态；恢复保留继续运行所需事实。仅成功自然日日结通过现有宿主接口保存：浏览器 IndexedDB，Server／Desktop SQLite。当前存档严格校验模式、身份、日期和字段，不增加 schema 代际、旧格式兼容、迁移或默认补字段。

## 边界与后续

本决定不修改沪深证券撮合、T+1、交易日历或证券前史来源规则。简单基本面属于明确的游戏简化，不声称完整会计合规；不向投资者补钱，不因虚拟权益有余额就允许现金分红、回购或其他现金股本行为。

`CompanySimulation` 的行业业务、有限客户现金和跨主体结算留到后续分支。既有独立会计算法与领域测试可保留，但不能为了保留测试而给简单 Session 加经营影子状态。共同入口及简单模式通过短单元测试和未实施者独立复核验收，不将此结果扩称为完整仿真或完整回归通过。
