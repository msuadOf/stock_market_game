# ADR-0031：Money 以十进制分字符串跨边界

- 状态：accepted
- 日期：2026-10-04
- 决策者：用户；AI 记录
- 关联：ADR-0002、ADR-0004、ADR-0025、ADR-0029、ADR-0030

## 背景与决定

Rust 的 `Money` 内部为有符号 `i64` 分，JavaScript `number` 不能精确表示其完整范围。
用户明确选择十进制分字符串，例如 `"1000000000000"` 表示100亿元。
JSON、WASM、Server、Tauri 和日终存档统一使用此表示；价格也是每股的分字符串。
TypeScript 的 `Money` 与 `Cents` 为 `string`，不把金融整数缩小到安全整数范围。

跨边界只接受规范 ASCII 十进制整数：`"0"`、无前导零的正整数或负整数，范围为
`-9223372036854775808` 至 `9223372036854775807`。JSON number、前导正号、负零、
前导零、空白、小数、科学计数与越界值均显式拒绝；非负现金、正价格等业务约束仍由
对应字段验证。可选金额的 `null` 不变，集合结构不变，金额元素使用字符串。

## 精确计算与呈现

Rust 内部算法、费用、价格最小变动单位和舍入规则不变。Web 的金额加减、数量乘价、
排序、冻结资金比较与整手数量计算使用 `BigInt`，经过范围校验再返回字符串；
Redux 快照与 UI 状态不存 `BigInt`。用户输入的元文本精确解析为分，显示金额通过整数
商与余数生成两位小数文本，不经过 `number` 再还原。

图表坐标与涨跌比例允许在呈现末端转换为 `number`，因此极大金额可能有视觉近似；
原始 OHLC 分字符串必须保留，不能从图表坐标反算委托价格、成本或余额，不能因两个
精确价格映射到同一坐标而忽略真实更新。

## 类型边界与非目标

持仓 `invested_cents/recovered_cents`、个人估值及因果诊断中的有符号分字段复用
同一 `Money` 编码；股数、时钟、比例、ID 不因字段邻近而改变单位或格式。
`AccountingAmount` 保持独立的 `i128` **元**十进制字符串，不能乘100或收窄到 `i64`。
已有 `u64` 累计成交额与其他无符号资源字符串保持原类型范围，不收窄为 `Money`。

本次不增加存档代际版本、不接受旧数字金额、不提供双格式、alias 或迁移。
当前 fixture 随当前契约更新；密封历史见证保留原字节，表示相关测试锚需通过独立
旧/新生产者证明只改变金额编码后更新，不能直接采用失败输出。
不改变 A 股 T+1、价格时间优先、申报数量、费用及现金来源规则；多人入场与权限接线
仍依 ADR-0030 独立实施。
