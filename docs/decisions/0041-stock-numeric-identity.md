# ADR 0041：股票数值身份（StockId）

- 状态：已采纳（2026-10-06）
- 编号说明：0037–0040 已被主工作区在途工作占用，本 ADR 顺延为 0041。

## 背景

引擎内股票唯一身份一直是 `StockCode(pub String)`（如 `"600519"`）。性能画像（callgrind）显示
CPU 大头是字符串机械成本：内存分配 ~14.8%、逐字节比较/搬运 ~9.4%，其中股票代码 newtype
在每 tick 的订单/账本/快照键位被大量克隆（单字段曾测得 1132 万次分配/3000 tick）。
同时存在设计诉求：显示名称应可由配置（yaml/json）替换，前后端通信应只传代号。

## 决策

1. **核心引擎以 `StockId(u32)` 作为股票唯一身份**：撮合、账本、NPC、快照、协议、存档
   状态全部使用数值代号；核心逻辑无字符串键。
2. **`StockCatalog` 目录是唯一翻译层**：`GameSession` 状态持有目录（id ↔ 代码/显示名）。
   **id 按代码字符串升序分配**（0..n），因此 `StockId` 的 `Ord` 即代码序，既有
   "按代码排序"的展示/输出顺序零逻辑改动保持。重复代码在构造时显式报错，不静默去重。
3. **字符串只留边界**：
   - 配置加载：`StockSpec.code`（字符串代码）不变，`GameSession::new` 时转换并分配 id；
     未知代码在公开入口显式拒绝（`IntentRejected`），绝不静默映射。
   - 显示与日志：经目录查 `display_name`（缺省等于代码）；后续可用配置文件替换名称。
   - 存档：状态中的股票键位全部数值化（破坏性变更，无迁移层——项目处于早期，
     不保留兼容），存档附带 `StockCatalog`（代码表）保证读档可还原。
4. **wire 只传 id**：协议消息与 `Event` 中的股票字段为 `StockId`（数值）；前端通过
   初始化时的股票目录表翻译显示。ts_rs 类型再生成。
5. **大 A 语义不变**：边界代码字符串保持真实 A 股格式；板块/交易所差异建模不动；
   撮合/费用/T+1/首错顺序/失败原子性零变化。`business_state_hash` 因序列化改变而变化
   是预期内的破坏性变更，如实更新测试，不伪装连续。

## 动机

- 性能：消除热路径字符串克隆/比较/分配（画像证据如上）。
- 设计（用户要求）：名称配置化（改 yaml/json 即改显示，核心零改动）；通信减负
  （数值代号替代字符串）；核心逻辑无字符串化，降低心智负担。

## 后果

- 一次大规模破坏性重构：存档格式、网络契约、ts_rs 生成类型全部变更，不写迁移层。
- 测试中需要经 `session.stock_id("600888")` 查目录构造内部键；目录不在场时无法
  凭空构造 `StockId`（除 id 本身），这是有意的显式性约束。
- 股票中途上市/退市（当前不支持）如未来引入，需要扩展目录生命周期。
