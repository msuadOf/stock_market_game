# 参考游戏交易面板观察与用户确认

日期：2026-10-05。参考应用：StocksMainForceSimulator（股票主力模拟器）。

## 本轮范围与证据性质

本记录整理本轮原生应用观察、用户随后明确给出的规则，以及与当前代码的对照。
本记录写于观察阶段，当时没有实施 WebUI 交易面板改动，不把以下提案当作该阶段已有功能。
后续实施结果见 [交易面板实现与验收](quick-trading-implementation-2026-10-06.md)。
参考游戏只作为布局和操作体验依据，不作为 A 股制度依据；实际委托继续遵守项目的
engine 规则、证券类别差异、T+1、资金和股份预留、费用及申报数量约束。

用户要求不再自行试验未知按钮，后续有未确认的行为直接询问用户。“批量”本轮不做。

## 已观察的布局与入口

- 桌面底部交易区包含活动委托、持仓、卖出表单和买入表单；买卖表单同时可见。
- 关闭整个交易区后，图表和盘口获得释放的空间。个股报价上的买卖入口可重新打开交易区。
- 交易区可以从底部展开为浮动面板，再收回底部；浮动面板的加减按钮改变下方列表高度。
- 行情、自选、持仓列表构成证券选择入口。选中不同证券会更新图表、盘口和交易目标。
- 从个股买入入口重新打开交易区时，参考应用会把买卖价格填为当前价，并把数量恢复为一手。
- B1、S1 选中后会跟随对应最新盘口；手工加减价格会退出跟随，保留指定价格。
- 交易间隔的弹出选项为 0.05s、0.1s、0.3s、0.5s、0.7s、1s、1.5s、2s、3s、5s、10s。
  买卖两侧分别设置间隔，选择后弹层关闭。
- 同价同量多次提交会形成独立委托；单条取消只针对那条委托。
- 参考应用的买卖两侧“取消所有”各自只取消对应方向的委托。这与用户对本项目的要求不同。

以上记录只覆盖实际观察到的响应；没有据此证明全部菜单、异常和时序边界均已测试。

## 用户已确认的本项目行为

### 自动下单与游戏时间

用户确认：间隔按游戏内时间计算；资金不足、可卖数量不足时保持开启，等待条件满足。

- 买卖分别有自动开关和间隔。自动关闭后，已经提交的挂单仍保留。
- 游戏暂停时不消耗执行间隔，不能按现实时间继续提交。
- 资金或股份不足属于可见的等待原因，不能静默取消自动任务，也不能伪造成功。
- 等待期间仍需在后续到期点重新检查当前资源；不可借款、补钱或擅自缩减一次申报数量。
- 自动定时重复下单与现有止盈、止损等一次性价格触发条件单是不同功能，不能互相替换语义。
- 用户随后确认：自动任务绑定原股票，切换当前行情和交易面板不会把原任务转到新股票。
  面板需要显示正在执行的股票和方向，使原任务保持开启这件事可见。

执行时点精度、跨时段恢复和关闭面板时是否继续执行等边界尚未由本次答复明确决定，
实施前需结合现有宿主能力判断，涉及用户意图的分歧须询问用户。

### 盘口点击

用户确认：点击价格只改变价格，不改变手数；点击档位手数采用已观察的累计数量行为。

| 点击区域 | 表单行为 |
| --- | --- |
| 档位价格 | 填入该档价格，数量保持原值；不会直接提交委托 |
| 卖方档位手数 | 填入该档价格；买入数量取从卖一到该档的累计数量，并受可买能力限制 |
| 买方档位手数 | 填入该档价格；卖出数量取从买一到该档的累计数量，并受可卖数量限制 |

价格和手数必须为两个独立的可点击区域，鼠标和触屏使用同一处理逻辑。
参考观察中点档位还更新了另一侧价格；本项目是否同步另一侧草稿，本记录没有将其定为用户要求。

### 数量比例与可用数量

用户确认：舍去尾数，不足一手结果为 0 手；“全部”是所有可用手数。

- 比例计算以当前可用手数为基数，按整数向下取整。例：一手的 1/2 = 0 手。
- 买入可用手数由可用资金、当前委托选价和本局费用计算，不按账户总资产计算。
- 卖出可用数量扣除 T+1 锁定和已有卖单预留，不能按总持仓计算。
- 比例按钮允许填出 0 手；0 手是草稿值，不得向 engine 发送零数量委托。
- 当前 engine 委托单位为股，展示手数需要显式换算，不能直接把手数发送为股数。
  “全部”快捷键按用户确认填入所有可用整手；例如可卖 150 股时为 1 手（100 股）。
  合法零股仍通过明确股数输入或独立入口完整保留，不能因整手快捷键删除合法卖出能力，
  也不能把“全部”快捷键自动包含零股误写为用户已确认的要求。
- “全部”的整手数量超过证券类别的单笔申报上限时仍须明确提示约束，不静默截断或自动拆单。

### 选价与撤单

- B1 = 买一，S1 = 卖一。
- 按钮显示“最小”“最大”。分别映射当前后端的 Lowest、Highest，保留受理时解析语义，
  不改成前端预先固定的跌停价、涨停价。它们仍生成限价委托，不称作交易所市价申报。
- “取消所有”作用于本人所有证券、两个方向的全部活动挂单，不受当前选中股票或列表筛选限制。
  部分成交的委托只能撤销剩余部分，不能撤回已成交事实。
- 用户随后确认：“取消所有”不关闭自动下单。操作仅撤销已有挂单，后续到期仍可产生新挂单，
  不能把停止自动与撤单合并，也不能把后续自动新单误报为撤单失败。

## 当前代码对照与实施提案

- `apps/web/src/app/useTradingCommands.ts` 当前只有一份买卖共用草稿，已有字段校验、
  T+1 与预留股份检查、单条撤单入口。拟抽出可复用的交易表单，买卖分别保留草稿状态。
- `apps/web/src/app/LocalRefreshViews.tsx` 的 TradeMarketControls 当前按最新价与可用现金
  估算所有比例按钮，未区分买卖，未计算费用，且小于一手的按钮不可点击；需按上述已确认语义调整。
- `apps/web/src/components/auto-order-manager.ts` 当前处理价格触发一次的条件单。
  拟另设共享的游戏时间调度逻辑，沿统一 EngineHost 提交路径执行，不能直接改写条件单含义。
- 桌面同时显示买卖表单、持仓和活动委托；移动端使用同一表单组件与处理逻辑，按屏幕空间切换显示。
  布局适配不能复制两套交易计算。
- 价格、资金计算沿用 Money 的十进制分字符串与 BigInt 精确计算；显示金额不能反算委托金额。
- 实施前用失败测试固定：价格点击不动数量、档位累计数量与资源限制、比例零手、
  买卖草稿隔离、游戏暂停不计时、资源不足保持开启、切换股票仍执行原股票、
  全证券双向撤单、取消所有保持自动开启。

相关现有契约：ADR-0022、ADR-0031、`docs/principles.md`、`docs/architecture.md`。
本记录不修改交易制度，不新增宿主协议或存档承诺；需要协议或持久化变更时另行明确范围。

## 观察操作的影响与限制

此前测试在参考游戏中买入了一手精工智造。关闭自动不会撤销已有委托，测试挂单此前已清理；
最新自动卖出观察没有捕获到新委托或失败提示，因此不能据此认定参考应用的异常反馈实现。
用户要求停止自行操作后，没有继续点击参考游戏或执行恢复操作；当前原生应用状态没有再次核验。
本项目 WebUI 没有因本记录新增委托、改变存档或推进游戏时间。
