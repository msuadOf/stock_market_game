# 红线：状态改动的"跨拍持久"验证（cross-tick persistence）

> 2026-10-22 建立。**起因**：同一类测试缺陷在多个批次重复出现——
> ① B4c 的 6 个持仓/现金类测试全部只验"事件当日"，未验跨拍存留
> （Sol 在 B4d 设计门中点名，列为合入前必补）；
> ② 该形态在 #116（休市日成交）修复时同样会重现——修完若只验当天，
> 缺陷会换个地方再犯一次。

## 一、这条红线是什么

凡是**改动了持久状态**的实现（账户现金、持仓、名册、快照、存档字段……），
验收测试**不能只断言"改动发生的那一刻"是对的**，必须证明
**这次改动在后续若干拍之后仍然存在**。

## 二、为什么容易漏（典型塌方式写法）

最常见的塌方式写法：

```rust
while session.civil_date() <= plan.ex_rights_on {   // 循环终止于事件日
    complete_day(&mut session);
}
assert_eq!(position_of(&session, npc, &stock), npc_before * 2);  // 断言紧跟其后
// ← 到这里就结束了，之后再没跑过一拍
```

它**看起来**很完整（有循环、有多日、有守恒断言），
但它只证明了"事件当日可见"。

**为什么这是塌方**：若存在"次日被别的值覆盖"的缺陷（如 spine 直改被组端权威
覆盖、快照未回灌、事务未提交），这个测试**完全绿**——因为它根本没跑到第二天。

## 三、正确写法

```rust
while session.civil_date() <= plan.ex_rights_on {
    complete_day(&mut session);
}
assert_eq!(position_of(&session, npc, &stock), npc_before * 2, "事件当日");

// ★ 再跑**至少一次真实交易 step**，然后重新断言
run_a_real_trading_step(&mut session);          // 不能只是推进自然日
assert_eq!(position_of(&session, npc, &stock), npc_before * 2, "跨拍后仍成立");
```

要点：

1. **必须是"真实交易拍"**，不是自然日推进。
   ⚠️ 两个自然日**不保证**跨过交易拍（休市日不产生 tick）⇒ 只推进日历不够。
2. 跨拍后**重新断言**同一个不变量（不是换个断言）。
3. 至少跨 1 拍；有条件的场景建议跨 2–3 拍看是否单调衰减或抖动。

## 四、什么不算（反例清单）

| 写法 | 为什么不算 |
|---|---|
| 只断言事件当日 | 没跑到第二天，覆盖类缺陷全绿 |
| 只推进自然日（`end_civil_day` × N） | 休市日不产生 tick，可能一拍没跑 |
| 跨拍后改断言另一个东西 | 没验同一个不变量是否存留 |
| 用"不 panic"代替数值断言 | 静默覆盖类缺陷不 panic，照样绿 |
| 只验"读面"不验"写面" | 读面快照可能独立，写面才决定是否持久 |

## 五、与"静默类"缺陷的关系

覆盖型缺陷的典型特征是**不 panic**（数值被悄悄改回/改错，程序照跑）。
这类只能靠**数值断言 + 跨拍重读**捕获，**不能**靠"不崩溃"或"仍出数"来判断。

⇒ 凡是涉及"两份权威"（如 spine 与组端、快照与实时）的改动，
一律默认存在静默覆盖风险，必须补本文件的跨拍验证。

## 六、快速自检（合入前逐条过）

- [ ] 我的测试有没有在**事件之后**再跑一次**真实交易拍**？
- [ ] 跨拍后有没有**重新断言同一个**不变量？
- [ ] 我验的是**写面**（持久后）还是只读面？
- [ ] 断言的是**数值**还是仅"不 panic"？
- [ ] 把改动**回退**，这个测试会不会变红？（不会红 = 没钉住）
