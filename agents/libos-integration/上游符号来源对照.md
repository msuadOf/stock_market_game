# web-thread 来源对照（初步）

日期：2026-11-12。上游快照为 `vendor/web-thread/upstream`，commit 与 MIT OR Apache-2.0 许可见 [ADR-0045](../../docs/decisions/0045-web-thread-vendor-admission.md)。快照保持不变；本表只描述已核对的源码关系，不代表完整线程层已经移植或验收。

| 上游源码及符号 | 本仓对应 | 当前关系与差异 |
| --- | --- | --- |
| `src/thread/atomics/parker.rs`：`Parker::{park_timeout,unpark}`、`EMPTY/NOTIFIED/PARKED` | `packages/engine/src/libos/mailbox.rs`：`Signal::{wait,notify}` | token 状态机及 Release/Acquire 顺序经改编；Native 使用 Mutex/Condvar，WASM 使用 atomic wait/notify。上游 Parker 绑定 `ThreadId`，本仓依赖单接收者约束，不是原样复制。 |
| `src/thread/atomics/channel.rs`：`channel`、`Sender::{send,drop}`、`Receiver::next` | `libos::mailbox::{Sender,Receiver}` | 都以 std mpsc 保存消息并在发送或断连时通知，但上游使用 `AtomicWaker` 和 async 双重检查，仅成功发送及最后一个 sender 销毁时唤醒；本仓使用 `Signal` 及中断消息保留，每个 sender 销毁和发送失败也会唤醒，等待者须容忍额外唤醒；不是该上游 channel 的直接移植。 |

| `src/thread/atomics/spawn/` | `libos::thread::wasm_impl`、`facade_slot::{arena,roles}` | 本仓 `init_wasm_facade` 初始化故障域和 `SlotArena`，`child_trampoline` 调用 `trampoline_run`；`SpawnJob` 与 `join_typed` 属本仓现有协议。上游 spawn/bootstrap 尚未接入，需另行核对 Worker 启动、TLS、tombstone、join 与释放，不能直接替换。 |


## spawn / join 的初步符号对照

| 上游符号 | 本仓符号 | 差异与待证 |
| --- | --- | --- |
| `atomics/spawn/mod.rs::spawn`、`spawn_without_message` | `libos::thread::Builder::spawn`、`facade_slot::roles::request_spawn` | 上游生成线程对象和 oneshot result channel，按主线程身份直接创建 Worker 或发送 spawn command；本仓发布 `SpawnJob` 到 `SlotArena`，通过宿主通知并等待应答。闭包、失败及取消所有权须逐状态比较。 |
| `spawn_common`、`spawn_internal` | `request_spawn`、`WasmFacadePlatform::notify_spawn_v2` 及浏览器监督者 | 上游创建 module Worker、发送 module/memory/task 指针并登记 Worker；本仓通过宿主监督者与 slot/generation 协议创建 child。不能视为上游 Worker bootstrap 已移植；消息失败、死亡和释放路径须验证。 |
| `__web_thread_worker_entry`、`thread_runner` | `libos::thread::child_trampoline`、`facade_slot::roles::trampoline_run` | 上游接收 task 指针并执行 async task；本仓校验 slot/generation，绑定 child 身份并运行 `SpawnJob`，另有 tombstone 与宿主退出流程。内存和 TLS 约束需以真实浏览器验证。 |
| 上游 `JoinHandle` 的 oneshot result | 本仓 `JoinHandle::join`、`join_typed` | 两者结果移交机制不同；本仓使用 join slot 和 generation，hard trap 不保证 Rust 返回 receiver。上游行为不能作为本仓资源对账证据。 |

这些是调用链对照，不是逐分支等价证明。`message.rs` 的 transfer 变体、取消竞态、异常和各自的生命周期尚需继续审计。

## `spawn/message.rs` 消息与 transfer 变体逐符号审计

审计日期：2026-11-12。依据上游快照 `vendor/web-thread/upstream/src/thread/atomics/spawn/message.rs`、`vendor/web-thread/upstream/src/web/message.rs`，以及本仓 `packages/engine/src/libos/thread.rs`、`packages/engine/src/facade_slot/{roles.rs,arena.rs,platform.rs}`。本节仅做源码阅读对照；未运行构建或浏览器验证。

| 上游符号 / 分支 | 本仓对照 | 语义差异、不能直接移植处与未验证项 |
| --- | --- | --- |
| `MessageSend::{send, receive}`、`RawMessage { serialize, send }` | `SpawnJob::{closure, invoke, drop_fn, drop_result}`；`SlotArena` 的 payload/join slot | 上游把 spawn 参数拆成 structured-clone 的 `JsValue`（`serialize`）及 Rust `Send` 所有权值（`send`），在子端重新组装；本仓没有通用启动参数协议，闭包与返回值由擦除指针及共享 memory slot 承载。不能把 `MessageSend` 的两路载荷当成 `SpawnJob` 替代品，否则会改变闭包所有权与失败回收契约。未验证 structured-clone 与本仓受控 std/Worker memory 的交互。 |
| `SerializableWrapper<T>::send/receive`：仅 `serialize=Some(value)`，`send=None` | 无一对一类型；最接近的是 bootstrap 元数据 | 这是 JS structured-clone 的可序列化对象，不是 engine 内的 Rust 闭包或 runtime 消息。`facade-supervisor` 只传 slot、generation、name、tombstone 地址等启动信息；不能把上游序列化载荷直接放入该协议。 |
| `TransferableWrapper<T>::send/receive` 与 `Transferable` 实现：`ArrayBuffer`、`MessagePort`、`OffscreenCanvas`、streams 等（部分类型受 `feature=message` / unstable API 条件限制） | `facade_slot::roles::request_spawn`、`FacadePlatform::notify_spawn_v2` | 上游把对象放入 transfer list，由浏览器移动底层资源并使发送端对象失效；本仓传的是共享 memory 中已发布的 Rust job 所有权和标量句柄，不转移 DOM/JS transferable。该变体不能用于本仓 `SlotArena` payload；不能假定同一 memory 或 handle 的 ownership 规则。具体浏览器对象覆盖随 feature 开关，未在当前产品宿主逐类验证。 |
| `SendWrapper<T>::send/receive`：`serialize=None`、`send=Some(T)` | `SpawnData.task` 捕获 `raw_message.send`；本仓 `SpawnJob` 的 erased `FnOnce + Send + 'static`、`invoke`/`drop_fn` | 上游 `SendWrapper` 的值并非单独放入 `channel::Sender<SpawnData>` 字段；`spawn` 闭包捕获 `raw_message.send`，嵌套 spawn 时该闭包作为 `SpawnData.task` 间接入队，再由目标 task 调用 `M::receive` 重组。它不是本仓的共享 memory 传输机制，本仓也没有通用 `T` 参数载荷通道。 |
| `[T; SIZE]`、tuple 的 `MessageSend` 组合实现 | `SpawnJob` 单一 payload | 上游逐项聚合 `Option<T::Send>`；序列化数组只在首次遇到 `Some(serialize)` 时补此前累计的 `null`，之后遇到没有序列化值的元素仅增加 `empty_serialize_count`，后续序列化值不会按该计数补空位。因此“序列化值之后再出现无序列化值、再出现序列化值”的混合模式会压缩 serialized 数组位置，与 `receive` 按原始 index 读取、预期长度为 `SIZE` 的逻辑存在错位/断言风险。该具体交错尚未通过测试或运行验证，源码存在该疑点；不能描述为普遍有序保留空洞，也不应将此实现原样移植。本仓一个 slot 对应一个 job，未实现任意 tuple/数组消息组合；移植前需独立定义 schema、版本与逐字段失败清理。 |
| 自定义 `MessageSend` 实现（示例同时返回 serialized canvas 和 `Send` 标量） | 无 | 上游允许调用方自行规定序列化/本地 Rust 值拆分及重组。当前本仓不接受用户自定义 bootstrap 消息类型，也未建立反序列化错误面；不能直接开放该扩展点。 |

| `setup_message_handler`：先 `spawn_receiver.try_recv().expect(...)`，再读 `event.data()`；undefined 时直接返回，否则取 serialized 值和可选 transfer list 后再次 `spawn_internal(...).expect(...)` | `trampoline_run`、`join_typed` 与宿主 `facade_child_trampoline` | 上游要求 Rust `SpawnData` 先入队且与后续 JS MessageEvent 一一配对。`send_message` 失败后补发的 `undefined` 会触发该分支；此时 `SpawnData` 已先取出，随后提前返回，局部 `data` 随闭包退出而析构，其 `task`（含捕获的 `raw_message.send`）不再执行。此析构及资源效果据源码控制流推断，尚无针对该路径的运行测试。serialized 重建错误则由 `expect` panic。facade 使用 slot/gen 校验与状态机，不以 MessageEvent 队列索引配对，child 在 `trampoline_run` 内绑定 tombstone，并以 `join_typed` 消费 typed result 或 death。不能照搬 `try_recv().expect` / `unchecked_into` / `expect` 错误策略；需保持本仓身份、死亡通知及清理协议。事件顺序、undefined 竞态和错误路径均未做 Chromium 实测。 |
| `HasMessagePortInterface` 的 `Worker` / `DedicatedWorkerGlobalScope` 实现 | `FacadePlatform::{notify_spawn_v2, wait_u32, worker_exit}` 与 TS supervisor | 上游抽象只统一 `set_onmessage` 和两种 `post_message` API；本仓平台接口覆盖原子 slot 发布、等待/唤醒和 worker 退出观察。接口表面相似不表示传输、活性或释放语义等价。 |

### 明确结论与证据边界

- `message.rs` 的 `MessageSend` 变体是给 `spawn_with_message` 用的 JS structured-clone / transferable / Rust `Send` 载荷协议；不是本仓业务 `GroupIn` / `DeskIn` / `UpMsg`，也不是 LibOS 下行消息队列。
- 本仓 `facade_slot` 的 bootstrap 是基于共享内存 `SlotArena` 的闭包所有权发布与 child 身份绑定：`request_spawn` 发布 `SpawnJob` 并调用 `notify_spawn_v2`；`trampoline_run` 校验 slot/generation、取出 job、绑定 WASM tombstone；`join_typed` 收取结果或结构化死亡状态。上游 `message.rs` 既没有这些门链，也不能证明 ADR-0044 的 `DEAD`、TLS、tombstone、hard trap 或 child release 生命周期。
- 上游 transfer list 搬移浏览器对象的语义，不等同 ADR-0043 的现金、股份、委托或成交 `Entity` move；两者不得因同用 “transfer” 一词而混同。此处不涉及 A 股业务规则变更。
- 尚未验证：上游完整 `message` feature 的原 manifest 构建、各 transferable 类型的产品浏览器支持、嵌套 spawn 的真实 Worker 消息交错、传输失败后的补发路径、与本仓受控 std/ADR-0044 故障记录的互操作。源码审计不构成可移植性或生产接入验收。

上游 channel 的 async executor 唤醒机制不能直接替代 Worker 的阻塞等待、宿主故障广播和 receiver 资源回收契约。该差异是当前适配工作的约束说明，不是对所有实现方案的最终结论；真实 Chromium 验证和上游 spawn 逐符号审计仍待完成。
