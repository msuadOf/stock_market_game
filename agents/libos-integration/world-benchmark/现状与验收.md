# World benchmark 现状与验收

本文件记录 benchmark 框架边界，不代表 Native/WASM 已通过跨端正确性或性能验收。现有 JSON、日志和 trace 都是历史实验材料；本轮没有执行测试、构建或 benchmark，也没有重新验证其中任何产物。

## 本轮代码

- `event_projection.rs` 逐端检查 `seq` 严格递增，但允许不同股票之间独立事件交错；同股、同账户顺序及事件内容仍逐项比较，全局日界等 barrier 仍按原顺序比较。
- `restore-run.mjs` 保持已有存档、事件、最终 hash 与事实断言，并把非空 `Trade`、`Desk receipt`、`Group rejection`、`auction` 计数缺口标记为“未完成”；这些计数不代表完整交易事实验收。
- `performance-protocol.mjs` 提供固定 seed/setup/依赖/工作量、release 产物、CPU 环境与线程数的样本校验、按执行前计划生成的交错采样次序、配对中位数与范围汇总和显式未完成状态。计划轮数未确定时不报告样本达标。`core-diagnostic` 与 `product-lifecycle` 分开处理；只有产品路径记录 `UI ready`、创建或恢复、跨日推进、完整保存和正游戏时钟跨度时才接受为产品样本。性能比例来自同路径配对的墙钟时间；游戏时钟加速只基于产品样本提供的真实游戏时钟秒数，不从 `tick/s` 外推。
- `measure.mjs` 将当前 `diagnostic_game_steps(3000)` 明确标为 `core-diagnostic`，记录 1000 tick 预热、3000 tick 工作量和计时边界，清楚排除 UI、存档、恢复与 shutdown。

## 未完成项

- 当前已有运行入口测量的是 diagnostic core 路径；没有已接入的真实 Native 与浏览器产品宿主成对测量器，也没有本轮生成的新样本。`product-lifecycle` 因此仍不能形成验收结论。
- 现有恢复结果包含 `trades: 0`、`deskReceipts: 0`、`groupRejections: 0`、`auction: 0` 的历史实验；按新覆盖标识应视为真实事实覆盖不足。撤单的非空事实、资金与股份最终及中间状态仍需由真实场景采集并逐项对照。
- “WASM 与 Native 相近”的数值阈值仍待用户确定；约 3000× 产品目标的计时起止与样本规模也待审核。代码不会自行判定达标。
- 未取得本轮的 release 产物、依赖锁文件摘要、宿主环境、CPU/线程样本或多轮交错数据；不得据历史日志推导新结论。
- 本目录代码已由未实施该目录改动的 subagent 独立只读复核；发现的问题已修正并再次复核。本轮整个仓库的完整 diff 复核仍由主任务完成。
