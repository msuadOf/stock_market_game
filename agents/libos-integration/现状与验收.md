# LibOS 接入：现状与验收依据

日期：2026-11-11。本文是工作记录，不替代 ADR。

## 已确认的目标与现状

- 用户要求以 `vendor/web-thread/upstream` 为源码基础构建 LibOS，复用既定设计，减少运行开销，并让 WASM 与 Native 的实际性能接近。Native 约 3000 tick/s 是已有样本的推进吞吐，不是已经验证的加速比；最终以同口径实测报告两种单位。
- `docs/decisions/0043-std-thread-ownership-runtime.md` 规定组与交易部所有权转移、FIFO 和收束、失败原子性；`0044` 规定早期死亡通知及 tombstone。替换底层机制必须保留这些契约。
- `0045` 保存上游原样快照并要求生产接入前完成浏览器及死亡协议验证。本次用户已明确要求将其代码用于 LibOS；适配代码应放在快照外，保留来源和许可。
- `packages/engine/src/runtime/wasm_wait.rs` 的协调者循环对 `std::sync::mpsc` 执行 `try_recv` 加 sleep。消息不会唤醒 sleep。Native 使用 `recv_timeout`。诊断记录的同入口 WASM A-B-A 分别为 264.51、699.24、243.52 tick/s；Native 长窗口为 3056.44 tick/s。这些不是同产物、同平台结果，不足以推断剩余差距归因。
- `packages/engine/src/thread_facade.rs` 已具有 Native 零包装别名和 WASM slot、spawn、join、tombstone 接线；不得把候选库的独立 Worker 生命周期直接替换上去而丢失现有死亡与回收保证。
- `web-thread` 的 Parker 是单等待者 token 协议；其 notify 只唤醒自己的原子字。现有全局 abort/death 字与 `std::mpsc` 私有等待字不同，因此仅替换 sleep 为 Parker 并不能让消息、断连和故障全部唤醒等待者。发送端、最后 sender 释放、永久关闭、宿主故障均需参与同一等待协议；需要避免检查后休眠前丢失唤醒。
- 前端 ACK 背压与逐帧投影是独立的产品路径问题，详见 `agents/web-architecture-diagnosis/report.md`；单靠线程库不能证明产品吞吐目标达成。交易事件、日界、存档和条件单语义不可为了提速而丢失。

## 验收证据

1. 相同队列语义下覆盖先通知后等待、等待期间通知、重复通知、检查与等待竞争、断连、关闭、超时和故障；覆盖消息顺序与跨线程可见性，真实浏览器验证。
2. 证明 worker 启停、join、失败、宿主 abort、受控 std 和 tombstone、清理及浏览器主线程响应；覆盖启动失败与硬 trap。
3. 以同一 setup、seed、输入轨迹、预热与计时窗口分段测 Native 与 WASM 核心、运行时以及完整产品路径，报告 tick/s、相对实时加速比、CPU、线程和限制；不能以参数调整或单次微基准冒充最终结果。
4. 对完整变更执行相关功能、交易语义与存档回归，并按仓库约定安排未实施改动的 subagent 独立审查与复核。
5. 以完整运行窗口验证约 3000 倍模拟时间加速目标：明确 tick 与交易日历的换算，纳入非交易时段、日界和保存耗时，分别记录 wall-clock 与计算口径；不得将 tick/s 直接等同于加速比。
6. 验证 Native 和 WASM 使用共同 runner 与等待状态机；UI ACK 不构成核心推进节拍；不可覆盖事实保留身份和顺序，日界、控制及恢复屏障仍满足约定。

## 上行通道试接复核（2026-11-11）

- `libos-upstream` 是实验 feature；WASM 上行改用通知通道，Native 仍使用 `std::sync::mpsc`。这只能作为试接，尚未证明两端满足共同等待状态机。
- 针对行政事务非阻塞检查补了故障前后检查；故障恰在出队之后时，阻塞与非阻塞适配器现在将消息放入接收器保留槽并返回 `HostAborted`，清理侧通过 `try_recv` / `try_iter` 可按 FIFO 读取。部分清理路径已通过 `try_iter` 排空，但各故障出口尚未端到端证明能够消费保留槽和在途队列，也尚未证明 `TaskDied` 的身份与 payload 端到端保留。受控 WASM 的 panic 按 ADR-0044 直接 abort，不能据此宣称通用消息契约已被证明。
- `converge_or_die` 与 Seal 的宿主故障均已标记 World 终态并停止 worker；Native 的真实 World 使用合成 `HostAborted`，分别在收到 0 / 1 个真实 SealAck 后验证已提交 tick、Calendar、publication Arc 和报告数量不变，终态拒绝重试。该测试先失败后通过，相关 Calendar 测试共 7 项通过；WASM feature 编译检查通过。它尚不证明真实 WASM 故障通知、完整账户状态或 worker join；多个 Drain 出口仍须统一审计和处理。
- 新增 World 接收收口用于 K 线诊断读取与生产使用的 `collect_plans_with`：合成 Drain 故障时原样返回 `HostAborted` 并判死；真实 World 测试先失败后通过，相关 Calendar 测试共 9 项通过，WASM feature 编译检查通过。K 线入口不是生产安装路径；计划簿读取发生在 `world.run_ticks(1)` 已提交之后，因此不能据此宣称整次 Session step 回滚。RuntimeDriver 会将该错误格式化为字符串；须验证 Session fatal latch、存档边界、原故障诊断及真实 WASM 清理有界性。其他 Drain 接收点仍未接入该收口。
- 日结的 DeskDrained、GroupDayDone 和 rollback 确认接收已接入宿主故障终态收口。直接发生 `HostAborted` 时不再尝试依赖参与者的正常回滚；若先有日结错误、回滚等待中再发生宿主故障，`DayEndRollbackHostAborted` 按发生顺序保留两个结构化错误。Native 真实 World 中合成故障覆盖首个 DeskDrained 前、0/1 个 GroupDayDone 后及 rollback 等待；Calendar 测试 12 项、日结公共视图测试 37 项及错误链定向测试通过，WASM feature 编译检查通过。部分 DeskDrained 后暂存清理、发送阶段故障分类、真实 WASM 故障与资源退出仍未验证；其他非日结 Drain 接收点也未全部接入。
- 行政收尾对 `HostAborted` 保留结构化主因：没有次生诊断时原样返回，有次生诊断时使用 `HostAbortedCleanup` 返回主因和诊断；shutdown issue 也会解包主因保留 worker。Native 确定性断连场景、三项定向测试及行政事务 28 项测试通过，WASM feature 编译检查通过。`thiserror` 的 `source()` 动态类型是 `Box<RuntimeError>`；已有 panic payload 时仍优先恢复原对象，但宿主错误与清理诊断在 unwind 前的对外可见性尚未证明。无次生诊断以及原 payload 与次生 panic 并存仍缺确定性测试；真实 WASM 故障后的 Final / join 有界性、保留槽清理及上层字符串化仍未解决。
- 完整个人态、信息移交捕获和 prepared 安装的 Drain 接收已接入宿主故障终态收口。生产 `collect_personal_full` 的通用 fatal cleanup 遇到 `HostAborted` 和清理异常时保留结构化主因与诊断；WASM join 的 `io::Error` 作为带 worker 与错误类别的显式诊断，不再伪装为 panic payload，此修正适用于默认及 LibOS 两种 WASM 构建。相关 Native 信息移交 10 项、facade DEAD join 3 项和 Calendar 12 项测试通过；两种 WASM 配置的编译检查通过，但真实浏览器的通用 fatal cleanup 还未验证。
- Native 局部合成故障在 prepared World 的一个真实安装回执之后注入时，新旧 publication 均未更换，旧 World 在该局部测试下仍可读取；prepared World 被消费后全部 owned handle 均有独立 join 结果，本次无次生 issue。该 seam 未广播实例级全局故障，不能推断同一 WASM memory 中的旧 Session 仍可恢复；也未经过真实 Session authority swap 或验证 WASM child 退出。
- 开仓派生、观察基、零售轨迹、信念、注意力、挂单及账户等九类读面和信息投递的 Drain 已接入宿主故障终态收口；挂单读取还拒绝在 `sever` 后将空 sender 表误报为成功空簿。Native 真实 World 矩阵验证了首次故障、终态重复读取和 publication 不变；强制信息投递测试在处理一个合法组回执后注入故障，检查 World 判死、Session snapshot 与 publication 不变。公开报告的三组 Native 夹具另行验证：正常对照的六个参与者实际获得信息，故障组在已收到非空更新后失败，Session 的完整个人态和注意力保持原样。设置故障注入时清空回执观测值，避免前次数据造成假阳性。该强制测试绕过生产 version/due 判据；生产判据的 Native 验证见下一条，真实 WASM 与完整产品存档门仍需验证。当前 Calendar 13 项、信息移交 10 项、信息投递 3 项及非空信息定向测试通过，默认与 LibOS 两种 WASM 配置此前的编译检查通过。回购读取、行政事务和 shutdown 的直接接收点具有独立清理包装，仍须按各自生命周期审计。
- Native 外置 RuntimeDriver 的 `runtime_step_with_install` 和内置 driver 的公开 `GameSession.step()` 均覆盖生产信息投递判据：同 seed 正常对照组真实公布月报并被两名参与者获知；故障组先提交 World tick 并公开同一报告，再于已校验的非空组回执后合成 `HostAborted`。故障组的 Session 信息态与投递开始时的注意力不被部分写回，首错被锁定，后续 step 和引擎 save 均返回同一错误；内置 driver 测试还直接验证 World 进入终态。两项定向测试于本次复跑通过。它们不证明真实 WASM、WorkerHost 或 IndexedDB 的相同行为；World 与公开报告此前已经提交，不能称整拍回滚。
- 行政终态清理会等待 join；非 `HostAborted` 的一般终态错误仍可能包装为 `ProtocolInvariant`，`HostAborted` 的处理见上文。需验证真实 WASM panic / hard trap 时清理有界，且原因可追溯。既有受控浏览器 fixture 仍有退出确认超时，不证明完整资源回收。
- 试接的 WASM `cargo check` 已通过；定向 Rust 测试 2 项与宿主布局及 supervisor Node 测试 13 项通过。这些测试不证明真实 World 故障路径、全量交易语义或性能目标。
- 使用 `libos-upstream` 和受控 tombstone std 构建的产物，运行 `controlled-panic/run.mjs` 后，真实浏览器中的 panic 和 hard trap 场景均观察到等待者唤醒及对应 join 失败，命令退出 0；记录在 `/tmp/stock-libos-upstream-controlled-browser.log`。该 fixture 使用验证专用通道，并非 World 上行接收；报告仍有 `FACADE_EXIT_ACK_TIMEOUT` 和 `incomplete`，不能据此宣称 worker 已完整退出或资源已回收。
- 保留槽变更后，Native 独立通道测试 36 项、上行适配测试 2 项以及 WASM feature 编译检查通过；真实 World 故障清理和保留槽的 WASM 热路径性能仍未验证。
- 真实浏览器中的 `GameSession` 引擎路径按 std → LibOS → std → LibOS 运行相同输入和计时窗口，分别约为 252、766、248、736 tick/s；这只是同配置下的初步诊断，尚未对照完整状态或测量产品 UI、跨日、存档与 Native。原始结果、失败记录和限制见 [试接测量记录](world-benchmark/试接测量记录.md)。
- 此后补测的一组浏览器 std / LibOS 样本在相同窗口下具有相同事件数和 `business_state_hash`，摘要计算在计时之后；比较器拒绝不完整或失败样本。该非密码学摘要仅覆盖现有业务投影，不证明完整状态、事件内容或交易顺序一致；具体数据与限制见 [试接测量记录](world-benchmark/试接测量记录.md)。
- Native 与浏览器 LibOS 的补测已校验 seed、setup JSON SHA-256、窗口及事件数量，但业务摘要不一致，比较器明确失败；两次 Native 的摘要一致。差异来源尚未定位，不能据此认定跨平台业务一致或将耗时作为最终性能验收；数据与限制见 [试接测量记录](world-benchmark/试接测量记录.md)。
- 逐字段追踪将首个差异定位到同一散户账户 `310` 的策略 `base_observation_probability`，两端 f64 bits 相差 2 ULP；账户 roster 一致，全部字段摘要有 83 处同位置不同。该概率使用 `exp_m1`，后续对输入的核对见下一条；其他差异及决策影响尚未证明。原始样本与限制见 [试接测量记录](world-benchmark/试接测量记录.md)。
- 后续按账户 ID 追踪确认：账户 `310` 的概率计算输入及 `exp_m1` 参数位值相同，原始输出相差 1 ULP，最终策略值相差 2 ULP；中间执行了 JSON 浮点规范化。两端 20007 条换算记录的账户顺序和输入均一致，96 条原始概率不同；其余业务字段差异及后续交易影响仍须验证，详见 [试接测量记录](world-benchmark/试接测量记录.md)。
- 直接采集真实规范化输入输出后，确认账户 `310` 的 WASM 概率在 JSON 规范化中再变化 1 ULP；两端规范化概率共有 82 个账户不同。Native macOS aarch64 的合成合法随机格点可使两个实测概率得到不同的注意力等待，但未证明该场景实际发生或产生不同委托；详见 [试接测量记录](world-benchmark/试接测量记录.md)。
- 隔离 `libm 0.2.16` 候选对本次 20007 个输入在 Native/WASM 返回相同的原始及诊断 JSON 往返位值；它会改变现有 Native 的部分初始概率，未接入 engine，也未证明正式依赖组合、旧档、交易或性能等价。详见 [试接测量记录](world-benchmark/试接测量记录.md)。
- 将两份隔离诊断的 `serde_json` 锁定到产品使用的 `1.0.150` 后，同一批候选输入的跨端结果和与 `1.0.154` 的版本间结果仍逐位一致；产品与诊断的相关 feature 树均为 default/std。诊断外壳并非正式产品产物，旧档、交易和性能等价仍未证明。详见 [试接测量记录](world-benchmark/试接测量记录.md)。
- Native 以旧算法生成的现行格式存档，在候选重建下通过过一次恢复及 3000 tick 的严格字节对照；但后续交错三次均出现事件字节差异，且前两次旧算法自身对照也有差异。三次最终存档和业务摘要均一致，首个不同 tick 去除顶层 `seq` 后事件多重集相同；这不能证明全部事件、真实历史旧档、WASM 或交易路径等价，也不能归因候选。详见 [试接测量记录](world-benchmark/试接测量记录.md)。
- 随后保留严格门并增加逐 tick 同股、同账户可见事件投影：三次交错样本的六组比较在 3000 tick 内均无局部投影差异，恢复与最终存档一致；其中一次旧算法自身对照的全局事件字节仍不同，批次严格门失败。该投影不证明 receipt、实际同价 FIFO 或完整中间状态；真实历史旧档、WASM 和性能验收仍未完成，详见 [试接测量记录](world-benchmark/试接测量记录.md)。
- 真实浏览器 supervisor 人工发布宿主故障的三个 `GameSession` 样本均返回 `TickConverge` 的 `HostAborted`；后续 step 和引擎 save 拒绝并保留首次错误，失败后的重试不推进 tick。最终 supervisor 报告均为 `incomplete: true`，未证明 worker 正常退出或资源安全回收。注入未与具体接收阶段同步，也未覆盖 panic、hard trap、IndexedDB 或日界存档；详见 [宿主故障会话验证](world-benchmark/宿主故障会话验证.md)。
- 随后在同类故障场景实际调用 `GameSession.shutdown` 并等待 supervisor child drain：三个样本均收到 6/6 个 owned handle 的 join 结果，1 group 和 5 desk 均以 `HostAborted` 失败返回，Final 数量均为 0；child drain 均成功，而最终 supervisor 故障报告仍为 `incomplete: true`。这证明这些样本中 join 已返回且 child drain 条件满足，不证明 engine/ingress quiescence、完整 Final 或共享 memory 最终释放。
- Worker 下行通知收件的实验原型位于 `runtime/worker_mailbox.rs`，尚未接入 World。Native 五项短测试覆盖已登记等待后的消息唤醒、同一发送者 FIFO、永久停止哨兵、故障域广播、出队后 fault/stop 时保留消息及断连；不能推断真实 WASM 或生产清理。独立预审确认接入前必须逐条证明停止及宿主故障都会通知每个等待槽；仅写 `shutdown` 或 external fault 原子标志不会唤醒等待。已出队载荷保留在 receiver 仅推迟释放，真实 worker 退出前仍须设计并验证剩余队列与保留槽的明确清理，不能直接 drop receiver 后宣称载荷安全。Native 的 `Duration::MAX` 等待只经当前 macOS 短测试，WASM 单次等待被原语饱和为最大有限值；不代表跨平台长期等待已验证。
- 同一原型新增分批清理移交：按保留槽、队列顺序转移消息所有权，显式区分暂空但 sender 存活、全部 sender 已断连及本批预算耗尽；只有明确断连才能视为收件结束，预算恰好取满也保守要求再次检查。七项 Native 短测试通过，新增测试覆盖分批、暂空后迟到消息、最终断连，以及真实 `GroupIn::Batch` 和 `DeskMsg::Ops` 类型的资源载荷移交。它不执行载荷、不证明资源已对账或 worker/宿主 quiescence；接入方须保留每批载荷，使用共享 deadline 控制等待，真实 WASM 和多发送者并发未验证。
- 下行所有权核对：`DeskMsg::Ops` 的 `DeskIn::Place` 包含组端已扣出的 purse 或股票，`GroupIn::Batch` 的 `DeskBatch` 包含资金、股票、成交、回执和终结标记；行政及计划消息也含事务与快照。终态清理不能把这些载荷当作普通成功业务重放，不能以空队列宣称账户守恒。组与交易部互持发送端，等待所有 sender 断开可能与等待 worker 退出形成依赖环；可考虑将 receiver 和 worker 退出结果移交清理域，再协调其余 sender 和诊断，具体方案及共享 deadline 尚未确定或实现。普通关停依旧须按既有 Final 协议走，不能用终态故障清理替代。

## 统一 LibOS 通道边界的第一步（2026-11-11）

根据用户明确的架构目标，`libos` 现参与 Native 与 WASM 的正式编译；新增 `libos::transport` 作为上、下行通道类型及创建的共同入口。Native 和默认 WASM 仍静态使用 std 类型，WASM `libos-upstream` 使用上行通知通道，`libos-worker-experiment` 进一步使用下行通知通道；类型选择与故障域登记迁入 LibOS。runtime 的 `upstream` / `downstream` 仍负责将底层创建错误映射为业务错误；上下行初始化错误现显示正确方向。Native 仅通过类型别名委托 std，没有为该层新增动态分发；尚未以机器码或性能实测证明整个路径零开销。

先写统一入口与 FIFO/断连测试并观察缺少入口的编译错误，再实现；错误方向测试也先观察参数缺失的编译错误，再修正映射。Native 验证构建的统一入口 1 项、上行 3 项、下行 1 项、WorkerInbox 2 项、Worker mailbox 8 项、World Calendar 20 项及真实错路由 3 项通过；各命令以 10 秒外部期限运行。Native 非测试默认 `cargo check` 通过，WASM 诊断工程的默认、`libos-upstream`、`libos-worker-experiment` 三种配置 `cargo check` 通过；这些编译检查不等于浏览器运行验证。独立复核确认本批未发现 FIFO/资产语义回归，指出旧有 host-ready 与故障并发时错误分类边界仍在，以及下行实际 WASM 故障路径未由映射单测覆盖。

这只统一了消息通道的类型和创建入口，**不是完整 LibOS 统一**：接收等待、故障映射、worker 生命周期仍有 runtime 层的平台条件或适配，线程创建仍走现有 `thread_facade`；WASM 下行仍是实验 feature，故障后 receiver 和在途资源的完整清理未验收。本批未重复实际浏览器性能测试，不能声称 Native/WASM 性能相近或目标完成。

## 非阻塞上行接收迁入 LibOS（2026-11-11）

## 正式 WASM 故障域与宿主握手（2026-11-11）

将 WASM facade 的 LibOS 故障域初始化、布局导出与 early panic 广播从 `verification-harness` 扩展到正式构建；新增正式 `libos_host_fault_layout` 导出，宿主启用 runtime 时优先读取它并交给 supervisor 登记。宿主目前仍接受只提供验证导出或无导出的旧产物，这只是迁移兼容，切换正式 LibOS 等待前必须强制校验新布局及 host-ready，不能把兼容路径视作故障广播可用。正式 facade 初始化会额外分配故障域并校验容量，初始化失败须废弃实例。

先添加正式导出通过握手的 TypeScript 测试并观察失败，再接通宿主；新增导出返回 undefined 的拒绝测试。宿主初始化、故障布局、supervisor 等共 22 项短测试通过，TypeScript `tsc -b` 通过；Native 故障域 14 项、tombstone 10 项及线程 4 项短测试通过。真实 `web-wasm` 默认配置经受控 sysroot release 构建成功，8 Cargo jobs，观察到 rustc 约 384% CPU，[构建日志](production-host/build.log) 与 [WASM/glue 摘要](production-host/artifacts.sha256) 已保留；构建前未冻结全部源码闭包。首次 TypeScript 编译检查命令因工作目录写错未执行，纠正后通过。

真实 Chromium 探针使用默认 release 产物、实际 `createFacadeEngineInitializer` 与 supervisor：配置完成时读取到 host-ready=1；主动调用 supervisor 故障后，结果显示 16 个槽，全部槽及全局故障域被标记。[输出](production-host/browser-run.log) 当次外层命令观察到退出 0；[探针](production-host/run.mjs) 固定本机仓库和 Chromium 路径，换机器须调整。首次加故障动作的探针将预期的 failure-pending 当作意外失败，退出非零；修正探针后重跑两次通过，未修改业务失败逻辑。探针未创建 child 或登记等待者，不证明真实 worker 唤醒、panic/trap 资源清理、完整产品游戏流程或性能。独立复核确认以上证据边界。

本批为正式 LibOS 故障通知准备宿主链路；默认 Worker 等待仍未切换，旧 watchdog 与上行回调仍待删除，两端统一目标尚未完成。

## 强制正式故障域握手及恢复能力预检（2026-11-11）

启用 WASM runtime 时，engine 初始化现在要求自有且可调用的 `libos_host_fault_layout` 正式导出，并在 supervisor 确认配置后才继续；缺失、仅有旧验证导出或返回 undefined 均显式失败。关闭或未请求 runtime 时不要求该导出。恢复 capability 的 `runtimeOverride: true` 也要求此导出，避免旧包通过预检后在实例初始化时才失败。默认构建 metadata producer 将该导出列入必需清单；独立复核又发现 producer 原本漏要求消费者必需的 `wasm_tombstone_init_primary`、`wasm_tombstone_bind_ingress` 和 `wasm_wait_death_layout`，现已补齐。启用 runtime 的旧 WASM 产物需要重建；存档 schema 未因本批修改。

按 TDD 先固定无正式导出的初始化拒绝及恢复预检拒绝，分别观察旧行为失败再实现；producer 的逐项缺失 metadata 测试也先失败后补齐清单。String 初始档和分块初始档缺少正式导出时，分别验证 prepared 档清理、token 清理、分块及控制端口关闭、无 configured；保留各自既有恢复与失败断言。初始化与恢复相关定向测试分批通过，producer/构建脚本 52 项通过，TypeScript 构建通过。真实默认 release WASM 与 glue 的导出交集包含 producer 所有 12 项必需导出；另一次真实 Chromium 重新经过正式握手，结果 host-ready=1、16 个槽均在主动宿主故障后标记。producer 的 12 项仅覆盖 String + runtime 必需集合；chunked 模式仍由额外 5 项导出预检，不能因 12 项通过而声称分块能力。

上述 Chromium 探针未启动计算 Worker，不证明等待者唤醒或故障资源回收。默认 Worker 仍走旧 watchdog，用户要求的完整 LibOS 统一及性能目标尚未完成；本批没有运行完整产品恢复或性能验收。独立复核已核对恢复契约、缺项测试和 producer 清单对齐。

## 默认 WASM 协调者上行切换至 LibOS（2026-11-11）

协调者上行不再把旧 watchdog 回调交给 LibOS：Native 通过 LibOS 内的 std `recv_timeout` 接收，默认 WASM 使用登记到正式故障域的通知 mailbox；deadline、断连、时钟异常和宿主故障映射到相位错误。Native 超时与断连的错误类别和相位保留，详情文案改为 LibOS 上行。默认 WASM 的 `HostAborted` 收口从实验 feature 扩展至真实 World、行政与清理分支。出队后故障保留消息只推迟释放，不证明资产对账或完整清理；旧的 Worker 下行 watchdog 仍存在，不能宣称整个 runtime 已统一。

先写三参数共同接收接口的就绪/超时/断连测试，观察旧五参数接口编译失败，再实现；Native 同时通过 LibOS 入口 6 项、transport 3 项、mailbox 22 项、World Calendar 20 项、真实错路由 3 项、行政事务 77 项，普通测试命令均使用 10 秒进程树 deadline。真实 `web-wasm` 默认 WASM cargo check 和 Native 默认 cargo check 通过；默认 release 产物 [构建日志](production-world/product-build.log)、[WASM/glue 摘要](production-world/product-artifacts.sha256) 已保存。诊断工程的上行模式声明已改为反映默认 WASM 实际使用 LibOS，不再错误依据旧 feature 名称报告 std。

真实 Chromium 默认 release 新建 Session 并推进 10 tick，[正常样本](production-world/normal-run.log) 由脚本确认 6/6 join 成功、1 组和 5 部 Final、child drain；初版日志 JSON 会省略 Ok 的 undefined 载荷，后续脚本增加显式成功计数并重跑。另一个真实样本先成功推进一拍，再异步触发 supervisor 宿主故障；[结果](production-world/fault-run.log) 返回 TickConverge HostAborted，shutdown 报告 6 个不同 worker 的 join 错误和 child drain，结果显示 0/0 Final。故障未与特定阻塞时刻同步，不能证明特定唤醒竞争、在途消息完整回收或资产对账。首次故障探针在 World 尚未构造前就触发，shutdown 正常返回使测试的“应当失败”断言失败；后续改为先成功一步，不将首次结果当作 World 故障证据。

## Worker 收件断连契约（统一 LibOS 计划第一批）

`worker_wait::receive` 原先将所有发送端断连当作 `Ok(None)`；这与计划中 `None` 仅表示已观察停止的契约不符。现增加 `WorkerReceiveError::Disconnected`，并由 `worker_inbox::map_worker_receive_error` 保留 `WorkerId` 映射为 `RuntimeError::Disconnected`。新增测试先因缺少断连变体编译失败；修正后空队列断连测试通过。队列余消息、停止与断连并存、身份映射另有测试，结果以实际执行记录为准。此修改尚未证明真实 WASM 或正式 World 完整生命周期；默认 Worker 下行仍未切换。

Native 重新编译测试程序后，`libos::worker_wait::tests` 4 项和 `runtime::worker_inbox::tests` 4 项均通过（各 10000ms 进程外 deadline、8 测试线程）；此前编译的相同实现另通过 65 项 `libos::` 测试，但不包含随后补入的 3 项测试。独立审查及补测后复核未发现本轮必须修复的问题。WASM 并发交错及正式运行路径仍未验证。

### 2026-11-12：正式 World receiver 移交红灯

在 `shutdown_completion/tests.rs` 添加真实 World 正常 Drain/Shutdown 后逐个 join 的行为测试：核对四个 Final，消费所有真实 handle，并要求返回 Group/Desk 有类型退出值及其 receiver，随后验证准入收束和队列排空。当前 Native 引擎测试二进制运行该测试失败于 `missing=[Group(0), Group(1), Desk(0), Desk(1)]`：四个句柄已 join，但返回类型仍是 `Result<(), RuntimeError>` 而非 `OwnedWorkerExit`。测试临时使用 `Any` 使当前与目标类型都能编译，正式接入后应改为静态匹配；该测试不证明资产已对账或 WASM child 已释放。不要用添加布尔标志冒充 receiver 移交。
