# 受控 std 的真实 child panic 验证

2026-11-11，验证范围为 `verification-harness` 下的实例级 `GlobalFault` 接线；产品 runtime 的通道尚未登记，JS `GLOBAL_ABORT` 尚未接线。

使用 `preparePinnedSysroot` 校验固定 `nightly-2026-09-05`、rust-src 和补丁锚点后生成受控 sysroot；`wasm-pack build apps/web-wasm --target web --release --features verification-harness` 使用专用 `RUSTC_WRAPPER`、独立 target、`CARGO_BUILD_JOBS=8` 和进程外 290 秒 deadline。首次 release 构建用时约 1 分 53 秒；观察到 engine rustc 约 749% CPU。随后在源码哈希记录前后重跑增量构建并比较所列七个文件的哈希一致，记录在 `source-before.sha256`、`source-after.sha256`；输出 WASM 与 glue 的哈希在 `artifact.sha256`。这七个哈希不是整个依赖树的完整 manifest。`facade_slot_init` 还会检查受控 std marker。

Chromium 使用真实 engine supervisor、engine Worker 和 facade child bootstrap。engine 在初始化后登记故障域通道并创建 child，第二次 spawn 返回预期错误且实际 child 创建数仍为 1。页面读取接收通道等待字，观察到 `PARKED` 后释放 child gate。child 经受控 std 发生真实 panic；接收方返回 `Aborted`，join 返回 `FACADE_DEAD_PANIC`，child 1 的 tombstone 为 `panic`，消息为 `LIBOS_FAULT_WAKE_PROBE`。浏览器 runner 在 10000ms 外部进程树 deadline 下退出 0，原始输出见 `browser.log`。`PARKED` 只表明登记等待，不证明底层 atomic wait 已阻塞；gate 超时会使 child 正常返回，而不是伪造 panic。此例没有覆盖 hard trap 或宿主直接写 `GLOBAL_ABORT`。

最终 failure 的 `context.incomplete` 为 true，后续原因中包含 `FACADE_EXIT_ACK_TIMEOUT`（未观察到真实 workerExit）；因此本例不证明 child 干净退出。page 和 Worker 最终整体销毁，也不能证明消息通道、Worker 栈或共享 memory 的独立释放。该单次功能检查不证明完整游戏性能或生产接入。Vite 输出包含可选 esbuild 的 unresolved import 警告，未阻止此测试；panic 本身造成的 Worker error 是本场景预期行为。

复现前须在新目录准备受控 sysroot 与 Rust wrapper，构建输出至绝对路径；随后运行：

```sh
LIBOS_CONTROLLED_PKG=/tmp/stock-libos-controlled-pkg node scripts/run-with-deadline.mjs 10000 -- node agents/libos-integration/controlled-panic/run.mjs
```

## 宿主共享内存故障写入验证

新增验证用 `verification_host_fault_layout`，从受控 std 的真实 Rust `GlobalFault` 导出全局状态、域标志及每槽故障字和等待字的地址。验证 fixture 在相同 shared memory 中检验槽数与 facade capacity，且要求五类具名保护区域（arena、engine/ingress tombstone、DEAD、现有 GLOBAL_ABORT）与新布局不重叠；本检查不能凭地址形状证明任意伪造地址确属 Rust 对象，调用方必须绑定可信导出及实例生命周期，并从已校验 substrate 构造包含正确长度的保护区域；parser 本身不证明这些区域的地址或长度来源。

浏览器第二个场景先从真实导出读取布局并登记等待，页面观察 `PARKED` 后调用 `abortLibosHostFault`；engine Worker 从 `verification_fault_wait` 返回故障。该场景直接调用新写入原语，**没有**经 engine-supervisor 的 fatal 或既有 `abortWasmWait`，不能宣称 JS GLOBAL_ABORT 已接线。`host-browser.log` 同时保留 child panic 与宿主写入两场景，命令退出 0；`host-source-before.sha256` 与 `host-source-after.sha256` 相同、`host-artifact.sha256` 为本轮产物。它们只覆盖列出的文件，非完整依赖 manifest。

宿主写入原语的五项 Node 测试覆盖多等待字唤醒、memory.grow、越界/重叠/缺项、稀疏槽及跨 memory 误用；Web TypeScript 编译检查通过。布局解析含排序与 O(N) 额外内存，故障广播同步遍历 O(N) 个槽；大容量事件循环延迟未测，不得据此宣称适合生产最大容量。`WeakMap` 所有权检查要求同一 JS realm 和相同 Memory 对象；在实例释放后调用仍由宿主生命周期负责禁止。

此前 panic 场景的 `FACADE_EXIT_ACK_TIMEOUT` 出现在 supervisor 将 join 槽观察为 `DONE` 或 `CONSUMED`、而对应 child 未报告真实 `workerExit` 时。真实 panic 不经过正常 trampoline 退出；该记录如实保留未证明静止的边界，不能将其简单消除并宣称安全释放。是否需要区分已确认死亡和正常退出的报告语义，仍需针对状态转换和资源证据单独验证。

## supervisor 配置握手与真实 fatal 验证

`verification-harness` 导出布局经 `facadeEngineConfiguration` 传到 supervisor；仅启用 runtime 且验证导出存在时尝试传递。supervisor 要求此前已登记同一 Memory 和 primary，验证 facade capacity 与既有五类区域，此外拒绝后续 child tombstone 与故障字重叠。旧 `GLOBAL_ABORT` 和 LibOS 通知分别尝试；任一路失败不会跳过另一路，原有嵌套 cause 经结构化失败记录保留。未经验证导出的正式包不启用此故障布局；现有 World 尚未使用 LibOS 通道。

`supervisor-browser.log` 使用受控 std release WASM、真实 supervisor 和 child bootstrap；fixture 使用 `createFacadeEngineHandshake` 登记 Memory、primary 和配置，但手工初始化 engine，未经过产品 `createFacadeEngineInitializer` / `worker-host` 完整链。两个独立浏览器场景均先确认等待登记，再释放 child gate：panic 场景接收方被唤醒，join 返回 `FACADE_DEAD_PANIC`，tombstone 为预期消息；hard trap 场景经 supervisor 的真实 child 故障出口发布旧 `GLOBAL_ABORT` 和 LibOS 故障，接收方被唤醒，join 返回 `FACADE_DEAD_HARDTRAP`，tombstone 为 absent。两个场景最终 `context.incomplete=true`，都记录 `FACADE_EXIT_ACK_TIMEOUT`，因此不证明 child 真实退出或资源回收。

本轮受控构建 `CARGO_BUILD_JOBS=8`，一次 rustc 进程采样约 617% CPU；最终增量构建前后的所列 14 个文件哈希一致，记录为 `supervisor-source-before.sha256` / `supervisor-source-after.sha256`，产物为 `supervisor-artifact.sha256`，并非完整依赖 manifest。浏览器命令受 10000ms 进程树 deadline，退出 0。相关 Node 测试分三个并发批次共 80 项通过，Web TypeScript 检查通过；不代表全仓回归。

保护区域由已登记的 supervisor substrate 构造；几何检查仍不能独立证明来自 WASM 的地址属于 Rust 对象。大容量下逐槽分配、布局排序/额外内存及同步故障广播的代价尚未测量。实例配置完成前发生宿主故障时尚无已登记的 LibOS 布局可广播，仍需按宿主现有故障终止路径处理。
