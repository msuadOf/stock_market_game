## 复用缺口与最新政策核对

- **沿用、不重开**：G01–G05（remote鉴权/倍率/pull/baseline/reconnect）、G18（Worker背压）、G19（Tauri固定高倍率聚合）、G20（普通新局取熵）；r19正文已逐条给出生产链断点。G35–G38公司期末/多行业会话/DEV订单/预算分类与这三篇无关，不重复。
- **0023–0026核查**：所有市场历史仅作虚拟前史、无真实市场校准；资金池不自动补钱；仅自然日日结公共存档、checkpoint仅内部；个体机构暂停买入不自动强卖。ADR-0005初版的泛化存档/市场/RNG语句不得扩张这些政策。
- **0021/0022核查**：限价、极价主动成交语义不能简化成必须新增 PlaceMarket；本次未发现三份架构 ADR 要求修改订单类型。
- **0018**：整体 proposed，不作为已批准完整时间线要求。**0027/0028核查**：运行时选择宿主、7个手动入口、有效tag触发Release/Pages；普通commit/PR不自动CI，签名/公证暂不做。因此 0007:40、52–55 的“CI必然对生成漂移门禁/固定自动CI与平台执行”不能当现行普通提交自动工作流要求；脚本仍可人工/被明确调用。也不把无签名列为缺口。

## 新发现 / 歧义收口

- **未登记新 G/Q**：当前能静态确认的生产断点均已由 G01–G05、G18–G20 覆盖。没有用 `cfg(test)` helper 或未调用纯函数作为生产实现证据，也没有以结构同名与否判断功能有无。
- **验收证据债**：三宿主端到端、remote真实浏览器鉴权与断线恢复、Worker/Tauri节奏与背压、桌面/移动真实视口、主题/中文视觉一致性均未在本轮运行；其中已知功能断点仍按 G 编号，其他是建议在对应构建/浏览器下做代表性短验证，不报告为已通过。
- **具体歧义**：0005:91 的 Publisher“16ms定时推送或客户端拉取”由 0010:32 定为 remote capability，但 G03显示生产浏览器 pull 未接；需以远程端到端短验证确认push帧消费与pull请求循环。0007:40/55 的CI措辞与0027/0028自动触发政策冲突，按新决定解释为可手动调用的门禁，不构成新缺口。
- 已检查的测试源码建议（均未运行）：先补/执行针对 G01–G05/G18/G19 的远程与宿主短契约用例；界面验收用现有 `apps/web/e2e/mobile-layout.spec.ts`、`trading-workflows.spec.ts` 的单场景及 production preview；保持普通 Node case/命令各≤10秒，避免把浏览器视觉/线上发布验收宣称为单测。
