## 新发现与歧义收口

- **新发现：原文 OrderId 分配责任互相冲突，暂不登记实现缺口。** Plan Task 2 指明 `Order { id }` 由调用方提供；Spec §2/§3 却写“本模块内自增分配”，并列 `next_id`，但其 `place(order)` 又接收带 id 的完整订单。生产路径由 session 草拟/分配 id 后传入，`packages/engine/src/session/pipeline/continuous_matching.rs:463-473`；簿拒绝重复 id `packages/engine/src/orderbook.rs:314-315`。未发现现行政策要求改为簿内造 ID。建议后续正式收口为“会话分配身份、簿分配优先序”，并给重复 ID/部分成交后的身份唯一性加一个普通短测试（现有部分成交、重复保护源码可审，但目前未见明确重复ID测试断言）。
- **设计内部签名歧义**：Spec §3 `new(tick) -> Self` 与同段“非法 tick → Err”、§5 `InvalidTick` 冲突；实现采用 `Result<OrderBook, OrderError>` 并有 tick 测试源码，语义已明确，无新增实现缺口。
- **价格边界差异属需求歧义，当前证据不足以判实现正确或缺失**：旧 plan Task 4/Spec §4 允许零价（`price >= 0`），生产簿拒绝 `price <= 0`（`packages/engine/src/orderbook.rs:335-345`）。本轮未找到对应最新决定/`docs/trading-rules.md` 明文依据，不能仅凭 A 股常识给它盖章；保留现状并由领域政策登记正价边界或修订旧文。短验证建议：在零价/正价边界测试中固定政策预期；无需运行本轮测试。
- **市场单/市价意图**：旧设计将市价单列为未来事项，但 ADR-0021/0022（当前审计政策）允许有界的极价主动限价成交。现有会话路径对未成交余额撤销并释放，不能按旧 YAGNI 清单提出“缺 PlaceMarket”新项。
- **未发现符合新缺口登记标准的订单簿生产断链**：价时撮合结果确实进入逐方回执、session 事件、盘口/委托状态消费；不能以模块存在或仅有单元测试作为此结论依据。未发现项不等于所有历史过程 DoD 已验收。
