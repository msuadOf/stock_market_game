## 新发现 / 歧义收口

- **无新增 G/Q。** 零 NPC 的 ByKind 校验缺口已是 G29；比例和、类内采样与 Pareto/散户 eligibility 的旧新契约待收口已是 Q06。真实市场统计校准、补充现金、公共日内存档、强卖和强制 PlaceMarket 分别被 ADR-0023/24/25/26、ADR-0021/22 覆盖为不要求或不适用，不得据旧需求再开缺口。
- **历史“存档复用 setter”属于实现路径漂移。** Design §1–2、§4（`:17–21`、`:92–97`）与 Plan Task1 L77–91 说精确恢复复用 `grant_position`；现存生产恢复路径直接从日终档恢复完整 Position（`packages/engine/src/session.rs:2911–2935`）。ADR-0025 限制公共档为日终档但要求保留资金、股份、T+1等事实；没有证据显示恢复结果缺事实。若要求必须共用 setter 属结构/API一致性需求，应明确是否仍必要，不得当作未实现精确恢复。
- **最新规则取代旧默认而非漏做。** GameConfig spec 的 `st_limit=0.05` 与测试注释中的旧值，不适用于当前主板风险警示股票；源码默认/验收断言均为0.10。交易制度判断依据由已有 `docs/trading-rules.md`/ADR-0021 登记；本轮遵守禁止网络，不重新核验官方网页。
- **配置灵活性边界明确但文案有歧义。** 旧 spec 说佣金、印花税、涨跌幅都可配置；现正式 A 股 setup 对印花税和涨跌幅施加政策校验（`packages/engine/src/session.rs:999–1011`），费用函数仍支持字段级配置并被账户直接消费。将“任意值均可用于正式 A股 session”理解为承诺会与现行交易语义冲突；需要需求方确认前，按正式市场规则限制解释。无需新增缺口编号。
- **代表性短验证建议（未执行）：** 对 float 建一个小 setup 同时验证随机/ByKind守恒、零 NPC/无有效权重拒绝、首 tick真实成交及账户余额费用守恒；对 config 验证 serde 坏值经 session 构造显式拒绝、买卖实际结算的佣金/印花税/过户费、主板10%限制及创业板类别边界。单条普通用例须小于10秒；分别进程运行需遵守 AGENTS 的 deadline 约束。完整交易制度依据不在本任务复核范围。
