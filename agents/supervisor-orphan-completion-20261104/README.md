# root 提前退出后的命令后代清理

日期：2026-11-04。来源：旧候选 `7f66a443`；旧快照方案没有直接合入，当前实现复用既有 token 清理器。

## 已确认的缺陷与实现

- 新用例在修改前确认：root 以 0 或 17 提前退出后，独立进程组后代仍存活，调用方不能据此确认清理完成。
- 每条 Linux 真实默认命令使用随机环境项，嵌套项互不覆盖。成功、失败均扫描继承该项的后代，使用同 birth 内两次环境读取确认归属，终止前复核 PID 出生身份。
- 补首次快照后父进程 fork、在 token 被读前退出的确定性真实用例。只有 token 匹配与新增 PID+birth 身份都不再出现才返回。临时移除新增身份检查时该用例失败，恢复后通过。
- 扫描按批让出事件循环，排除早于监督器出生及已终态进程，避免本机约 1.25 万个 /proc 条目造成不必要读取。沿用原共享 deadline、原退出码及 stderr。
- 保留限制：主动清空继承环境、权限变化和外部 daemon 不受强隔离保证；整机进程持续变化可导致保守超时；custom spawn/cleanup hook 沿用原合同。本实现不能宣称任意后代都可被识别。

## 验证与独立审查

- 使用 `run-with-deadline.mjs 10000 -- node --test --test-timeout=10000 --test-isolation=none` 分别执行：基础 24/24、cleanup 16/16、orphan 3/3，全部 exit 0；套件分别约 3.32、4.93、0.90 秒。四路并发。
- proc 身份套件先前直接运行 20/20 通过；最后带进程树监督复验在磁盘准备阶段超时，未通过，不能算最终绿灯。
- 首轮独立审查发现单快照/零匹配 fork 竞态；已修复并由第二名未实施代理重新审查，未发现阻塞问题。审查明确保留上述识别边界。
- 正式 scripts 聚合配置：4 文件 worker、每文件/用例 10000ms、总批 300000ms。首次缺少 TypeScript 依赖；按锁文件安装后仍在既有 `stageFrontend` fixture 的 btrfs 元数据等待处超时，聚合未通过。日志在本目录。
- 该独立 staging fixture 的临时根迁到 Linux `/dev/shm`（其它平台 tmpdir），同 case 约 522ms 通过；断言和 timeout 不变，另有独立审查。整批其它磁盘 fixture 仍受现场 I/O 压力影响，不能把单例通过写成聚合通过。
