# CompanySystem 与 SimpleFundamentals 实施清单

> **范围与状态：** 本文按 2026-10-06 最新 [Q14 公司基本面与经营系统设计蓝图](../remaining-questions-and-features/q14-financial-model-design.md) 重整。目标是 `company/` 薄共同入口及可独立运行的 `SimpleFundamentals`，其财务查询、披露、分红、配股、增发、回购与 `CompanySimulation` 具有相同功能和业务语义。`CompanySimulation` 的经营系统由用户授权后续另开分支；当前不要求先完成客户/行业生产 dispatch。计划不代表实现或验收已完成。

当前已接通周期生成、四种 `CompanyKind` 的汇总财务、公开查询与披露、Session 日结和严格恢复，以及新局的 seed 预览与实际创建。基本面不是完整经营仿真；各类别使用独立标注的虚拟汇总科目，不冒充贷款、保费或客户收付款。现金分红候选接线已验证显式名册/法定事实下的真实税前到账、应付清偿、同日合计除息锚及公开公告/NPC 本人获知；个人公开市场身份可通过真实 FIFO 卖出触发股息税补缴并严格恢复。送转已接通实际登记全链路（方案→R 日碎股分配→R+1 非交易过户入账、投资者加股、发行股数守恒、沪深分列除权锚），限售继承按同限售类整批继承、混合来源显式拒绝，Simple 侧只做面值展示事实。送转公开 typed 公告与 NPC 本人获知已于 2026-10-08 G 批接通（18:00 公告通道、Web 存档 parser 同步）；送转个税与转增资本公积账面校验仍未完成（后者 2026-10-08 N3 批已接通）。2026-10-07 S2 批已接通本机 WASM 宿主的偏好配置 UI 入口（新局 `SimpleCompanyPreferences`）、偏好提案拒绝台账与配股认购拒绝回执查询面；Tauri/远程宿主查询面、其他税务身份仍未完成，`cash_settlement` 如实为 `false`。底层接线不能扩称完整分红、认购或回购已可使用；证据与边界见[除息基础复核](ex-reference-price-review.md)、[Session 接线复核](session-corporate-actions-review.md)、[送转登记记录](stock-distribution.md)及[当前交接](current-handoff.md)。

验证范围只包括短单测、编译、类型检查及构建。前序 Simple 批次的 Rust 代表短测 85 项、Web 新合同短测 45 项通过；后续报告窗口、现金公告、个人信息不足及股份分配基础的定向证据分别登记于[当前交接](current-handoff.md)，不把 85／45 作为所有后续改动的最终证据。真实存档由 release Engine 生成并验证恢复续行，绑定通过正规 typegen 生成。默认 features 下的 workspace 调用方编译及前序 WASM／Web 构建通过；旧经营 Session 的特定集团和冲击接线留作后续 Simulation 门禁，不因迁移测试归档而登记为通过。未运行完整回归。

## 已确定边界

- 新局显式选择 `Simple` 或 `Simulation`；一局内不切换，存档严格恢复原模式。未知、缺失或错配状态显式失败，不做静默降级、默认填充或兼容迁移。
- `CompanySystem` 只负责共同身份、实现分派、共同财务/股本行为契约、结果及严格状态存取。身份不能强制内含 `Books`、`ContractBook`、客户表；拆出共同身份与仿真实体。`simple/` 与 `simulation/` 不互相调用。
- 两模式对上层提供相同功能与业务语义，包括财务查询/披露及公司股本行为。`simple` 省略具体客户、订单、产线、逐合同网络及研发项目，不省略报表、税务和股本行为所需的汇总状态；不能按模式返回功能不支持。
- `SimpleFundamentals` 严格按显式配置的结算周期生成营收与开支变化，周期可为月、季度、半年或年；不强制内部按月生成，也不将月度当作权威唯一粒度。营收、固定及变动开支等各自使用与所选周期对应的规则，随机扰动按各结算周期分别配置。利润、净利润、权益/ROE 等由一致的收入、费用、税务、权益状态推导，不能再独立抽取/乘一个净利率或利润增长覆盖结果。应收应付、收现付现等汇总规则须支撑财务表间勾稽，但不得伪造具体客户或经营事实。
- `simple` 的公司现金/投资额仅为汇总账面展示数据，按上次结算账面数据与百分比规则更新，不建模真实公司现金余额或真实资金流向。不得增加补款周期、额度、申请或 `SyntheticFunding` 虚拟资本事件；也不得声称展示值代表可支出的真实公司现金。
- 投资者端分红、配股/增发认购、回购委托与成交仍操作真实投资者账户和股份；这些事实按主体、事件标识和状态幂等处理，不得被公司账面百分比更新覆盖、重复发放、给认购者补钱或伪造成交。`simple` 分红按可分配利润及方案等条件结算给真实持股人，不因仅供展示的账面现金不足而拒绝；配股/增发认购受本人实际现金约束；回购必须通过真实委托和成交。公司账面值与投资者实际结算是分离语义，不能捏造二者之间的真实资金来源链。
- `accounting/` 仍是唯一金额、记账、计量、报表算法；simple 可经汇总事件复用账簿与结算规则，不运行完整经营仿真，也不另设与账簿无关的展示现金。
- 指标带单位、期间、范围、模式来源和披露时间。不可用仅适用于双方共同的数据条件（例如未披露、无历史期间、零分母）；simple 不能因模式而缺财务字段。合法零值、共同条件下不可用及输入/状态错误分别表达。
- 基本面结算周期与 `ReportFrequency` 独立配置。结算周期长于所需报告期间且没有该细期间已结算事实时，不把长期间金额擅自均分到未来细期间、不伪造已结算资料，也不因此取消或静默跳过既有披露；按真实可用数据表达细期间材料不可用及其原因。
- 玩家、NPC、估值与 UI 通过共同查询/披露入口读取；NPC 仅使用本人已获知材料，计划/未公开结果不得前泄。能力/业务条件可以拒绝不满足约束的单次股本操作，但不得把 simple 模式本身列为不支持。
- `CompanyKind`、`IndustryId` 与证券板块分开。最终仿真涵盖各公司各自业务链；旧工业单一范围不是最终产品边界。
- `CompanySimulation` 以后应保持单一权威公司账簿现金、每个客户独立有限现金/债务、事件具名来源/去向及跨主体原子结算；支出优先级依公司显式 policy，不设全体公司隐含 `R&D`/`CapEx` 顺序。已有有限客户现金和 Bank 来源基础可保留，但不能称为生产 dispatch 已接通。

## 参数与实现边界

- SyntheticFunding 已由用户明确否定，不是待答子项目，不应出现在实现计划、存档、账簿或测试契约中。公司账面展示值不建模真实来源流向。
- 财务生成使用的具体可编辑 preset 数值尚未在本清单逐项批准；用户已确认可编辑虚拟 preset 这一方向。未确认的值只做配置，不声称是行业事实。
- 参数合法范围、百分比更新的精确字段映射、各期间税务规则、报表展示口径与模式字段结构按实现中的正式接口逐项明确；现实 A 股制度须另据官方现行材料核验。
- 后续 simulation 支持范围和默认参数不作为本批 simple 的前置条件；两模式共同功能语义不可因此降级。
