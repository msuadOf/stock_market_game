# 递归 rustfmt 噪声清理审计

- 基线：分支 `main`，比较对象为 `HEAD` 中各 modified `.rs` 原文。
- 判定命令：每个文件分别执行 `rustfmt --edition 2024 --config skip_children=true --emit stdout`，随后将输出与当前文件按完整字节比较；用 SHA-256 记录 HEAD 原文与当前文件。
- 并行：32 路独立 rustfmt 进程；盘点阶段未改源码，恢复阶段的范围见下方处理结果；未运行 Cargo、测试、索引或提交。
- `PURE` 表示当前文件完整字节等于 rustfmt 格式化后的 HEAD 原文，且不属于并行作者明确 owner 范围，可安全恢复为 HEAD 原始字节。`DIFF` 表示当前字节与格式化后的 HEAD 不同，保留；不能推断其中各 hunks 归属。`EXCLUDED` 文件依照 owner/公告 consumer 范围排除，不纳入纯格式恢复，即使一致也不恢复。
- 共判定 162 个 modified Rust 文件：139 `PURE`、11 `DIFF`、12 `EXCLUDED`。
- 处理结果：139 个 `PURE` 文件均在应用补丁前再次验证 current SHA-256 与本台账记录一致、HEAD SHA-256 未变化；使用完整文件上下文的 `apply_patch` 恢复为 HEAD 原始字节。139 份 HEAD 原文已通过 `apply_patch` 备份至 `.tmp/company-system/recursive-rustfmt-cleanup/`。9 个较大文件首次受命令输出上限影响，单独提高读取上限后重试成功。无跳过、无恢复失败。
- 清理后保留初始判定中的全部 `DIFF` 和 `EXCLUDED`，合计 23 个文件。执行期间另出现 `packages/engine/src/accounting/disclosure_roe.rs` 工作区修改；该文件不在初始 modified Rust 清单，未触碰并交由 owner 保留。
- 未运行 Cargo、测试、索引或提交；恢复只使用 `apply_patch`，没有使用 Git 还原命令或直接写入源码。
