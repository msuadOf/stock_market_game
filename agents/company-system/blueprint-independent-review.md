# CompanySystem 蓝图独立复核

## 范围与结论

依据用户在 2026-10-06 指向并随后更新的 `q14-financial-model-design.md`，连续读完最新文件 666 行，复核 `docs/decisions/0035-company-system-simple-fundamentals.md` 全文。先前已连续读过关联 `company/economy/system_sim/README.md` 和 `DESIGN.md` 820 行，以及工程原则、ADR-0016、0024、0025、0029、开放问题、架构与下列实际接线。本次没有修改用户蓝图、移动源码、运行 Cargo、访问网络或执行回归。

最新设计覆盖此前“simple 不提供现金/完整报表/股本能力”的方案：两个模式必须提供相同上层功能与财务语义，simple 简化内部过程，不简化共同结果。旧评审提出的“无账簿初始化”“以缺少现金能力拒绝 simple 分红”和“新增 partial-report 载荷”不再是实施建议；旧文件与审查历史只能用于追溯，不应作为当前实现门禁。

用户明确本轮实施共同接口与 `simple` 全链路；复杂 `simulation` 由用户另开分支实现，当前 Simulation 请求显式拒绝，不把旧 CompanyOperations 当作已实现新仿真，不自动降级。两个模式内部不互相运行。蓝图、演示公式和真实案例不等于默认数值批准；用户已许可明确标注虚拟、可编辑、seed 可复现的预设；最新回答明确取消 SyntheticFunding，不再询问生成触发、额度或资本投入映射。

方向符合经营与证券交易分层、本人获知及严格日终恢复。simple 只按上次结算与百分比规则生成账面财务，不追踪真实公司资金流向，也没有每月资金生成概念。投资者端公司行为仍使用真实账户、股份和成交，不是任意补钱许可。这里是设计与 caller 审查，不是代码验收，没有重新核验交易所、中国结算或会计法源。股本、行业监管与税务仍须各自记录官方依据和适用日期。

## 可执行的共同契约

以下名称为建议，不是已经导出的 API；复用既有 CompanyId、CompanySpec、CivilDate、scope、period、金额、publication 与股本领域身份，不另造同义类型。

- `CompanySystemConfig { issuers, implementation: Simple(config) | Simulation(config) }`：tag 与专属字段成组，共同身份不强制 Books/客户/合同；simple 自己可以使用汇总 Books，不用 Option 万能实体装全部仿真。
- `CompanySystem { issuers, implementation, advanced_through }`：只持所选实现，simple 唯一汇总账面状态与 simulation 唯一真实资金状态分别持有；恢复日期与内部月份/下一日期交叉校验。
- `create(config, start_date, seed)`：全部身份与映射先验，选中实现生成明确日期前史；simple 前史汇总财务与开局真实余额连续，不调用旧完整经营来填报告。当前 Simulation 未实现返回明确错误，无 fallback。
- `advance_day(date, inputs, commands)`：恰好下一自然日，candidate 生成汇总事实、过账、共同业务结算、披露后再提交；失败不得部分提交 RNG 或公司行为。重复日执行与单个业务幂等分别校验。
- `capabilities(company)`：功能集合不因 simple 模式减少；当前操作条件、数据未披露、无历史或零分母分别描述。Malformed 输入不是“不支持”，真实零值不是“数据不存在”。
- `query_fundamentals(query, trusted_visibility)`：所有模式同一完整报告契约；玩家取已公开、NPC 取本人获知，网络调用不能自选 Internal 权限。内部财务不得偷渡为公开视图。
- `query_explanation`：simple 返回真实汇总账面生成贡献及实际公司行为结算事实，不能编造具体客户或研发。内部未公开诊断另设授权，非公共字段。
- `submit_command`：相同股本规则和结算入口，先校验身份、条件与参数；受理不代表完成。simple 因资金或利润不足可业务拒绝，不可按模式永久判 Unsupported。
- `export_state/restore`：严格当前 tagged state，保存汇总账面财务、已受理未执行公司行为、披露、随机和月份事实。未知 tag、缺/额外字段、日期或引用错误、现金/股数守恒错误显式拒绝，无 schema 代际、default/alias 或旧字段兼容。

simple 的营收、固定开支及变动开支分别生成；变动开支按营收比例或自身增长择一，不重复生成。所得税、利息、折旧等依会计科目只计一次，不另抽净利润/ROE覆盖结果。比例超过 100% 可表达高成本亏损，零收入复业用明确输入。净利润与平均权益按同期间/同范围派生 ROE，非正权益不可用，不把月指标冒成年指标。

汇总收现/付现规则、应收应付批次、资产与债务可省略细粒度客户，但必须形成勾稽报表；旧款回收不能再次确认收入。年度/半年/季度材料累计真实月份流量，期末取对应日余额；同期间 Annual > HalfYear > Quarter > Monthly、同 scope 取材、归母/少数股东与更正规则保持。股本行为对现金、权益和平均权益的真实影响不能被月末目标余额覆盖。

SyntheticFunding 已被用户否定，不创建补款周期、额度、申请、事件、资本投入科目或变相替代机制。simple 的报表现金和投资金额是账面模型，不声称资金来源与流向真实闭合；这不豁免投资者端幂等、原子性、股份与税等共同规则。制度性的配股/增发仍用认购者实际现金；回购需真实委托与成交，不制造卖方。simulation 不采用 simple 账面简化，仍遵有限现金与明确经营/融资来源。

## 本轮纵切面与未来交接

1. **共同入口和唯一 owner**：共同 registry 拆离财务，Session 只调用 CompanySystem。原独立账务与领域测试可保留供未来仿真使用，不能成为 simple 的后台经营影子。未实现 Simulation 请求显式拒绝，未来迁移后不保留兼容入口。
2. **simple 完整财务链**：明确配置→上次结算与百分比规则生成营收/开支和汇总账面→结账/披露→本人获知→NPC 分析→玩家查询。全报表满足共同结构、来源标 SimpleGenerated，不创建虚构客户和业务经历。
3. **共同股本闭环**：分红、送转、配股、增发、回购复用唯一规则；Simple 公司侧为可核对账面，投资者侧为实际现金、股份、税和幂等事实；两者边界明示。各行为按适用法源区分条件，不因为复杂经营尚未实施而省略 simple 功能。
4. **所有宿主接通**：WASM、Server、Desktop、Web parser、新局表单和存档使用当前统一结构；UI 财务业务不按 mode 分叉，只展示新局选择和生成来源。普通查询不重载存档；成功自然日日结才写 IndexedDB/SQLite。
5. **未来 simulation**：有限客户收付、资源/产能、研发与各行业业务继续作为后续交接，不宣称本轮完成或运行；共同规则不能为了 simple 实现复制出另一套 simulation 专属股本算法。

生产预设明确标虚拟、可编辑、seed 可复现；可按稳定场景输入生成，不用证券现价倒推正确基本面，不把蓝图演示数字当默认数值批准。多人市场控制授权与经济账户及保存 mode 分开，读档不授控制权。

## 短测与独立验收门禁

每个 case 和整条普通测试命令均不超过 10 秒，短分片并行；本次未运行测试或回归。最终非作者需审查完整 diff 与实际短测：

- 无逐客户/工厂/合同经营网络的 simple 真实初始化及跨月推进；营收/固定费用不同增速、变动费两种规则互斥、亏损、零基数及复业、非法比例和金额溢出。
- 同源账簿的收入、费用、所得税、账面现金、资产/负债/权益及报表勾稽；费用不重复，不编造实际客户收付款。
- mode 严格 round-trip，未知 tag、缺字段与状态不符拒绝；Simulation 未实现拒绝；月中恢复不重抽月份/RNG，不重复已执行公司行为。
- 年/半年/季度/月累计窗口正确；平均权益反映分红/增资/回购时点；内部生成和未来事实不可公开，公开但 NPC 未获知不可读。
- 无 SyntheticFunding/补款周期/额度/申请及虚拟资本投入；simple 账面变动说明不冒称真实资金链，query/load/retry 不重复实际公司行为；simulation 不采用 simple 账面简化。
- 分红/认购/回购等共同执行结果真实改变现金和股数，月末不覆盖；状态不足如实业务拒绝，不伪成交、不向认购者补钱。
- 任一系统错误使公司、结算对方、公开库、业务事件、随机及保存 candidate 回滚；投资者资金合法不足不是技术故障或静默补钱；simulation 才要求实际公司现金来源链。
- 三宿主公共结构/金额单位一致，UI/NPC 按相同报告契约消费，无另一套 partial simple DTO 或旧格式兼容。

## 四份设计文档独立复核

完整阅读最新蓝图 666 行、ADR-0035 33 行、ADR-0024 64 行与 company-actions-design 92 行。记录与用户本次真实回答核对，不以旧方案或工具搜索代替全文阅读。两份 ADR 的核心决定符合最新回答：simple 按账面结算百分比更新，不追踪真实公司资金；SyntheticFunding 明确取消，不留作待答；共同股本功能保留，投资者侧不任意覆盖、不补认购资金、不伪成交。

此前四处发现已由 root 修正，并逐处复核关闭：

1. 蓝图第二章第 5 节仍写“公司允许生成资金不意味着给认购者补钱”，与第 4 节取消生成机制冲突；改为“公司账面展示不意味着给认购者补钱”。
2. company-actions-design 第 1 节“公司经营与商业债务收付要求完整复式记账…照常实现”未区分 simulation，可能把真实经营网络又强制加入 simple；限定实际仿真经营，simple 只汇总账面，股东实际账户操作保持共同结算。
3. 同文件第 2.3 节旧“二级市场撮合不需要登记子账、登记子账只服务股本变动”不正确覆盖分红登记日持有人与红利税批次；应说明普通成交不改变总股本，但股东登记/持有期事实仍须维护。
4. 同文件第 4 节“重试不重复生成公司现金”易保留已否定机制暗示；改为重试不重复执行实际支付/收款/发股，明确无公司补款。

修正后的 ADR-0035 和 company-actions-design 已记录用户追加确认：Simple 报表现金仅展示，不作真实付款预算；分红满足可分配利润及方案等条件时不以展示现金不足拒绝。投资者实际到账仍唯一且原子；配股、增发检查本人现金，回购经真实委托及成交；Simulation 不豁免实际公司现金预算。本审查不决定默认经济参数或资金映射，也不将用户游戏简化误称现实 A 股融资规则。

ADR-0024 的后续修订已明确不要求资金循环、不保证成交、不直接给已有账户补钱与新公司行为许可并不矛盾，投资者池不再被错误约束为跨全部模式必然单调下降。blueprint 原“公司允许生成资金”句已改为“公司账面展示”，普通成交登记 holder/tax lot 与不改变总股本相互一致，重试文字不再保留补款暗示。

**四文件设计文档复核通过**，允许该文档范围提交；这只证明设计与用户回答对齐，不证明任何公司系统代码已经完成、通过单测或完整回归。蓝图中概括的“同等状态/适用条件相同”须结合 ADR-0035 的明确公司现金边界解释，不能把同数值的展示现金当成 Simulation 的真实预算；已建议作者将该限定同步到蓝图对应原章节，作为消歧而非新经济决策。
