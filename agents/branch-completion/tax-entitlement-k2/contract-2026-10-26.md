# TAX-K2：Bonus 原R权益、所得激活与来源接缝合同

日期：2026-10-26。状态：待未实施 Sol 独审的最小实施合同；没有业务实现或测试运行。
K1基座为 `b0e53af2b511e1b08a1726e8f7d9f82237a64dd4`，已限定批准并由唯一writer精确移植main。
本稿落实已审个人税账v3中允许的条件K2，不改变它的真实来源/日期/生产能力门。

## 1. 这片要消除的错误

原长期100股R登记、10送10、面值100分，实际收到100股红股。所得10000分属于本次R原权益。
旧 `StockBonusTaxBasis` 绑定新lot，待新lot出售时以其短期取得日收20%是错误方向。
本片要让本次所得使用原R100股与原持期，激活前已处置仍保留并在激活后补评一次；
新lot只在后来另一R形成自己的新所得原权益。

本片继续不调用旧 `record_stock_bonus_basis`，也不修改旧生产评税/`collect_due`。
不撤 `UnsupportedPersonalStockBonus`，不改SaveSlot/Web，不给未来税务日作默认日期。
K2纯域通过与后续真实受控生产接线通过分别验收，不能以新增helper宣称生产税bug闭合。

## 2. 现有真实来源有什么、缺什么

已实读K1税账、`stock_distribution.rs`、`share_registry.rs`，以及已审R2
`session/corporate_actions/distributions_day_end.rs::prepare_stock_distributions`。

| 现有权威 | 可直接复用的事实 | 不能从它推导的事实 |
| --- | --- | --- |
| `StockDistributionBook.plan()/registration()/receipt()` | event、issuer、stock、BonusShares种类、方案比例、R日期、物理R holdings/settled_receipts、户级original/whole/fractional数量 | 真实税务日终、物理R到tax原权益中间capture归属 |
| `StockDistributionBook.status()/credited_on()` | 状态已标Credited和物理到账日；validate重放冻结分配 | 独立证明账户/registry已真实安装；该日就是税务入账日 |
| `StockDistributionReceipt.holders` | 明确账户户级新股整数、原股数量、原物理lots | tax lots与物理lots永久一一同构；`SourceLotAttributionPending`已经闭合 |
| `CashDividendTaxBook`完整操作序重放 | 每个已存在frontier的tax lots、真实条件税务净处置、现金已收及collection事实 | 所有CorporateAction都是拆股或独立新增；正向默认分类仍被K1 F1禁止 |
| R2全局candidate中的registry请求/账户candidate/公司声明 | 未来可联合证明同一个发股事实、面值/数量/方案与行政安装 | 目前个人Bonus门前没有已安装的个人发股/税账事实，不能拿候选冒真实激活 |

来源依据延续已审v3及其官方manifest：089号股票红利按票面收入额，85/101号原权益持期与三档，
中国结算2012通知的同一真实税务日净额原则。尚未获得送股具体进入R或ex税务期末的原件，
所以这里的日期必须由明确条件事实输入，不从R+1上市推定。

## 3. 最小共同域，不再建第二套持仓账

K1书名和旧serialized字段保持。本片新增一个**条件输入对象**与只读评估入口，不给生产SaveSlot加字段。
它携带Bonus登记/激活事实，引用旧book实际操作frontier；持仓和处置仍由同一个book重放，
carrier、原R快照、评税数字都派生。不得把完整book clone、独立当前lots或累计assessed存成第二权威。

概念接口（最终Rust名可在TDD最小化）：

- `ConditionalBonusTaxFacts { registrations, realizations }`：调用入口明确为条件kernel，
  不是生产caller可凭任意字符串取得trusted来源的协议。
- `BonusRegistration { event_id, registration_frontier, shares_per_existing_share_micros, par_value_per_share }`。
  `registration_frontier`为输入book已有操作完成后的prefix，0表示opened_on/opening_lots；
  day和完整R tax lots由该prefix重放派生，避免额外同值日期/lots可独立篡改。
  本片只接受**完整、无中间capture歧义的R tax lots**；physical R归属生产者尚未闭合时不能上生产。
- `ConditionalBonusRealization { event_id, acquisition_operation_seq }`：指向同一book真实条件日事实的
  CorporateAction正向取得，source.event必须等于该Bonus event，且在登记prefix之后。
  实际数量/date/stock/account从该日receipt/本book取得，不开放任意gross金额或激活日期。
- 新入口 `assessment_with_conditional_bonus(lineage, bonus_facts)` 使用同一个transport/evaluator，
  K1 `assessment_with_unit_lineage` 等同传空Bonus事实，兼容已审K1条件行为。

登记所得key始终为当前book scope内 `(TaxIncomeKind::StockBonus,event_id)`，现金仍为
`(CashDividend,event_id)`；同字符串跨kind可同时存在，不能靠前缀转换。
同kind同id的重复完全同事实登记/激活只计算一次；异frontier/比例/面值/来源操作明确冲突。
realization不可被两个Bonus event使用；已给transition的同一正向操作不能再声称是独立Bonus新取得。
旧 `stock_bonus_bases` 与本候选并用继续明确拒绝，禁止从旧新lot税基猜原R。

### 3.1 此片允许的无碎股激活

R原权益总Q，比例r（micros/1000000），必须精确满足 `Q*r` 为正整数且等于实际取得新股数。
所得gross=该实际新股数×冻结面值；每原R单位所得=ratio×面值，以exact rational表示。
仅登记不评税；未找到实际条件取得回执、数量不符、同event异来源或金额溢出都拒绝。
本片只做一次完整发股，第二个不同取得回执的分次发股明确拒绝，不能装成已支持。
户级碎股使实际新股数不等于方案精确乘积时返回带event/原Q/ratio/actual的具体不支持，
这是仍待官方所得分配证据的边界，不把所有普通无碎股个人Bonus无限期挡掉。

### 3.2 与K1 F1的兼容

严格验证的Bonus realization提供本候选内的**显式独立新取得分类**：其新lot不承载本次已有R所得。
所有未由此明确绑定的CorporateAction正向仍走K1 MissingTransition拒绝；没有默认独立新增。
这仅证明条件事实内部一致，不证明它来自真实已安装发股。未来受控来源adapter须按第5节
从真实domain/行政candidate生成该事实，并拒绝另一份仅数量守恒但不符来源的声明。
资本公积转增/配股等独立取得不在这里冒充Bonus分类；其明确来源分类由各自后续adapter完成。

## 4. 共同评税与收缴分片

### K2a：原权益登记、实际所得激活、typed身份

在登记prefix注入与Cash相同的派生carrier，消费仍由K1当前区间求交/机械反投影完成。
Bonus实际激活后，对激活之前或之后的本次原权益消费均按其**处置日**与原R持期评估；
不得改按activation日，也不等新lot出售。
把K1共同现金循环中的“给定原R lots+实际所得realization+处置份额→事件累计half-up到分”
抽为一个共同私有evaluator，Cash/Bonus都调用。旧Cash输入、累加顺序与已审K1结果保持。
限售继续遵守现有类/原解禁日；本片首先以PublicMarket无碎股fixture验收，既有mixed restricted拒绝不放宽。

### K2b：候选部分收缴和重放，不能把prepare当真实扣款

共同assessment要可按指定book frontier计算，不仅最终tail；用于激活/处置/收缴的历史重放。
已有book.collection是真实旧Cash收缴，照实扣减且不改其历史outstanding快照。
新增Bonus欠税的候选收缴使用纯 `prepare_collection(available_cash)` 计算collected/remaining_cash/
outstanding/needs_funds；它没有账户副作用，不自行形成“已实收”。

要继续重放已收Bonus税，必须有显式条件收缴事实：`ConditionalTaxCollection { event_id,
through_frontier, available_cash, collected }`。frontier表示评税前缀，输入顺序表示该前缀之后的收缴次序；
同frontier按显式数组顺序，不靠event字符串。每个fact必须逐步验证collected恰为
`min(该前缀累计税额-此前真实/条件已收, available_cash)`，还须非负且Money不溢出。
同event同事实重试只计一次，异frontier/available/collected冲突；禁止同真实book collection事件重复入条件列表。
恢复时重放同样evaluator/扣收，不信保存的assessed/outstanding数字；只保留输入事实。
该列表是条件输入的收缴来源，不另建任意可改累计税额；进入生产时必须由D1a/Admin实际结果生成，
不能把caller提供的available_cash冒真实余额，不能合成钱缴税。

K2a先红绿冻结独审，再接K2b；两者都在本次有效尾项继续实施，不把K2b改成长期遗留。
若reviewer认定上述数组次序不足以为未来持久化服务，本片仍可作为纯条件事实，但必须指出
缺失的真实联合operation_seq接缝；禁止提前把它输出为生产schema。

## 5. 真实来源adapter的明确后续接缝

R2当前在 `prepare_stock_distributions` 得到plan/receipt/credit_lots后、账户/registry安装前返回
`UnsupportedPersonalStockBonus`。本片不在这行前制造已激活所得。
后续R4须在同一全局candidate中：

1. 取得已validate的StockDistributionBook/RegistrationSnapshot及Simple声明的冻结面值/种类/总数，
   将同账户 `HolderDistribution.original_shares/whole_shares` 与已核R TaxRegistrationBasis绑定。
2. 从REG-P受控完整税务日和capture归属生产者取得registration_frontier/tax lots来源；
   如果physical R资格与税务view需要中间归属，先完成那份确定映射，不默认用tail全部lots。
3. 按真正已核的税务入账日生成完整TaxDayBoundaryFacts；物理credit_on只作物理来源，
   不作为税务日期自动赋值。此时才能确定哪个tax acquisition operation匹配本次发股。
4. 公司domain、registry实际receipt、真实账户候选新股都成功且相互勾稽后，产生同一候选内的
   realized Bonus所得和待收税。任一失败丢弃所有候选，Observer零提前发布。
5. 使用D1a账户/Admin候选实际扣款结果生成收缴事实，禁止把prepare返回值当已安装；
   K4将原R事实、单位映射、所得激活、联合operation序与收缴事实同批接engine/Web严格恢复。

生产前仍须：原basis/capture来源、真实税务日、当前lot未来税龄、碎股所得/退休终结必要规则，
以及上述真实事务/SaveSlot/Web重放闭环。没有这些，个人Bonus门保持；不是删除任务或永久Unsupported。

## 7. 实施与资源

唯一税账writer仍为本树；白名单继续cash_dividend_tax.rs/entitlement_units.rs及子tests，必要时新增同目录私有bonus模块。
只在agents本主题写记录。K2条件类型不生成Web TS、不改SaveSlot；正式持久化/真实事务属于明确后续批。
轻harness继续真实本树module+现有rlib，不仿写业务，不Cargo/不抢main必要构建。
每次源码→真实build→binary→run前后SHA绑定，单case/整命令10秒、8threads，必要构建300000ms/codegen32及进程树采样。
预计binary仍约26MiB、单轻link<1GiB预算；超预算先报负结果/调度，不启动冷engine target。
本设计须由原未实施Sol回答AGENTS三问并裁定最小事实/顺序/收缴接缝后，才实施。
