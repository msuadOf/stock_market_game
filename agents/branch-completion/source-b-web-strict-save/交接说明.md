## 实现与真实测试

新入口消费 108 个可达结构规则（112 个 Rust 类型原始 inventory 不是 112 个新增 parser）。声明表只描述 wire；专用 books、closing、finance、setup codec 复用既有实现。RAW tokenizer 是唯一 raw JSON 边界，先拒绝重复键及转义后同键，再将原始数值 token 交给具体 codec；最后 materialize 检查所有数值已被消费。required nullable、未知字段、sparse array 和原型键均有窄测试。

起始真实完整存档 9 个测试在旧 parser 上为 0/9 失败，原件见 `red-v1/`。随后保留了真实非空报告、四种 Approved Book、非空 Legacy 集团等暴露的原始失败。独立复核发现的 ExactDividendTaxAmount 非零分母及约分、AccountingAmount i128 分值域、SimpleFinanceState.last_month、Bank income_tax_policy 位宽及 IncomeTaxPosition 年度/重述期间，均先记录 Missing expected exception 红，再窄修 codec。各 `*-red-*.stdout` 为原始记录；fraction-red-v1 是测试错误地期待空 registry 含分数的 fixture 失败，真正生产漏洞红为 fraction-red-v2，不能混称。

最终 `current-verification-v8/` 含全部 36 个 save 测试文件，共 261/261 通过：9 个并发 Node 命令，每命令 4 个 case worker，case timeout 与外部进程树 deadline 均为 10000ms。app TypeScript 按原 strict config 的全部 757 根文件加全部 ambient 精确四分片，覆盖证明沿用 `current-verification-v3/coverage.json`。v8 TypeScript/lint 因 period unused import 真实失败；移除该 import 后 `current-verification-v9/` 四片 TypeScript 全通过，最长约 7.45 秒；save 目录与 generated SaveSlot lint 通过。未屏蔽 lint 规则，也未放宽 deadline。v4 runner 未设置 captureOutput，失败 stdout 原始工具输出仍保留，定位时另用 v5 捕获；不能把 v4 空日志冒称完整结果。

旧测试仅同步新 company_state tag、required catalog、Bank 新 required 字段和更精确错误路径；保留既有失败断言，不增加生产兼容。测试 projection 仍明确为 projection，不能作为 Rust producer 见证。

## 诚实边界

本片证明新结构、primitive/custom-serde codec 与上述真实八份完整 wire 的恢复闭环；不声称复刻 Rust 所有跨字段业务 restore 或所有既有复用 codec 与 Rust Deserialize 全域等价。独立 reviewer 记录的既有复用限制包括：Journal.parseAmount 仍为灵活格式 regex、未完整限制 i128；Journal.date/旧 instant 未限 1900..2199；旧报告 ReportVersion sequence/supersedes、chart_version 未限 u32；Seeded/Scheduled fiscal_year、offset_days 未完整限制 i32/u8；旧 value.period 其他调用未统一限制年份。本片新增的精确税额、SimpleFinanceState、Bank 税务位宽及 IncomeTaxPosition 漏洞已修，以上未改层限制仍须在后续独立范围处理。
