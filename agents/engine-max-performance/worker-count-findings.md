# worker 数正式配对：锚定交错配对门控试点（未过门槛，暂不落地）

## 背景与依据

探索波 parallel-scaling 诊断（产物 `.tmp/perf-expl/parallel-scaling/`）：worker 扩展曲线倒 U、峰在 4 worker（诊断口径 4w 293x vs 16w 213x）；机制为 16 worker 多烧 ~4 核在 futex/sched_yield、worker 仅 ~5% 样本在做引擎工作。worker 数选择不属于已否决项（否决的是 Rayon spin/sleep 自旋参数）。本轮以锚定交错配对门控做正式判定。

## 前置修复与归档

- `default-setup.json` 此前被 `.gitignore` 的 `/agents/**/*.json` 规则忽略、从未入库（外部 agent 无法复现主线负载的根因）。已加白名单例外并提交 **fcc97177**（chore(test): 收录基准默认负载配置）。
- 冻结 anchor 归档：`.tmp/perf-anchors/d918bc2c-30ce134d/`（binary SHA 30ce134d…、setup SHA 58b5b191…、README 注明跨会话必须复制归档复用、不能重编——release binary 字节复现依赖构建路径）。

## 协议：锚定交错配对

同 binary 双臂只改 RAYON_NUM_THREADS（probe 经 argv→env 传入）：序列 A_start(16), H₁(16), C₁(4), H₂, C₂, H₃, C₃, H₄, C₄, A_end(16)，共 10 跑；每跑前记录协变量（load5、本核段 0-15 与 SMT 兄弟段 64-79 与并行 agent 段 16-47 的 busy%、温度）。五重判定：anchor 漂移 ≤1%；4 对 dᵢ=Cᵢ/Hᵢ 全部>1；mean(d)≥1.02；mean(d)−1≥2·sd(d)/√4；两臂区间分离。anchor 超限弃会话重试一次。判定只基于同会话交错配对，禁止跨会话比较原始 speed_x。

## 会话一（2026-10-06 晚，e6-aip-*）

| run | 臂 | speed_x | run | 臂 | speed_x |
|---|---|---:|---|---|---:|
| astart | 16 | 229.194 | h3 | 16 | 231.753 |
| h1 | 16 | 241.529 | c3 | 4 | 250.321 |
| c1 | 4 | 250.760 | h4 | 16 | 223.005 |
| h2 | 16 | 232.153 | c4 | 4 | 248.255 |
| c2 | 4 | 249.155 | aend | 16 | 232.671 |

dᵢ = 1.03822 / 1.07324 / 1.08012 / 1.11323；mean(d)=1.0762；H 臂区间 [223.0, 241.5] 与 C 臂 [248.3, 250.8] 完全分离——配对四条全过，但 **anchor 漂移 +1.52% > 1%，弃会话**。协变量显示会话期间环境 load5 从 7.4 升至 11.4（并行 agent 段 16-47 busy 最高 17%），慢漂方向与 anchor 差一致。

## 会话二（紧接重试，e6-r2-*）

| run | 臂 | speed_x | run | 臂 | speed_x |
|---|---|---|---|---|---:|
| astart | 16 | 229.931 | h3 | 16 | 217.311 |
| h1 | 16 | 236.649 | c3 | 4 | 243.373 |
| c1 | 4 | 238.819 | h4 | 16 | 238.072 |
| h2 | 16 | 237.420 | c4 | 4 | 247.670 |
| c2 | 4 | 236.316 | aend | 16 | 229.991 |

anchor 漂移 +0.03%（过）；dᵢ = 1.00917 / **0.99535** / 1.11993 / 1.04032——d₂<1、两臂区间重叠（h4 238.07 > c2 236.32）、mean(d)−1=0.041 < 2·sd/√4=0.056，**配对三条未过 → 判定不通过**。

干扰证据（协变量逐跑记录，`.tmp/e6/covariates*.jsonl`）：c2 与 h3 恰逢并行 agent 在 16-47 核的负载高峰（busy 40.5% / 28.3%，其余 run ≤10%）及温度尖峰（Tccd1 62°C）；h3 无中途停顿（逐秒 CPU 剖面无低载秒），为持续性争用/热干扰，非自身异常。load5 会话内 11.2→12.8 持续上升。

## 资源利用对照（会话二 -cpu.json 均值）

H16 平均 **5.85 核**、C4 平均 **2.35 核**——C 臂以 40% 的 CPU 消耗取得更高吞吐（两会话合并口径：8 个 C run 均值 245.6x vs 8 个 H run 均值 232.2x，+5.7%；全部 C run 高于 H 臂全会话均值）。方向与探索波诊断一致，但按协议**不构成正式胜出**。

## 结论

1. **worker=4 暂不落地**：两次会话均未通过五重判定（会话一 anchor 失败、会话二配对失败），失败模式均为外部干扰（并行 agent 负载 + 环境负载上行）而非效果反向。生产配置保持 Rayon16 不变。
2. 门控协议本身工作良好：两次会话各有一条旧式"两组均值比较"会误判的信号被正确拦下（会话一的 +7.6% 会被 anchor 拦、会话二的 d₂ 反转会被全对同号要求拦）。
3. **建议在独占窗口重测**：并行 agent（16-47 核）空闲、load5 平稳时重跑一次完整序列；协议修正建议：(a) 准入带增加并行 agent 段与兄弟段 busy% 硬阈值（如 <10% 才开跑）；(b) 配对数 4→6 以上以压 SE；(c) 预先登记的样本剔除规则（仅协变量违约的 run 可剔除并留证），避免事后挑样本。
