## 现金分红的一条可执行结算链

1. 输入必须是显式的公司决议/政策事件（公司、证券、每股税前金额或核定总额、公告日、权益登记日、除息日、支付日、唯一事件身份、市场/币种/精度）；验证日期顺序、金额非负/正值约束、持有人股份合计和股东会决议事实。法定“六个月内”只约束期限，不能生成支付日期。按当前代码契约运行，不将法律规则或政策快照冻结到存档代际，也不增加版本迁移。
2. 登记日按真实登记账冻结受益人和数量，产生不可变 entitlement。买入日登记的股份依据真实登记时点判断；登记日后卖出不转移既有 entitlement，登记日后的新买入不取得旧权利。账户撮合成交的日终净股数与登记快照必须一致，不能仅依赖当前 Position 查询历史资格。
3. 公司宣告与付款分离：宣告时借记权益/未分配利润、贷记应付股利；登记产生应付个人/机构/外部股东的明细；支付时从公司实际银行/现金账贷记资金并冲减应付。资金不足则拒绝/部分支付必须按明确政策做原子结算与可见状态，不得透支或自动补款。公司对自持股份不生成 payable。
4. 对适用的个人持有人建立以证券账户为单位的 FIFO `TaxLot`：每次真实取得/转出记日终净增减；每笔登记股息关联到对应取得批次，登记尚未最终结算的股息税务事实。101号规定持股一年以内派息时暂不扣缴，不是派息时先扣后退；卖出时再按适用档次核算最终税额、扣除已结清额并从个人账户收取税款。资金不足时明确欠缴/待缴与通知事实，不能造现金；可否继续卖出、阻止后续交易等不在这些来源已核实，不能擅自定成法定义务。
5. 除息仅用税前每股现金额与市场规则更新除权参考价及后续涨跌幅锚。它不等同支付，不修改历史成交，不把税后现金净额用于定价，不产生伪造成交。沪深市场日历输入必须来自已决定的 `ExchangeCalendar`，休市后的“次一交易日”不得按自然日加一。
6. 全链路应有事件幂等键、提交前验证/提交后原子性、公司现金/应付/权益/外部收款守恒、证券股份不变、个人税款待缴余额守恒，以及完整 SaveSlot 恢复验证。存档只保存继续运行所需最少事实；不新增隐式兼容迁移。

## 当前引擎事实缺口

- `Account` 只有现金与 `BTreeMap<StockCode, Position>`；`Position` 是 `qty`、`t1_locked`、成交额汇总，没有取得日期、取得来源、限售属性或逐批 shares。按现有 Position 不能执行85号所需账户日终净增减 FIFO，也不能区分同一持仓中可流通、限售、送转来源等不同批次。
- 新局 `seed_float` 仅将 `StockSpec.float_shares` 分给 NPC；`InitialAllocation` 只提供 NPC 分类/人数/未分配盘汇总，不分配玩家。`StockSpec.total_shares` 是发行总股本且可大于 `float_shares`。差额股东名册、账户外部受益人、自持库存股均没有权威逐持有人记录。把差额默认为公司自持或直接从派息总额扣除而不给收款人，都会改变股份/现金守恒。
- `AccountKind`（Retail/Inst/Hot/Player）是策略/玩家类型，不是法定税务身份。账户目前没有自然人/居民企业/证券投资基金/非居民等 tax profile；NPC 风格不得用于推导纳税人身份。
- 公司端是独立会计 `Books`，1001/1002 是公司现金科目；投资者 `Account.cash` 与公司账套隔离。没有股东现金到账/公司付款的跨域凭证，不能直接用改 Account 余额绕开公司应付、流水、幂等和恢复。
- 初始 NPC 持仓由初始化 `grant_position` 给出，未绑定取得日。把所有初始股一律当作“已持有超过一年”会直接影响首次股息个人税；按开局日期生成 lot 也是游戏事实，必须由当前 seed/setup 显式给出，而不能假称真实取得日期或额外冻结成存档版本契约。
- `CompanySpec.issued_shares == StockSpec.total_shares` 校验总量，不等于持有人名册完整。公司拥有的本公司股份不可分红（《公司法》第210条），但当前账本没有此股份持有人记录。非流通股或未模拟股东亦可能依法领款，需有明确外部受益人/清算端点。

## 仍须显式提供的游戏经济参数/事实

这些不是“是否实现”问题，功能已获授权；它们是在确定性模拟中必须给出的事实源，不能让实施者自行编造法律依据：

- 每家发行人实际是否作出分红决议、可分配额、税前每股金额/精确比例、利润与现金约束、公告/登记/除息/支付日期。真实法源规定公司决策和时间边界，不提供虚构公司个体参数。来源应为显式公司政策/公司决议事件，输入范围未给定前不得自动按利润比例派息。政策事实不要求跨更新冻结，也不新增存档版本/迁移；官方规则版本/施行日期仍须记录为研究和实现依据。
- 开局完整股东名册：`total_shares` 怎样分配给 NPC、玩家、非交易外部股东、公司自持及其他明确类别；应精确股数守恒。现有 `float_shares` 是模拟流通盘，不是全体股东分配证明。
- 各持有 lot 的取得自然日、取得来源、证券账户、限售类别及解禁日。初始 lot 日期需明确采用哪一虚拟事实，不得统一默认为前一年或开局日后再声称真实 A 股税期。
- 每个持有人明确税务身份与范围：玩家自然人、NPC自然人/居民企业/证券投资基金/非居民等按游戏需要设 profile。策略类型不是法律身份；未取证身份必须明确不支持/拒绝计算。
- 小于一分的每股现金金额表达、公司总额与每户金额如何分配分以下尾数/余款。A 股实际登记结算尾差算法中国结算业务指南本轮不可达，不能自己选择“最后一户拿余数”冒充真实规则。即使有理数核心可实现，也必须在注册结算层保留待处理/拒绝状态。
- 递延个人税在卖出时个人账户现金不足的行为。本轮证据表明资金不足需补足，但未核实游戏应如何后续追缴及其与撮合交易权限关系；必须显式设计而不可凭空记账。

## 未纳入本轮可直接实现的边界

- 中国结算沪深发行人业务指南在本轮请求均重定向维护页，未读到正文：逐户分钱/股、碎股和尾差排序、实际派息到账/预划、配股缴款及失败退款登记操作、回购专户与注销步骤、送转股份原限售继承均不得声称已证实。
- 国税函〔1998〕289号原文及现行效力清理未取得；广东税务局粤地税函〔2005〕345号仅有限责任公司事实及其对289号的转引。资本公积不同来源的上市股份公司个人税务结论不得补齐推断。
- 送股、资本公积转增、配股、增发、回购分别需要对应现行法规和交易所/中登登记原文、业务状态机、整数股份及限售处理；现金除息公式不可复用为它们的全部规则。清算分配仍未获本任务自动扩展。

## 独立复核要求

本计划的证券股东结算语义需非作者复核：所列现金个人股息规则是否只作用于适用自然人及基金特殊边界；沪深除息公式是否限定为现金项；是否将公司持股与全部发行股分配完整；代码模块建议是否仍忠实于 Session/Company/Account 边界；哪些未核实事项仍被清楚列出。实施阶段再对完整产品 diff 另行复核，不能由本文件审查替代。
