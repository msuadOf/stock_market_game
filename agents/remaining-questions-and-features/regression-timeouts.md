# 公司场景普通测试超时修复

本轮处理 `company_operations` 的两整年虚拟经营前史，以及 `company_scenarios`
的诊断只读、闭市自然日和存档恢复检查。普通 case 保持独立进程、一个 harness
thread、一个 Rayon thread 与进程外 10000ms 硬期限，不增加 ignored 项。

## 失败证据与原因

密封基线的 64 case 并发收集将四项记录为超时。使用同一 inventory 的二进制、
保持 `RAYON_NUM_THREADS=1`，将四项独立进程并行复跑：两整年前史在 8.51 秒
通过，诊断只读在 8.07 秒通过，闭市自然日与恢复一致性仍被 10000ms supervisor
终止。这不是业务断言失败，但前两项的余量也不足以承受全量回归压力。

原公司场景每次初始化五个发行人完整前史，诊断双会话生成约 9.7MB 存档；
闭市检查额外恢复两份完整存档，恢复检查还推进三份完整交易日。重复公司数量
与这些用例分别验证的行为无关，不应借分钟级时限保留重复准备工作。

## 代表性 fixture 的范围

三项公司场景改用单发行人 fixture，但保留全部 NPC 类别及原数量、六 tick、
开盘集合竞价与撤单窗口、连续交易、收盘集合竞价、T+1 和原股份分配配置。
新增纯结构测试固定这些边界。五发行人覆盖的原 fixture 与原结构测试均保留，
其他跨发行人或策略特定用例不变。事件、存档、未读信念及闭市零 tick 的原断言
完整保留，不改生产代码、不注入虚构成交。

两整年前史不能缩成短日期区间：仍真实逐日推进 2028—2029 年并生成两次以
比较同 seed 的账套与调度队列，保留工商与保险两行业及全部原断言。保险每天
生成的保单组数从 2 缩到 1，降低累积合同数量；没有缩短历史或绕过真实经营。

## 验证状态

root 以默认 feature、32 Cargo jobs 共享构建实际得到
`company_operations-4a14711434dbcaa4` 与 `company_scenarios-2f0d8d239d972fdb`。
五项相关短测全部通过；四个实际场景分别在 Rayon threads 为 4、1 的条件下，
以最多四个独立进程并行执行，每个命令保留进程外 10000ms 门禁。

| 场景 | Rayon 4 | Rayon 1 |
|---|---:|---:|
| 两整年前史与同 seed 重放 | 4.86 秒 | 4.87 秒 |
| 诊断读取只读 | 1.77 秒 | 1.80 秒 |
| 闭市自然日与未读信念稳定 | 2.56 秒 | 2.53 秒 |
| 日终存档恢复与继续运行一致 | 2.76 秒 | 2.79 秒 |

新增 fixture 结构测试在 0.00 秒通过。诊断用例的权威存档为 2,051,990 bytes，
并仍比较全部事件与存档字节。上述结果是定向短测，不替代完整回归与下述独立复核。

完整搜索确认原 `session()` 与 `fixture_session()` helper 已无调用，也无 feature
条件引用，故删除这两个 helper，保留五发行人 `setup()`、日期 fixture 与全部测试。
