# 2099 年后日历与日期表示

## 当前实现与缺口

`CivilDate` 已严格表达 `1900-01-01` 至 `2199-12-31`，按格里高利历校验，`2100-02-29` 非法。默认 `CalendarPolicy` 的运行区间仍为 `2000-01-01` 至 `2099-12-31`，初始化前史自 `1998-01-01` 起；内嵌香港天文台派生事实覆盖 `1998–2099`。完整政策装配逐年要求农历／节气事实，不能仅把运行上界改大而把缺失年份当作普通交易日。

`CalendarPolicySpec` 已可显式装配含完整 `2100` 事实的政策；适用范围、逐交易所开闭市、虚拟前史查询及序列化恢复并非在所有地方硬编码 `2099`。这不证明默认游戏已能运行到 `2100`，也不证明任何测试合成日期是真实未来假日。

跨层生产遗漏是 Web `candleDate` 把一切 `2100` 日期拒绝，即使其来自合法显式政策。该函数服务日 K 表示和 host／save 行情解析，不承担当前默认政策开局校验。已将其上界对齐现有 `CivilDate` 的 `2199`；保留 `1998` 初始化下界、Unix 秒整数及 UTC 零点要求。`StartDateInput` 与默认政策仍为 `2099`，没有擅自开放无假日资料的开局。

## 仍需确定与实施

资料外假日规则尚未决定，不能宣称总账中的2099年后日历能力完成。可以明确选择只保留周末及固定公历假日的未来模拟简化，并支持显式输入假日；或者采用可信且核验过的天文历法算法推算农历／节气，但仍不能把未来交易所休市安排标为 `Official`。不采用相邻年替代、400年循环映射或缺事实静默开市。

运行上界还需与合同及次年报告排期统一：现有日期类型最多2199，放开2199年度运行会在下一年度报告构造时越界。必须明确末年停止行为及排期失败原子性，不能机械把所有2099数字换成2199。存档/API 当前结构严格校验，不引入新 schema 版本、旧档兼容或默认字段补齐。
