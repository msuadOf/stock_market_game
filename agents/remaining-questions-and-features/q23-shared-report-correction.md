# Q23 四行业共享报表税更正候选

## 契约与职责

`company/report_correction.rs` 将四行业相同的报表更正、年度所得税级联与公开版本追加
编排为只读输入、完整 `CorrectionScratch` 输出。它不负责修改原行业 Owner，也不越过
行业子账保护边界。`IndustryBooks` 必须先检查原始凭证的受保护科目，并在安装前对实际
完整行业候选执行恢复守卫；`CompanyOperations` 和 `GameSession` 再组合真实公司与集团。

工业专属 `correct_and_publish_with_tax` 也委托同一共享候选，不维护第二套更正算法。
专属入口保留受保护科目与真实贷款利息子账拒绝语义，随后在真实 `IndustrialBooks` 克隆
上安装候选并经完整 `Deserialize` 验证，成功后才同时安装账套、结账及公开库。共享错误
按实际阶段映射原工业／披露错误，Owner 恢复失败保留 `Composite` 的真实错误来源。

`Books`、`IncomeTaxPosition`、事件游标、`ClosingEngine`、`PublicLibrary` 的候选要一起
通过才能安装。发生失败时，原输入全部不变，保留更正理由和类型化来源；账务、税务
不变量、结账和披露错误分别为 `CompanyCorrectionError` 的独立类型，不能通过字符串
猜测把不变量错误降级成可恢复业务拒绝。

更正按历史报告期计算经营与税务影响，凭证的真实过账日期及现金日期不回写。年度税差额
按实际所属年度映射有效期间，税务和结账来源映射在候选安装前必须完全一致。历史公开版
不可变；受影响的后续已公开报告增加 `Correction`，尚未公开登记版追加真实序号的
`Original`，不覆写旧版、不冒充已公开更正。

## 领域依据与范围

取得障碍仍保留。本次是公司工程编排共用，不是四行业完整准则合规声明。

## 2026-10-08：后期更正污染前期 ROE 的生产缺陷

`ReportRequest.adjustments` 是整个 Scope 的累积来源 → 有效历史期间映射，非空并不表示
每个历史报告都受影响。原生成器把全局非空值直接传给 ROE，令更正目标之前的报告也变为
`Unavailable(IncompleteEquityEventHistory)`；四表与附注不变，却使 `SimpleFinanceState`
安装候选时重建的完整 `ReportSet` 与原登记版不一致。不能通过减少前史、改选最早月或
放宽恢复守卫来修复此生产缺陷。

本次只把 ROE 的影响判定拆为「存在有效目标期间不晚于报告末期」。目标之前的完整报告
保持原值；窗口之前的调整可能改变期初权益，因此目标及后续报告继续保守标为权益事件
历史不完整，不从汇总表伪造完整事件序列。原全局非空判定仍用于 `Consolidated`／
`ConsolidatedRestated` 的无成员命名空间输入拒绝，不能按本次 ROE 时间范围放宽。
D2 的损益有效期间与现金实际收付期间、税务级联及公开版本不可变／`supersedes` 均未改动。
ROE 一般公式沿用[既有官方核验](../company-system/official-roe-research.md)，CAS 28 完整
取证缺口及游戏简化边界保留，本次不是新增法定计算公式或完整准则合规声明。

本独占副本在生产实现修改前实际取得两项新增行为 RED：真实两月前史更正后月因前月
