# Q23 地产 IncomeTaxOwner

## 语义与实现

地产沿用 Q23 已核验企业所得税年度口径和现有 `IncomeTaxPolicy` 游戏简化，不新增
土地增值税、法定预缴日程、优惠资格、现金退税或资金补充。Fixture 显式采用
2500bp、五年亏损结转；该参数不冒充地产完整税务模型。

`RealEstateBooks` 显式拥有 `income_tax_policy` 和严格 `IncomeTaxPosition`，调用
四行业共享年度级联候选。预售收款属于合同负债，不计入税前利润；实际交付收入与
结转成本进入年度利润。重复计提仅过账差额，零差额不消耗事件身份；真实现金不够
缴税时整账套与税状态保持原值，后续经营回款后才可支付。

地产科目表和列报同时登记 `1811`、`222104`、`6801`，不更改科目表版本。
恢复使用共享年度链与 Books 勾稽守卫，不增加字段默认、旧格式迁移或兼容。

通用原始 Journal 更正必须保护 `1122`、`1541`、`1542`、`2001`、`2203`、
`2231`、`2501` 及三个税务 Owner 科目：这些业务对应项目、预售、借款、尾款或
税评估子账，不能只改总账绕过结构化事实。生产日结与通用原子更正接线由 Q23
外层任务统一完成，不能仅因本 Owner 存在就声称整个 Q23 完成。

## 地产组合 Owner 守卫补缺

非作者复核发现 `validate_owner_state` 初始仅检查税状态。完整核对地产处理器和
`session/persistence.rs` 后，确认 Session 原有地产检查只覆盖借款到期日的日历范围，
没有项目、预售、借款或尾款与当前总账的组合勾稽。新增六项短测试先在统一 host16
产物运行：四项错误状态确实被旧守卫接受，断言真实失败；成熟借款付息／偿清和一致
编辑库存两项正控制通过。各项独立进程并行、外部十秒 deadline、Rayon 八线程，
日志为 `.tmp/checklist-wave4/estate-owner-state-{1..6}-red.log`。

必要修复保留既有经济语义，仅补保存事实内部一致性：项目投入、结存和结转成本
守恒；交付套数和预售标记一致；有效项目／买方／贷款人引用；尾款日期和非负余额；
`1541`、`2203`、`1122`、`2001`、`2501`、`2231` 分别与相应子账勾稽，不能让
长短期借款互相抵销。双链余数按半偶舍入限制为正负半分母以内；到期后仍可计息，
偿清借款与历史零余额开项不删除。行业必需科目的分类、现金及备抵标记须保持明确。

守卫不重建资产历史来源，不要求合法编辑后项目金额能逐笔映射历史购地交易；不新增
持久字段、版本或兼容。项目完工日与开发首日的回拨是既有 API 接受行为，本轮不借
恢复验证改变这一另立领域问题；完工和开放中断同时存在等内部状态矛盾仍拒绝。
实际绿测与独立复核由外层统一构建后补记。
