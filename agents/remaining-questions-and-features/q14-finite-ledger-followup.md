# Q14 有限客户账簿恢复与生产接线

## 范围与前置事实

本批开始时，`customer_finance.rs` 已实现独立客户余额、经营收支端点、原到期日与登记顺序偿付、核销不免责和幂等回收，但只有 `Serialize`。现已补齐独立账簿的严格当前恢复，生产会话和宿主存档仍未接入。本批先以真实登记和付款fixture固定合法恢复及非法事实拒绝，再补恢复算法；不设置未批准的客户开局资金、收入分布、行业参数或研发优先顺序。

恢复只验证继续运行需要的结构与事实一致性，不根据历史收支倒算或证明当前客户现金的历史来源。当前现金可以编辑为另一非负值；不允许负现金、超额债务清偿、无效日期、重复登记序号、错配事件回执或缺失对应真实流水。所有字段必填，不加版本、迁移或兼容默认值。核销、回收及普通付款的余额前缀必须按真实应用顺序检查；同日不能按事件 id 字典序推测。债务登记也应与财务事件共享事实顺序，避免把同日稍后才登记的债务误当作早先付款时已经存在。

## 债权人绑定

旧 `repay_due` 由调用方指定一个收款端点，而债务本身没有债权人；跨公司共享客户时可能把甲公司的债付给乙公司。绑定债权人是已经确认的真实来源／去向要求，不涉及新的经济参数。

债务登记现已显式传入 `creditor`，区分 `Company(CompanyId)` 与具名 `External`，不与 `Customer(CounterpartyId)` 混用；债务付款与核销后回收只取该债务自己的 `creditor`，不能由调用方改写。全客户债务统一按原到期日及登记序消耗同一有限现金，逐项付款结果保留债权人，不保留旧API兼容包装。本模块21项短测与独立复核证据见 `q14-creditor-binding.md`；生产公司现金另一侧仍未接线。

联合来源身份随后已实现：`CompanyClaimIdentity` 把公司、开项或强类型合同义务联合编码，区分贷款本金与每笔真实利息来源，登记和严格恢复都检查来源公司与实际债权人一致；当前本模块29项短测通过。构造和恢复不复制客户现金、不生成收入、不证明实际Owner凭证存在，生产映射依赖仍见 `q14-creditor-binding.md`，不能将编码实现当作客户资金闭环完成。

## 生产接线依赖

1. `CompanyOperations` 持有一个共享客户财务簿，同一客户不能按公司复制余额；它是私有经营事实，只随成功自然日日结保存，不暴露未来收支或私有客户现金给 NPC。
2. 显式场景输入提供客户身份、开局现金与经营收支事件；初始化不能默认无限现金，不能按债务缺口生成收入。
3. 工商销售的真实应收开项与债务身份一一映射，保持原合同日期，不因重试改写到期日。联合公司／来源身份编码已经提供，但生产仍须由真实Owner返回并校验来源，不能从金额、分录位置或某个全市场唯一source假设补猜。
4. 每自然日评估到期及未清偿债务，`repay_due` 实际分配驱动 `collect`，后续补付只清原应收，不再次确认收入。
5. 在同一个私有经营候选内完成客户现金扣减、各债权人 `Books` 现金增加和应收清偿；任一步失败不安装任何一侧。不得把具名 `Company` 端点当成已过账事实。
6. 部分核销及核销后回收需要应收子账逐项残额和已回收事实、正式分录依据及与客户债务同步的原子接口；基础模块本身不冒充正式 ECL 或工业核销分录。
