# Q14 客户有限现金基础模块

## 范围

本批在 `packages/engine/src/company/customer_finance.rs` 提供可独立测试的客户现金、经营现金流和债务事实基础，并由 `company` 模块导出。客户标识复用 `CounterpartyId`，不与证券交易账户混用。

账簿已提供严格当前 `Deserialize` 和继续运行不变量校验，但没有接入 `CompanyOperations`、公司 `Books`、到期调度、会话装配或宿主存档恢复，也没有建立月度上市公司经营模型。后续公司月度业绩仍需沿行业需求、销售、成本/研发、利润和实际收付款的因果链实现；客户回款只清偿原应收，不重复确认收入。现金规模、经营收支分布、重要客户识别等尚未确认参数均未设置默认值或概率。

## 已实现事实

- 每客户有独立现金与债务状态；开局现金和每笔经营收支金额均由调用方显式提供。
- 现金流保留日期、金额、`source`、`destination`；模拟边界外端点必须显式命名。客户现金不足、金额溢出、端点自转账和不完整端点输入均明确拒绝。
- 每笔债务保留开立日、原合同到期日和登记序号。客户到期付款按原到期日、再按登记序号分配，只使用当前可用现金，可部分清偿；残额继续保留原逾期起点。事实日期不允许倒退。
- 每笔债务显式绑定 `DebtCreditor::Company(CompanyId)` 或具名 `External`，不与 `Customer(CounterpartyId)` 混同。付款／核销回收接口不能由调用方传入其他收款人；跨债权人债务共同消耗该客户唯一余额，现金流水与回执保持该债务自己的债权人。
- 付款、核销、回收及现金流事件按唯一事件 id 幂等执行；同 id 不同载荷显式冲突。失败先完成校验，不留下现金、债务、流水或事件记录的部分变更。
- 债务登记与财务事件共享 `next_fact_sequence`，相同日期也保留真实应用先后，不从事件 id 字典序推测；各修改路径的序号容量在安装业务变化前checked校验。
- 账簿恢复拒绝缺字段、未知字段、重复map键、负现金、矛盾债务余额、非法日期和序号、错配回执及流水；按事实顺序检查普通付款优先前缀、核销当次法律余额、先核销后回收和单批付款合计值域。当前非负客户现金允许编辑，不以历史流水倒算或证明其来源；无版本、默认补齐或兼容恢复。
- 核销要求调用方传入非空 `WriteOffEvidence`；模块保存依据，不按账龄或随机结果自动判断核销。核销减少普通账面余额，但不减法律债务；核销回收只减少法律余额和未回收核销余额。逾期状态根据法律余额派生，因此核销后仍保留原逾期日。
- `repay_due` 与核销回收使用不同余额路径，不能重复清偿；客户向模拟内公司支付的另一侧公司现金原子入账留待后续同一转账事实接线。

## 测试

测试位于 `customer_finance::tests`，共21个 case：

1. 客户现金隔离、收支端点明确、余额不足失败原子以及收款方溢出失败原子。
2. 到期日/债务登记序排序、可用现金上限与部分付款、原逾期日保留。
3. 付款相同载荷重试幂等、相同事件 id 不同载荷拒绝。
4. 到期时无现金不付款；相同事件重试不补钱，后续显式经营现金流入和新付款事件才可付款。
5. 财务事件日期回退拒绝且状态不变。
6. 债务开立日期倒序登记拒绝且状态不变；空核销依据拒绝。
7. 部分核销保留法律余额；核销回收和普通应收清偿分路；核销/回收幂等、超额回收拒绝；核销后法律逾期起点仍可查询。
8. 合法账簿严格往返，恢复后相同付款保持幂等。
9. 负现金、超额清偿、错误回执与缺失流水明确拒绝。
10. 缺字段、未知字段、重复键、非法日期和金额溢出拒绝；合法现金编辑允许。
11. 总量自洽但先回收后核销的事实拒绝。
12. 核销当次法律余额回执不准确拒绝。
13. 前债未清仍付后债的错误分配拒绝。
14. 同日事件逆字典序与稍后登记债务按真实事实顺序合法恢复。
15. 五类修改路径的事实序号溢出均在安装前原子拒绝。
16. 同次付款多笔合计超出 `AccountingAmount` 值域拒绝。
17. 共享客户的不同公司债务按原到期与登记序付款，末笔部分付款，不把资金转给同一调用方；恢复后幂等。
18. 核销后回收支付绑定债权人，普通应收余额不重复清偿；恢复后回收幂等。
19. 普通付款流水重定向拒绝，付款命令额外收款人字段明确拒绝。
20. 债权人必填，客户命名空间与空债权人拒绝；相同标识文字的客户与公司仍独立。
21. 核销回收流水重定向及回收命令额外收款人字段明确拒绝。
