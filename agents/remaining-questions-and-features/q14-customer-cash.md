# Q14 客户有限现金基础模块

## 范围

本批在 `packages/engine/src/company/customer_finance.rs` 提供可独立测试的客户现金、经营现金流和债务事实基础，并由 `company` 模块导出。客户标识复用 `CounterpartyId`，不与证券交易账户混用。

本批没有接入 `CompanyOperations`、公司 `Books`、到期调度、会话装配或存档恢复，也没有建立月度上市公司经营模型。后续公司月度业绩仍需沿行业需求、销售、成本/研发、利润和实际收付款的因果链实现；客户回款只清偿原应收，不重复确认收入。现金规模、经营收支分布、重要客户识别等尚未确认参数均未设置默认值或概率。

## 已实现事实

- 每客户有独立现金与债务状态；开局现金和每笔经营收支金额均由调用方显式提供。
- 现金流保留日期、金额、`source`、`destination`；模拟边界外端点必须显式命名。客户现金不足、金额溢出、端点自转账和不完整端点输入均明确拒绝。
- 每笔债务保留开立日、原合同到期日和登记序号。客户到期付款按原到期日、再按登记序号分配，只使用当前可用现金，可部分清偿；残额继续保留原逾期起点。事实日期不允许倒退。
- 付款、核销、回收及现金流事件按唯一事件 id 幂等执行；同 id 不同载荷显式冲突。失败先完成校验，不留下现金、债务、流水或事件记录的部分变更。
- 核销要求调用方传入非空 `WriteOffEvidence`；模块保存依据，不按账龄或随机结果自动判断核销。核销减少普通账面余额，但不减法律债务；核销回收只减少法律余额和未回收核销余额。逾期状态根据法律余额派生，因此核销后仍保留原逾期日。
- `repay_due` 与核销回收使用不同余额路径，不能重复清偿；客户向模拟内公司支付的另一侧公司现金原子入账留待后续同一转账事实接线。

## 测试

测试位于 `customer_finance::tests`，共 7 个 case：

1. 客户现金隔离、收支端点明确、余额不足失败原子以及收款方溢出失败原子。
2. 到期日/债务登记序排序、可用现金上限与部分付款、原逾期日保留。
3. 付款相同载荷重试幂等、相同事件 id 不同载荷拒绝。
4. 到期时无现金不付款；相同事件重试不补钱，后续显式经营现金流入和新付款事件才可付款。
5. 财务事件日期回退拒绝且状态不变。
6. 债务开立日期倒序登记拒绝且状态不变；空核销依据拒绝。
7. 部分核销保留法律余额；核销回收和普通应收清偿分路；核销/回收幂等、超额回收拒绝；核销后法律逾期起点仍可查询。

独立 reviewer 核查后，最终验证使用 `engine-ff3b7be40fde148f` 测试二进制逐 case 执行上述 7 项；每 case 有独立 10 秒进程监督，7 个 case 并发，7/7 通过，各 0.00 秒。单 case 命令形式为：

```text
node scripts/run-with-deadline.mjs 10000 -- target/debug/deps/engine-ff3b7be40fde148f --exact company::customer_finance::tests::<case> --test-threads=1
```
