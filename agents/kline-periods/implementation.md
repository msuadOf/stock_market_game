# K 线周期与 UI 合并校准

## 现行目标

用户明确要求日／周／月／季／年 K，以及120／60／30／15／5／1分钟 K，放入折叠周期表单；
原5／20交易日数量聚合被取消。MA 编辑由独立任务接入共用 `MarketKlinePanel`，
默认 MA5／10／20／30／60，不再恢复旧独立 Mobile K 线绘图 owner。

## 本批实现与验证

- `calendar-candles` 按公历自然周期聚合，精确 `rawPrices` 与全部真实成交额、笔数保留；
  混入虚拟前史的周期不伪造真实 `tradeStats`。自然季／年及真实金额两项曾实际失败，修复后通过。
- `ChartPeriodTabs` 两端共用五日与折叠 `KlinePeriodSelector`，不保留 disabled 更多周期入口。
  选择回调拒绝未知值；信息标签与市场撮合不受显示周期选择影响。
- UI 合并保留 `MarketKlinePanel`、坐标布局、`TradingTimeline`、`FiveLevelBook` 的证券交互，
  恢复个人交割、日终分钟历史入口和 controller 权限边界，不整文件取回旧独立 Mobile 图形。
- `DesktopIntradayChart` 从实际前端／Rust 分时均价结果绘制可选均价线，复用全天时间轴；
  缺少成交事实不补线。新消费者测试先实际失败后通过，不把隐藏旧图表 overlay 当可见实现。
- 聚合、选择器、投影及 Desktop 分时共29个短 case，并发4，case 和整命令均10000ms硬上限，
  实际0.79秒全部通过。不做完整回归。
- 共用季／年 K 消费者补一项真实跨季、跨年日期样本，选择器与共用面板12项短测通过，
  实际1.55秒；断言实际聚合后的数量与自然季度／年度文案，不仅验证选择按钮存在。

## 尚待接线与独立复核

`MinuteKlinePanel` 使用独立真实分钟模块；已日结分页与活动日内查询消费由子任务实现。
`LocalRefreshViews` 传入其数据入口由 UI 合并任务负责。当前记录不冒称分钟 K 全部宿主接线已完成，
最终需对三宿主真实 `queryCurrentMinuteHistory` 与新共用消费者做短测和非作者独立复核。

分钟消费者由未实施该模块的父 agent 全文独立复核；发现并修复了11:30／15:00端点归桶、
午休没有形成中桶、u64／u128累加上界、规范价格与日期输入、重复日期、活动日错配与迟响应、
共享坐标样式的红涨空心／绿跌实心、高位一分涨跌误判以及极小量柱消失。
修复后父 agent 再次全文核对与复跑16项短测，并发4、case及整命令10000ms，实际0.86秒全绿；
共享主图坐标、真实 HH:mm 时间轴与量柱均可见，没有日K反推分钟或竞价指示量冒成交。
模块复核通过不替代当前分钟 Core、生成类型和三宿主真实查询的各自门禁。

独立复核确认自然周期与精确金额处理符合要求，但发现 Desktop 旧 `fiveDay` 独立状态与
共享周期 owner 并存、非“分时”一律送入自然 K 面板，分钟与五日选项会触发显式拒绝。
这项由 `LocalRefreshViews` 合并 owner 修复，非作者再次确认两端按分时、五日、自然周期、
分钟周期分别路由，分钟 consumer 传入活动查询及 tick 刷新，独立五日状态和按钮已移除。
该复核仅关闭共享周期路由发现，不冒称活动分钟 Core 与完整 Host 契约已验收。
Mobile 短测还揭示共用面板须恢复 Q08 的指标源与能力守卫；调用方已传入真实设置，
共用面板的 MA 与来源补齐由独立 MA 任务负责，旧单根蜡烛要求 MA5 部分均值的样本须改为
足量真实日期输入后验证，不以删除“不支持／不回退”断言规避问题。
