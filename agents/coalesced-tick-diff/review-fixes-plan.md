# 累计区间审查修正计划

日期：2026-11-09。基线：`831d1469`，分支 `codex/coalesced-tick-diff`。

本文件只规划后续修改，尚未实施。目标是补齐独立审查指出的行情压缩遗漏，恢复诊断模式的约定，并清理过时的架构说明。沿用已有累计槽和区间交接，不重新设计撮合与持久化。

## 1. 目标与范围

当前实现已合并末版状态投影，但 `DeferredInterval::push` 仍保留每拍完整 `PriceTick`，再复制盘口和 candle 到 `continuous_samples`。本轮要让同一分钟内的可覆盖行情只保留必要末值，同时完整交付成交、委托结果、错误、披露、竞价及日界。

交付内容受业务需求约束；传输可以采用累计区间和专用采样结构；前端仍自行处理状态、条件单和图表。三者语义一致，不要求使用相同的数据结构或执行频率。

本轮包含 engine 的发布协议与区间累积、server/desktop 的必要接入、前端协议及消费者适配、生成类型、对应 ADR/架构说明。撮合算法、账户结算、费用、T+1、NPC、存档格式、数据库、历史查询产品、WASM 调度和 UI 页面设计均不改；不新增订单事务日志、消息中间件、动态订阅或全量 fallback。

## 2. 必须先固定的数据契约

### 2.1 把当前状态、图表采样和行为输入分清

| 数据 | 区间内处理 | 现有消费者依据 |
|---|---|---|
| 当前市场、账户、活动委托 | 保留区间末版，沿用现有 `RuntimeDelta` | 状态应用 |
| 成交、接受/拒绝/撤单、结算错误、公司披露和日期事实 | 保留原事件、身份、seq 和 tick | `effects.ts`、公司协调器及日界 |
| 开盘/收盘竞价事件与采样 | 本轮全部保留 | 竞价采样和阶段边界 |
| 连续图表采样 | 同股同现有分钟槽保留最后一点及该时刻 candle，跨槽保留 | `MarketChartProjection` 最终按 `TradingTimeline.minuteSlot` 覆盖同槽 |
| 条件单价格观察 | 保留原 seq/tick 顺序的最小 `code/seq/tick/last_price` 序列 | `AutoOrderManager.consumePoints` 实际只读 code 和 last_price；seq/tick 用于协议覆盖与顺序校验 |

条件单不能只看分钟末价：一分钟内越过触发价后又回来，原逻辑仍会触发。它不需要每拍盘口、成交量或完整 candle，因此不能以条件单为由保留完整 `PriceTick`。本轮新增一种协议内的最小价格观察载荷，调整前端条件单点类型，禁止伪造缺失盘口或用默认值补字段。保持既有触发次序和提交价，不把条件单迁入 engine。

`continuous_samples` 先复用现有样本类型并按同股/分钟槽替换，不再逐 tick append；不另起图表 DTO 重构。删除原始 `PriceTick` 后，不能再靠 `project_timeseries_parts` 从 `facts` 生成 `continuous_points`：交付时必须按每股保留样本的最后一点重建 `continuous_points`，继续满足现有“样本末点等于 continuous_points”的校验；区间中没有该股连续采样时不补造点。最新盘口仍来自末版市场状态。原始 `PriceTick` 经验证和提取后不再同时存入待交付 `facts`，从根源去掉双份逐拍盘口/candle。

### 2.2 压缩后的 seq 覆盖必须可校验

保留既有 `seq_from/seq_to` 的源事件区间，不重新编号成交或委托。现有 `facts.length == seq_to - seq_from` 只适用于未压缩事实，不能简单删掉断言、允许任意缺口。

计划为压缩区间增加有类型的“已覆盖报价 seq 范围”：只由 producer 从已验证的 `PriceTick` 生成，相邻范围合并。接收端检查保留事实的 seq 与报价范围不重叠、不越界、没有遗漏，合起来精确覆盖原区间；普通无压缩帧继续用现有严格校验。范围标记声明的是被覆盖报价，不得用来掩盖成交、拒单等非报价事实。

最小价格观察与被覆盖的每个报价 seq 一一对应：每个覆盖 seq 恰有一条观察，不得重复、缺失或与保留事实重叠。观察保留原 seq 和原 tick，检查 seq 严格递增、tick 非递减且位于帧 tick 区间内，并验证 stock、价格及覆盖范围的合法性。接收端只能验证 producer 声明的覆盖、观察和保留事实是否自洽，不能从被省略的原载荷独立证明事件确为 `PriceTick`；源事实的类型、身份及内容必须在 producer 压缩前验证。不能把这种声明误报为接收端完成了原始事实验证。

Rust/Web 的解析、校验、canonical retry、生成类型与测试同步；报价范围、每条观察的 code/seq/tick/价格和保留采样都参与 canonical 比较，观察内容或配对变异不能被当作相同重试。同 `(tick,key)` 身份规则保留。公司协调器等自行检查精确事件数量的消费者也必须改用同一覆盖契约，不能只改顶层校验后让下游拒收。

`SessionFactCursor` 不再依赖保留全部报价本体续号。先核对并复用现有逐拍完整事实验证，再使区间登记能以已验证覆盖推进 seq 前沿，尤其覆盖“末拍只有报价”和“没有事件的 tick”；不可把 seq 游标退回最后一个保留的非报价事件。保留必要的 Session 域局部身份续号。

## 3. 实施顺序

1. **先补最小失败 fixture。** 同股同分钟多次报价、一次价格触发后回落、一笔成交；旧实现应在“报价完整载荷/图表样本数量仍逐拍增长”处失败。另用跨分钟边界 fixture 固定现有显示时间轴。
2. **增加严格的压缩覆盖表达。** 先实现 Rust/Web 对保留事实加报价范围的覆盖校验、canonical retry，再接相关下游。完整事实生成与核心提交仍保持原规则；压缩仅发生在已提交数据进入发布累积器之后。
3. **在 `DeferredInterval::push` 提取并合并。** `PriceTick` 拆为有原 seq/tick 的最小价格观察、分钟槽样本和报价覆盖标记；其它事实原样保留。消费只使用末版状态，并由每股样本末点重建 `continuous_points`，跨分钟点和竞价不丢；不先生成逐拍完整 view 再压缩。
4. **接通前端消费者及日界重建。** 条件单消费最小观察序列，图表消费分钟样本，当前状态应用末版 diff；日内历史重建使用相同表达，`CivilUpdate` 仍作为独立边界。读档/换 generation、重试和失败区间不越界。
5. **隔离诊断模式。** `simulation-diagnostics` 保持逐 tick 完整外围投影与诊断，绕过普通累计覆盖；使用诊断专用同步消费边界，避免改成无界 Full 队列。该例外只属于诊断构建，不恢复普通运行的 8 tick 等待，也不改变普通路径已明确的中间 view 语义。
6. **收敛文档和死接口。** 更新 `docs/architecture.md` 与 ADR-0010 的累计区间、覆盖规则、诊断例外；删除 server/desktop 空的 `finish_fixed_batch`、不可达错误分支，以及经引用核对确实无用的旧批次字段/方法。保留真实的 flush、控制命令、日界与失败交付边界，不借清理重排 actor。

## 4. 边界与明确限制

- 分钟槽必须复用当前 `TradingTimeline.minuteSlot` 的整数时间映射；不能直接用另一套 engine 分钟键冒充。用少量默认/自定义窗口边界 fixture 对齐 Rust 与 TypeScript，必要时只增加纯时间换算 helper，不能让 engine 引入 React 或前端模块。
- 日内成交、必要事件和最小条件单观察仍可随实际数据量增长。完成后应宣称“可覆盖行情及完整投影不再逐拍重复保留”，不能宣称所有区间恒定内存或无限快于下游也不增长。现有 `parts`、`pending_runtime` 的轻量逐拍登记暂不重构；若最终测量表明它们成为主要占用，再单列后续优化。
- 日级存档与已有分钟/交割历史的日终保留契约沿用，不把日内盘口或触发观察写入长期存档，不以传输压缩删除正式分钟历史。不得把传输用报价覆盖范围当成持久化交易日志。
- 末版 view 构造失败仍显式停止，失败区间不冒充成功，核心提交不回滚/重跑；先前已成功交付的区间前缀保持。普通中间 view 不构造已是本轮明确边界，不能重新要求逐拍外围检查等价。
- 条件单异步提交失败后的重试时机是现有行为，本轮不进一步压缩价格观察。将它压成价格极值、跨价摘要或仅在有条件单时订阅，需要另行确认，不能在本轮顺带实施。

## 5. 最少验证与完成门禁

遵循 TDD，只新增/调整与此次风险直接相关的短 fixture：

1. 在原有短 fixture 中对比逐拍与压缩后的图表价格、分钟 volume、`cumulativeTurnoverCents` 和 `cumulativeVolumeShares`；覆盖同一分钟分多区间交付和跨分钟。完整报价事实被移除、同区间同分钟样本只剩一个，`continuous_points` 等于每股样本末点；盘口/candle 不再双份逐拍保存。
2. 同时含报价与成交/拒单的区间，报价覆盖和保留事实精确覆盖 seq，最小观察与报价 seq 一一对应；重叠、漏段、越界、重复、观察原 seq/tick 错配和变异重试被拒绝，Rust/Web 规则一致。
3. 中途越过触发价又回落，条件单触发次数、顺序和提交价与原逐点消费一致；无需完整盘口/candle。
4. 复用现有超过 8 tick、区间末版失败和整日日界 fixture，确认两个 native 宿主及次日首拍不回归；诊断专用 fixture 验证中间 Full 的外围错误仍报告。

普通 Node case 和整命令均不超过 10000ms，Rust 普通命令也受外部 10000ms deadline；独立 fixture 并行。类型生成与编译单独归类构建，使用实际多核参数与不超过 300000ms 的外部 deadline。依赖只在本 worktree 内使用，不通过可写共享 `node_modules` 执行安装。

先检查保留载荷数量和内容，再用已有 3000 tick probe 做一次有限交错比较；不新建通用 benchmark、不跑全量回归、长期模拟或浏览器矩阵。负载不稳时只报告测量限制，不追测到出现理想数字。

完成后由未参与实现的 Sol subagent 复核完整 diff：范围、目标完整性、架构、大 A 语义及跨层契约；有效问题修复并复核后才能宣称完成。本文件不是通过记录。
