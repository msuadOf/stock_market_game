## 精确来源生命周期

以下元组按 `(authority_epoch, install_sequence, source_tick, source_generation, day_end_stage, non_tick_revision, mirror_phase)` 排列；所有 phase 为 `Continuous`。

- public restore 初始：原 live 为 `(1,3,2,3,RetainedPublished,0,Continuous)`；新 restore 为 `(0,0,2,0,Tick,0,Continuous)`。
- public 下一真实 tick 3：原 live 为 `(1,5,3,4,Tick,1,Continuous)`；restore 为 `(1,2,3,1,Tick,0,Continuous)`。
- public 下一真实 tick 4：原 live 为 `(1,6,4,6,RetainedPublished,1,Continuous)`；restore 为 `(1,3,4,3,RetainedPublished,0,Continuous)`。
- G8 每个 phase 独立从同一完整档 restore：令 `n=index+1`、`t=phase*TICKS_PER_DAY+n`；native 为 `(1,n+1,t,n+n/TICKS_PER_DAY,末拍 RetainedPublished 否则 Tick,0,Continuous)`，serial 为 `(0,0,t,0,Tick,0,Continuous)`。
- G8 两条 native continuation 均先 restore，再 civil，然后下一日首拍，expected tick 由外层 phase 公式推导；两侧均为 `(1,3,(phase+1)*TICKS_PER_DAY+1,1,Tick,1,Continuous)`。

推导要点：首次 lazy static 接管安装一次而 generation 为 0；每个真实 tick 发布一次，末拍 retained 再发布一次，但整拍只安装一次。civil INFO 的 `through_changed` 使私有 install_sequence 与 World non_tick_revision 各增一；它不改可见 origin，下一市场拍才把新来源一并安装。public 的新 restore 已在次日，首拍前没有这次 civil；G8 continuation 则在 restore 后完成 civil，故两侧 private 安装计数均多一。
