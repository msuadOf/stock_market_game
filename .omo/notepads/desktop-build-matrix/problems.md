# Problems

## 2026-09-13

- Current Ubuntu host does not package during this task. Dry-run validation intentionally does not install or invoke `cargo-xwin`, Tauri CLI, NSIS, signing credentials, system dependencies, or release builds.
- Code review found that the constrained NSIS preflight advertised the MSVC target and LLVM/lld but initially checked neither; normal mode now requires the installed `x86_64-pc-windows-msvc` target, either `ld.lld` or `lld`, and `llvm-rc` or a versioned `llvm-rc-N` before `cargo tauri build` can start.
- Independent review found the generated constrained prerequisite list omitted the already-enforced LLVM resource compiler; it now names both accepted linker and `llvm-rc` forms. The task scope prohibits changing the previously added desktop README in this correction.
- Final-review remediation: native Windows `.cmd` shims now run through an explicit `ComSpec /d /s /c` argument vector, without a shell-string command; dry-run labels checks as planned rather than performed; the Wasm binary is parsed with `WebAssembly.Module`; and `lld-link` is accepted alongside other LLVM LLD drivers. Tauri documents LLVM/LLD presence, not these executable-name/probing details, so versioned `llvm-rc-N` support is labeled as a distro compatibility extension.
- Final independent review found `.cmd` paths containing spaces required a quoted single `ComSpec` command argument and that external Windows signing via `signCommand` was inaccurately implied to be impossible. The planner now quotes `.cmd` command/argument data without shell interpolation, its tests cover a spaced shim path, and the README distinguishes Tauri's unavailable default signer from a configurable external signer.
- Final Tauri semantic review further clarified that configurable external signing is mandatory for a signed cross-compiled installer, while an unsigned NSIS build can still proceed. Planner and README wording now state that signed distribution requires `bundle.windows.signCommand`.
- Final implementation review found that `corepack --version` did not prove Tauri's configured `corepack pnpm` frontend command was runnable. Normal mode now probes `corepack pnpm --version` directly and test coverage proves a managed-pnpm failure blocks Cargo/Tauri execution.
- Final Tauri semantic review found that accepting generic `lld`/`ld.lld` or versioned `llvm-rc-N` executables could create a false-positive preflight because the documented route invokes `lld-link` and `llvm-rc`. The matrix now requires those exact executable names; no alias is created implicitly.
- Final implementation review reconfirmed that preflight must run the actual `corepack pnpm --version` command rather than only `corepack --version`; this exact managed-pnpm probe is now used on POSIX and through the fixed Windows `ComSpec` vector.
- Final scoped correctness review found that LLVM checks treated a command that exited nonzero as available. Exact `lld-link` and `llvm-rc` probes now require exit status 0, with regression coverage proving either failure blocks `cargo tauri build`.
- Authoritative NSIS command-line documentation lists `/CMDHELP` as the compiler usage command but does not document either `-VERSION` or `/VERSION`. The normal NSIS preflight now uses `/CMDHELP`, and tests prove an alternate version flag does not satisfy the probe.
