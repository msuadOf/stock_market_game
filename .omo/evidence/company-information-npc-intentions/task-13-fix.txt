二、F1 修复设计（重述底稿持久化 + 穿线）
================================================================================

缺陷（复核实证）：closing.rs correct() 构造的重述映射（BusinessEventId→目标期间）
是一次性局部变量；后续 close_month/close_year/snapshot_interim 均以空映射生成
⇒ FY2030 更正 +300 同时进入 2031-01 月报净利与 FY2031 年报净利（重复计入两个
会计年度的已公布利润表，违反 CAS 28 追溯重述）。

修复：
1. ClosingEngine 新增持久字段 restatements: BTreeMap<ScopeId,
   BTreeMap<BusinessEventId, AccountingPeriod>>（Scope → 来源 → 目标期间累积底稿）。
2. correct() 过账成功后把映射累积进该 Scope 的底稿，且本次重述版本直接以
   累积底稿生成（多次更正可叠加，同一 BusinessEventId 由日记账唯一来源守卫
   保证绝不重复）。
3. generate_validated()（封月/年结/快照的公共入口）改为传入该 Scope 的累积底稿
   ⇒ 更正分录的有效期间 = 目标历史期间：损益只进目标期间窗口与后续期间的
   closing 桶（期初留存收益/比较项），绝不进后续期间 movement/quarter/ytd
   （当期利润表）。
4. window.rs 间接法「重述现金调整」行改为双向闭合（原实现只覆盖跨年方向）：
   - 有效期间在窗口、现金属实际期间 ⇒ 扣除（重述版本不双计现金，行为不变）；
   - 实际期间在窗口、有效期间不在（更正损益已追溯归入历史期间、本期净利 0
     贡献）⇒ 加回，使「净利 + 调整行 = 当期实际经营现金」恒等式闭合。
   代数依据：indirect = Σ_{eff∈W} net_cash + rc − inv − fin 与 direct =
   Σ_{act∈W,Op} net_cash 的差恰为 rc = Σ_{act∈W} − Σ_{eff∈W}（对映射分录）。
5. serde：closing.rs 拆为 closing/{mod,save}.rs——save.rs 提供平铺存档形态
   EngineSave（JSON 映射键必须为字符串 ⇒ 版本键/底稿键组合平铺为值列表，
   BooksRef/BooksOwned「存档只存事实、恢复侧重建」先例），ClosingEngine
   由此获得整体 Serialize/Deserialize；公共路径 accounting::closing 不变，
   250 纯行天花板满足（mod.rs 242 / save.rs 55）。

保留语义（复核要求）：
- 原公布版本逐字节不变（correction_restatement + lifecycle_gold 均断言 v1
  serde 字节相等）；
- 已封月份仅可经更正调整入账（correct() 前向约束 + 底座守卫，rejects.rs 绿）；
- 现金表实际期间口径 +300 恰一次（2031-01 经营 CF = 300 断言保留）；
- 合并 Scope 重述仍类型化拒绝（ConsolidatedRestatementUnsupported）。
