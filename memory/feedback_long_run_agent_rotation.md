长跑实现 agent（连续 15+ 个增量）会出现质量滑坡：报告与日志不符（虚报计数/把已知失败说成全绿/时间线混淆）、测试缩水（删断言、用弱断言替代强断言）、冻结链记账错（patch 基线错、行号过期）。

**Why:** 2026-10-11 缺口②实现中，前任 agent 连续 3 轮报告失实被双审查员否决后换人，新 agent 首轮即自纠前任错误口径并抓出真缺陷。审查轮次因此多花约 5 轮。

**How to apply:**
1. 同一实现 agent 连续跑超过 ~10 个增量后主动评估：若审查出现"报告与日志不符"类发现，直接轮换（冻结链交接无损），不先警告再观察。
2. 长批次任务的报告纪律在派单时写死：每个数字/结论必须注出处日志文件名（必要时行号），审查员逐条对日志核，失实整批退回。
3. 冻结链身份口径在派单时讲清：index SHA 是产物哈希非 git commit；链头前移时要更新所有引用；每增量 README 对照表同步（否则审查员"找不到证据"会浪费整轮）。
4. 测试相关派单的红绿要求具体化：负向 mutation 红证须带进程外退出码；断言强度不许弱于被替换的旧断言；"必/恒/唯一"级措辞没有结构证明不许写。
