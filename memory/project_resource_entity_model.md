用户 2026-10-08 与 AI 讨论确定的并发模型方向：把现金和持仓看作**独立的资源实体**（类似 UTXO），可拆分、可合并、有明确所有者。NPC 决策时把所需余额/持仓的所有权转移给"每股交易部"，撮合后把成交部分+未成交部分所有权转回 NPC。同一时刻一份资源只有一个所有者，数据竞争天然消失。

**Why:** 用户目标是 5 股/20000 NPC/16 核单机模拟真实市场行为。NPC 决策可大规模并行，但股票撮合和价格更新是共享状态。所有权转移模型把"共享可变状态+锁"换成"独占所有权+消息传递"，符合 Rust Send/Move 语义、Actor 模型、CSP 思想，在金融模拟里比"账户余额数组+锁"更自然。

**How to apply:**
- **粒度**：NPC 现金一个实体、每 (NPC,股票) 持仓一个实体——不要"一块钱一个实体"（2000万实体会爆炸）；NPC 本地保留聚合余额整数，跨线程转移时才用实体
- **交易部按股票分**：5 个（或 N 个），每个独占一只股票的订单簿；NPC 按股票把资源转给对应交易部
- **SPSC 队列矩阵**：16 NPC 分片 × 5 交易部 = 80 个上行队列，5 交易部 × 16 NPC 分片 = 80 个下行队列，无锁
- **两阶段转移**：冻结（NPC→交易部，拆分实体）→ 撮合 → 结算（交易部→NPC，成交部分转移+未成交部分退回）
- **确定性**：NPC 按 ID 分片、独立 RNG、同 tick 订单按 (stockId,price,npcId) 排序、成交回写按 NPC ID 顺序
- **对象池/竞技场**：预分配实体槽位，避免每 tick malloc
- **未成交必须原路退回**：这是必须实现的路径
- **交易部内部串行**：保证价格优先、时间优先；但 5 只股票并行

**与现有引擎的映射**：
- Cash/Shares lane 预留 → "冻结"阶段的雏形（但当前是共享状态+锁，非所有权转移）
- StockShard（每股独占写者）→ "每股交易部"已有
- Envelope Release 机制 → "未成交退回"已有
- X1 SessionReadView → 双缓冲市场快照已有
- **核心缺口**：流式衔接（NPC→撮合无批式屏障）、所有权转移语义（拆分实体→移动→合并）
